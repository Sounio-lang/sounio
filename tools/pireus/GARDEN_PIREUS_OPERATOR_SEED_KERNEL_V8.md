## The generated operator

Lane indices are the 16 elements of `F2^4`, encoded as integers `0..15`.
`XOR` is bitwise addition in `F2^4`, never addition modulo 16.

For exact integer vectors `a` and `b` of length 16, v8 defines the operator
generated by the seed table `S`:

```text
GeneratedSeedProduct(S,a,b)[d]
  = sum_(i=0..15) coefficient(S,i,i XOR d) * a[i] * b[i XOR d]

coefficient(S,i,j) = 1 - 2*S(i,j)
```

Thus a seed bit `0` means coefficient `+1` and a seed bit `1` means
coefficient `-1`. The destination is not an accumulation index discovered
inside a vertical loop. Once `d` is fixed, all 16 pairs `(i,i XOR d)` land in
that destination. The primitive computation is a horizontal reduction.

No associativity, cocycle law, division property, Cayley-Dickson identity, or
historical novelty follows from this definition. A nonzero arbitrary residual
is still a valid bilinear twisted-XOR operator. Its first exact carrier is the
bilinear map `Z^16 x Z^16 -> Z^16`; it is not called an algebra multiplication
unless later Sounio evidence supplies any additional laws.

## Destination-major kernel IR

v8 compiles the operator into exactly 256 terms in this canonical order:

```text
for d in 0..15:
  for i in 0..15:
    term_id = 16*d + i
    term.destination = d
    term.left = i
    term.right = i XOR d
    term.coefficient = 1 - 2*S(i,i XOR d)
```

Every destination owns one contiguous 16-term group. The kernel contains:

- 16 destination groups;
- 16 terms per group;
- 256 terms total;
- one XOR permutation per group;
- one 16-lane sign mask per group;
- one fixed ordered horizontal reduction per group.

The IR is target-independent. It does not name AVX-512, NEON, SVE, CUDA,
Metal, or FPGA primitives. Later material parity may map the same group to
each canonical target without changing term identity or the Sounio result.

## Independent executable checks

The first Sounio executable must implement two independent paths.

The table evaluator reads `S(i,j)` directly in `(i,j)` order and accumulates
into `d=i XOR j`.

The IR evaluator reads only the compiled destination-major terms and reduces
the 16 terms belonging to each destination.

The executable compares both paths on all declared probes. It must also check:

```text
term_ids_unique = 256
source_pairs_unique = 256
destination_groups = 16
terms_per_destination = 16
xor_address_checks = 256
coefficient_checks = 256
ir_roundtrip_checks = 256
```

All counts above are finite contract sizes, not expected execution outputs.

## Basis sweep

For every ordered pair `(i,j)`, Sounio evaluates basis vectors `e_i` and
`e_j` through both paths. Each of the 256 products must contain exactly one
nonzero lane in its 16-vector result:

```text
destination = i XOR j
value = coefficient(S,i,j)
all other 15 lanes = 0
```

This sweep binds every seed cell to executable behavior. It is independent of
the three dense probes and prevents a checksum-only implementation from
standing in for the operator.

## Dense probe inputs

The first executable uses three exact integer probes. These inputs are fixed
before execution; their 48 output values are deliberately absent from the
matcher-free source and this Garden.

For lane `i` in `0..15`:

```text
probe_0.a[i] = i - 8
probe_0.b[i] = ((5*i + 3) mod 17) - 8

probe_1.a[i] = ((i*i + 3*i + 1) mod 19) - 9
probe_1.b[i] = ((7*i + 2) mod 23) - 11

probe_2.a[i] =  i + 1  when popcount(i) is even
             = -(i + 1) otherwise
probe_2.b[i] = 15 - i
```

All arithmetic is exact signed 64-bit integer arithmetic. For every probe let
`A=max_i |a[i]|` and `B=max_i |b[i]|`; each output satisfies the explicit
uniform bound `|output[d]| <= 16*A*B`, which is below the signed 64-bit bound
for the three declared input formulas.
Floating-point reassociation and tolerance cannot hide a term-order defect in
the first material contract.
