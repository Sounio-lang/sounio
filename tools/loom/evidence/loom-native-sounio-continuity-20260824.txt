Claim under test
----------------

OCaml Loom already verified the physical process identity, semantic journal,
Guardian journal, and generation-lineage chain. Sounio already encoded the
transition policy behind a private linear host-admission seal. The missing
boundary was executable: no native Sounio process consumed the facts that the
OCaml host intended to promote.

The new adapter is a native Sounio ELF. OCaml derives thirteen bounded tokens
from verified facts, sends one canonical stdin frame, and accepts only the exact
Sounio verdict. The first accepted frame becomes an immutable generation-birth
receipt. Later status reads execute the policy over both the current heads and
the birth frame. A runtime upgrade may therefore revalidate an old birth
receipt without rewriting it.

Positive and negative witness
-----------------------------

  sounio-loom-continuity-adapter-selftest: PASS
  language=Sounio engine=lean_single transport=stdin
  initial=accept clean=accept pod=accept
  predecessor=refused count=refused kind=refused canonical=refused

The incomplete Pod predecessor is identical to the positive Pod frame except
that its predecessor semantic-journal token is zero. The shipped rule returns
the exact `SOUNIO_CONTINUITY_REFUSE` verdict with rc=42.

Sabotage control
----------------

The gate changes exactly this policy guard in an isolated module copy:

  if observed.predecessor_semantic_head_token == 0 { return None }

to `if false`. It rebuilds a second native Sounio ELF and reruns the previously
refused frame. The mutant accepts. This establishes that the named Sounio rule,
not an unrelated parser or host failure, causes the refusal.

Bridge and persistence witness
------------------------------

  sounio-loom-beagle-bridge-selftest: PASS
  authority=loom+sounio
  native_policy=verified
  receipt_sabotage=refused
  lineage_sabotage=refused-before-spawn

The bridge exercises initial generation, same-generation kernel recovery,
clean respawn, and simulated Pod resurrection. Every promoted generation has a
distinct 64-hex receipt. Journal growth does not rewrite its birth receipt.
Appending one line to the receipt makes the snapshot path fail closed with HTTP
409 and `sounio-continuity-receipt-mismatch`.

Evidence boundary
-----------------

This proves a process-level OCaml-to-native-Sounio policy binding, a targeted
Sounio mutation control, deterministic receipt persistence, current-policy
replay, and atomic runtime packaging. The OCaml host remains the TCB for OS
identity and journal hashing. The adapter uses the lean_single bootstrap engine
because the modular Madaros path still has a known linear-value baseline.

This is not a direct in-process OCaml FFI, a signed receipt, exactly-once effect
execution, a separate-Pod pending-inbox result, cross-node recovery, production
authority, a PL/CS novelty claim, or priority evidence.
