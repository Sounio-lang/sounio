MATERIAL BOUNDARY
The OCaml realization opens the exact sounio-coord-state/.claims.lock with the
Linux flock(2) syscall used by the shell coordination runtime. Under that lock
it binds a regular process-presence record, a stable inventory digest, current
boot ID, PID namespace, PID, PID start tick, and every existing exact claim,
endpoint, native capability, and presence artifact for the agent/lane key.
Endpoint and capability records must match the same session and process
generation. Heartbeat expiry is never promoted to absence.

Plan mode never mutates. Apply mode first writes and fsyncs a PREPARED WAL,
asks the frozen Sounio action 9047 executable for QUARANTINE_READY, then renames
the bound artifacts into a new transaction-addressed directory. The complete
record, inventory, related-artifact, kernel, cause, and transaction binding is
revalidated after the WAL and again after the Sounio decision, immediately
before mutation. Any drift fails closed. The implementation then fsyncs the
source and destination directories, writes a complete receipt, changes the WAL
to COMMITTED, and appends an ALLOW audit decision. Validation failures append a
DENY decision while holding the same lock. Files are moved, never deleted.
