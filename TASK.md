## Why

The existing GUM stack in `stdlib/darwin_pbpk/epistemic_pbpk14.sio` and `stdlib/darwin_pbpk/bbb/bbb_gum.sio` is **first-order only** (Jacobian of the PBPK output map). For high-nonlinearity rapamycin endpoints (Kpuu × CL coupling on AUC_brain), the JCGM Supplement 1 acknowledges a second-order correction term involving the Hessian of the output. No existing PK/PD package implements 2nd-order GUM through ODE integration. This lane closes that gap.

Mathematical content (per JCGM 100:2008 §F):
- 1st order: Var(y) ≈ Σᵢ (∂y/∂xᵢ)² · u²(xᵢ)
- 2nd order correction: + ½ Σᵢ Σⱼ (∂²y/∂xᵢ∂xⱼ)² · u²(xᵢ) u²(xⱼ)  (when input PDFs are symmetric and uncorrelated)
- Mixed-partial estimator: ∂²y/∂xᵢ∂xⱼ ≈ [y(x+hᵢ+hⱼ) − y(x+hᵢ−hⱼ) − y(x−hᵢ+hⱼ) + y(x−hᵢ−hⱼ)] / (4 hᵢ hⱼ)

Each Hessian element costs **4 PBPK14 integrations**. For 7 epistemic indices that's 7² = 49 mixed partials × 4 = 196 integrations vs the Jacobian's 2·7 = 14. Acceptable budget; PBPK14 Tsit5 step costs ~ms.

## Sounio dialect pins (do not violate)

Read first: `docs/guide/SOUNIO_QUICK_START.md`, `docs/guide/SOUNIO_GOTCHAS.md`. Top 5 mistakes to avoid (per `sounio_llm_training.md`):

1. **No semicolons.** Sounio is layout-significant.
2. **Fixed-size arrays only.** `[f64; N]` with N a literal const — no runtime length.
3. **Mutable refs are `&!`**, not `&mut`.
4. **Effects are required** on fns that read/write global / I/O. Use `effect io` etc.
5. **No traits / derives / impl** in `lean_single.sio` self-host subset; for stdlib code you may use modules but not impl blocks.

Avoid `let g_*: f64 = ...` at module scope (BSS init not honored — see `feedback_native_compiler_limits.md`). For mutable cross-call state use a fixed array inside a small "state struct" passed by `&!`.
