# ===== bug C — type-blind field-index hash (FIXED, type-free bucketed) =====
# field_idx_from_name_simple (lower.sio) used byte[0]%64 -> two fields sharing a
# first letter aliased one aggregate slot; the 2nd write clobbered the 1st (last
# write wins). Type was NOT recoverable on the read side (Expr carries no resolved
# ty; the Lowerer tracks no var types), so real-index keying is impossible for
# general receivers. FIX = a TYPE-FREE bucketed FULL-NAME hash computed IDENTICALLY
# at construction (lower_struct_fields_ref, now the single shared function) and at
# every read (ExprFieldAccess, assign-target 4622, enum payload bind 5307):
#   slot = byte[0]%64 + 64*(fullNameHash%4)  -> range 0..255.
# Consistent BY CONSTRUCTION (no type info either side) => NO real/hash mixing
# hazard, NO false-reject, never report_error for a valid field access. Aggregate
# allocs grown in lockstep: plain struct 64->256 slots, tagged enum 65->257, enum
# tag slot 64->256, and the 8 epistemic emit_named_field constructors ir_alloc(0)
# (512B=64 slots) -> aggregate_storage_bytes(256) so bucketed slots up to 255 cannot
# OOB the heap object (the round-3 OOB landmine: ir_alloc(0)+named-field writes).
# WRONG TURNS recorded so they are not repeated:
#   - round-3 C recorded a type only for `let p=Foo{}` + struct-typed params and
#     report_error'd every other receiver -> FALSE-REJECTED mk().v, let q=p, nested,
#     array-elem (valid base-correct code). It also left enum payload on the hash.
#     -> NEVER report_error a valid field access; keep the consistent fallback.
#   - the naive "upgrade construction to real-index, leave reads on hash" -> indices
#     DISAGREE -> miscompiles even NON-colliding structs (worse than base). The
#     C_control_mix_discriminator witness (q.ax=5 across a copy of NON-colliding
#     {ax,bz}) is the single discriminator: it is 0 iff a fix mixed real+hash.
