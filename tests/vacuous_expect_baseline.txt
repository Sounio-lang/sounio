# Known-vacuous-annotation baseline for scripts/dev/run_sio_test_suite_v2.sh.
#
# Background: the harness's //@ expect-stdout: / //@ error-pattern: extraction
# used to parse annotations with a quoted bash `=~` pattern
# (`"//@ expect-stdout:\ "(.*)`). Quoting the whole pattern makes bash treat it
# as a LITERAL STRING instead of a regex, so the capture group never captured
# and BASH_REMATCH[1] was always empty -- every expect-stdout/error-pattern
# assertion in the suite matched an empty expected string, i.e. VACUOUSLY,
# since the code was written. 321 files use //@ expect-stdout:, 559 use
# //@ error-pattern: (repo-wide grep count at the time of the fix).
#
# ENGINE CALIBRATION -- read before deleting an entry.
# This list is calibrated against the engine the required `full-test-suite`
# CI job runs: souc-stage2 (the frozen lean_single seed), passed in via
# SOUNIO_TEST_SOUC_BIN. Under the default local compiler (Madaros) most of
# these tests PASS, so a local run reports nearly the whole list as "passed in
# this run". That is expected and is NOT a licence to delete them. Measured
# 2026-07-27: CI reported 36 tolerated and exactly 1 genuinely stale entry
# (linear_early_return.sio, since removed), while a local Madaros run reported
# 20+ as passing. Only a run using the CI engine can retire an entry.
#
# scripts/dev/run_sio_test_suite_v2.sh was fixed (separately, already
# committed) to extract with parameter expansion instead of regex:
#   if [[ "$line" == "//@ expect-stdout: "* ]]; then
#       expect_stdout+=("${line#*//@ expect-stdout: }")
#   fi
#   if [[ "$line" == "//@ error-pattern: "* ]]; then
#       error_patterns+=("${line#*//@ error-pattern: }")
#   fi
#
# That fix makes the check REAL for the first time. Measured before/after on
# the full corpus (2900 test files) under the plain lean_single engine (the
# engine CI's required `full-test-suite` job actually gates on via
# SOUNIO_TEST_SOUC_BIN=/tmp/souc-stage2, NOT the Madaros-routing default
# `bin/souc`): before the fix, every expect-stdout/error-pattern test passed
# (vacuously, by construction); after the fix, exactly the 36 tests below
# fail for real. These are PRE-EXISTING wrong (stale, malformed, or otherwise
# mismatched) annotations that the vacuous bug was silently hiding -- they are
# NOT regressions caused by the extraction fix, and they are NOT approvals of
# the underlying test. Cross-checked against PR #1531's "Full Test Suite" CI
# run on commit 941add1c (which carries the same extraction fix, commit
# 4d8f6ce2): identical 36-test failure list.
#
# Root-cause notes (not exhaustive -- these were spot-checked, not all 36):
#   - ontology_family_refutation_cannot_replace_global_truth.sio and
#     ontology_missing_observation_cannot_replace_admissible_observation.sio
#     are NOT wrong annotations. Both are run through the ontology-validation
#     wrapper (scripts/ci/run_ontology_validation.sh ->
#     scripts/ci/build_ontology_validation_souc.sh), whose generated `compile`
#     subcommand runs a custom check-only driver
#     (scripts/ci/ontology_validation_driver.sio) FIRST; when that driver
#     rejects the program (correctly), it prints its OWN short witness-style
#     output and exits WITHOUT ever invoking the real compiler's `compile`
#     subcommand -- so the harness's captured stdout/stderr never contains the
#     human-readable "error[E009] ... argument type does not match parameter"
#     text the test's //@ error-pattern: expects, even though the underlying
#     type rejection is correct. Plain `./bin/souc compile` on the same files
#     DOES produce the expected text. This is an output-format mismatch
#     specific to that validation wrapper's driver short-circuit, not a wrong
#     annotation and not a type-checker defect.
#   - tuple_signature_param_arity_mismatch.sio and
#     tuple_signature_param_type_mismatch.sio both pin
#     //@ error-pattern: ")" (a single literal closing paren) -- worth a
#     second look at whether the annotation itself is truncated/malformed
#     versus the compiler output genuinely lacking it; not yet root-caused.
#
# Regenerate (recompute the current real failure list and replace this file):
#   SOUNIO_VACUOUS_BASELINE_REFRESH=1 SKIP_BUILD=1 \
#     SOUNIO_TEST_SOUC_BIN=./bin/souc-lean-single-x86_64 \
#     bash scripts/run_sio_test_suite.sh
#
# One repo-relative test path per line (paths, not bare basenames, because
# several basenames collide across tests/run-pass, tests/compile-fail,
# tests/ui/*, tests/stdlib/*, e.g. two 'wrong_arg_count.sio' -- only the one
# under tests/ui/type/ is part of this suite's corpus). PRE-EXISTING wrong (or
# wrapper-artefact) annotations, NOT approvals -- shrinking this file by fixing
# the underlying test's annotation or the wrapper's output capture is the
# goal; the harness blocks only on entries that are NEW.
