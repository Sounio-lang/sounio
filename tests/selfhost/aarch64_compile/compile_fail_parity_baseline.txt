# compile_fail_parity_baseline.txt — arm64 mirror checks still missing.
#
# Each line is a tests/compile-fail case that the x86 target REFUSES and the
# aarch64-linux target still ACCEPTS. Read by
# scripts/ci/a64_compile_fail_parity_gate.sh.
#
# THE LIST IS EMPTY. Measured 2026-09-04 over all 658 tests/compile-fail cases:
# every case the x86 target refuses, the aarch64-linux target also refuses.
# It held 265 entries before the TYPECHECK_FAILED gate in compile_all_arm64,
# then 55, then 8, then none.
#
# These are NOT tolerated behaviour. Each one is a check the x86 pass has and
# the arm64 mirror does not. Removing a line belongs in the commit that adds
# the missing check, together with the fixture that proves it fires on both
# targets. Never add a line to make the gate pass: a new divergence is a
# regression in the arm64 mirror, not a fact about the corpus.
#
# The last eight entries were the gtt_* cases, and what closed them is worth
# recording because the obvious fix was the wrong one. The a64 GTT refusal site
# was already present and already correct; it could not fire because its input,
# EXPR_CH_SET, was always zero. Seeding it at the `.value` access ALONE closes
# all eight and breaks about ten run-pass programs — the topology then exists
# but does not propagate, so legitimate hessian_of queries look out-of-topology.
# The fix is the whole beta-9 chain, mirrored into the a64 pass in one commit:
#
#   reset      compile_primary_a64 entry (EXPR_CH_SET / EXPR_PARAM_USED = 0)
#   seed       compile_postfix_tail_a64 `.value`, plus the KM cache that makes
#              the channel NUMBERING agree with x86, plus channels 4-7
#   propagate  compile_additive_a64 / compile_multiplicative_a64 operand unions
#   propagate  pow / atan2 two-argument unions in compile_primary_a64
#   persist    VAR_CH_SET on reassignment in compile_stmt_a64
#   fixpoint   gtt_loop_snapshot / gtt_loop_union around the a64 while and for
#
# After the chain, one run-pass file changed on a64: drift_gate_hessian_of now
# fails — with the SAME diagnostic the x86 target has always printed for it.
# That is convergence, not a regression; the file's placement in run-pass is a
# pre-existing corpus fact.
