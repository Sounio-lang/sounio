# Code Generation

code generation は、Sounio に複数の実在する compiler profile がある
ことを最もはっきり示す領域です。**既定の公開ワークフロー**は
`bin/souc` の背後にある checked self-hosted native path です。別の
omega artifact が、オプションの Cranelift JIT と GPU profile を
それぞれ異なる backend contract で公開しています。

## 現在のソースマップ

- `self-hosted/native/` は native lowering、encoding、ABI、register allocation、object format を扱います。
- `self-hosted/wasm/` は WASM 向け lowering、encoding、module construction を扱います。
- `self-hosted/gpu/` は PTX、SPIR-V、Metal、tensor-oriented work、GPU lowering を扱います。
- `self-hosted/llvm/` は LLVM 向けの別サブツリーとして残っています。

## checked artifact が証明すること

- **既定のランチャー（`bin/souc`）**：self-hosted native codegen を ELF/Mach-O
  に出力します。詳細は `artifacts/omega/selfhost_verification_report.v1.json`
  と `docs/guide/MINIMUM_VIABLE_SOUNIO.md` を参照してください。
- **オプションの JIT profile**：Cranelift JIT は別の checked artifact で
  有効になっています——既定の onboarding path ではありません。
- GPU profile: GPU codegen が有効。JIT は無効。PTX 出力は `build --backend gpu` で利用可能。
- Self-hosted GPU テンプレート: 既定のコンパイラ（`bin/souc`）は GPU 構文を
  コンパイルし、CPU fallback を実行できます。`kretikos` CLI は、定義済みの
  PTX/CUBIN テンプレート向けに小さな in-tree emitter ドライバを構築します：
  `kretikos emit-ptx`（`self-hosted/gpu/ptx.sio` 由来）と `kretikos emit-cubin`
  （`self-hosted/gpu/nvidia_bare.sio` 由来）。`kretikos bundle` は、これらの
  artifact をハッシュ、構造チェック、任意のツールチェイン/ランタイム検証、
  明示的な境界とともにまとめます。
- したがって docs では、default profile の挙動、GPU profile の挙動、
  self-hosted テンプレートの挙動、source tree 上の実装範囲を分けて
  書く必要があります。

## native v2 preview レーン

リポジトリには、backend sovereignty program 用の public preview
`native-v2` レーンも追加されています。互換エイリアス
`native-v2-shadow` は廃止されました。これは新しい安定した
エンドユーザ向けバックエンドではありません。

- 目的は、`RuntimeContext`、ターゲット別レジスタ方針、Machine IR の期待値を
  機械可読な artifact に固定することです。
- 現在の `x86-64` preview レーンは、self-hosted shell で実際の Machine IR +
  legality path を通って `scalar_core` な native ELF を生成し、
  `RuntimeContext` 経由で `gc_state` と managed-object descriptor table を
  公開し、native-v2 heap object を固定容量の handle table で
  `alloc`/field/index 解決します。さらに、precise slot scanning と
  pin-aware relocation を持つ executable な descriptor-driven
  mark-compact GC model も持ちます。その subset 外の opcode family は
  fail-closed です。
- `AArch64` は現在、Mach-O 出力と同じ scalar-core preview contract を
  emit していますが、まだ compile-only preview であり、runtime で
  検証済み（runtime-attested）の native lane ではありません。

## 有効な backend set を確認する

```bash
export SOUC_BIN="$(pwd)/bin/souc"
"$SOUC_BIN" info

export SOUC_GPU_BIN="$(pwd)/artifacts/omega/souc-bin/souc-linux-x86_64-gpu"
"$SOUC_GPU_BIN" info
"$SOUC_GPU_BIN" build examples/kernel_vec_add.sio --backend gpu -o /tmp/kernel_vec_add.ptx

export SOUNIO_NATIVE_V2_CONTRACT_PATH=/tmp/native_backend_v2_contract.v1.json
"$SOUC_BIN" run self-hosted/compiler/main.sio -- --self-test
```

正規の gate-backed artifact は `artifacts/omega/native_backend_v2_contract.v1.json` です。

## 古くならない codegen docs の書き方

- 実装アーキテクチャを説明するときは backend directory を書く。
- 既定の公開体験を説明するときは checked JIT artifact を書く。
- 公開 GPU codegen を説明するときは checked GPU artifact を書く。
- backend の実行 path は、実際に検証した artifact と command に結び付けて書く。
