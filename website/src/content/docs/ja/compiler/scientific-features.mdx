# Scientific Features

Sounio における科学計算は、単一のモジュールや目新しさのための機能ではありません。epistemic typing、stdlib のドメインlane、超複素数の数学、GPU 関連の作業、そしてドメイン固有のテストの組み合わせです。そのため、包括的なページは構文だけでなく、システム全体を見る必要があります。

## 現時点で最も強い部分

- gate に裏付けられた stdlib の科学 lane である `fmri` と `darwin_pbpk` は両方とも通過しています。
- 現在、7 つの hyper-execution lane が required gate を通過しています。
- リポジトリには `hypercomplex`、`gpu`、`tensor`、`distributed` の作業専用の self-hosted ディレクトリに加え、ドメイン固有の例とベンチマークが含まれています。

## ソースマップ

- `tests/stdlib/fmri/` と `tests/stdlib/darwin_pbpk/` は、最も強力な公開科学的証拠です。
- `tests/stdlib/nn/`、`onn/`、`qnn/`、`snn/`、`spnn/`、`quantnn/`、`math/` は、現在通過している hyper lane をマッピングしています。
- `self-hosted/hypercomplex/`、`self-hosted/gpu/`、`self-hosted/tensor/` は、科学的ランタイム作業における最も明確な self-hosted 実装面です。
- `benchmarks/` と `docs/research/` はより広い文脈を提供しますが、artifact とテストが現在のサポート主張に対する最も強力な情報源であることに変わりはありません。

## gate に裏付けられた科学的状況の再現

```bash
bash scripts/stdlib/stdlib_hyper_execution_gate.sh
STDLIB_RUNTIME_REGRESSION_STRICT=1 bash scripts/stdlib_science_pipeline_gate.sh
```

## ドキュメント執筆の指針

- 通過している lane と検証済みの fixture を優先して示してください。
- 無効化された、または stub の科学モジュールは roadmap の在庫として扱ってください。
- GPU ネイティブの科学カーネルや深い超複素数バックエンドのような高度な領域について論じる際は、ソースツリー内の実装作業について話しているのか、チェック済みの公開artifactの挙動について話しているのかを明確にしてください。
