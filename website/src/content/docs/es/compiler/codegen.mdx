# Code Generation

La generación de código es donde Sounio muestra con más claridad que existen
varios perfiles reales de compilador. El **flujo público por defecto** es la
ruta nativa self-hosted verificada detrás de `bin/souc`. Artefactos omega
separados exponen perfiles opcionales de Cranelift JIT y GPU con contratos de
backend distintos.

## Mapa actual del código fuente

- `self-hosted/native/` cubre lowering nativo, codificacion, ABI, asignacion de registros y formatos de objeto.
- `self-hosted/wasm/` cubre lowering, codificacion y construccion de modulos para WASM.
- `self-hosted/gpu/` cubre PTX, SPIR-V, Metal, trabajo tensorial y lowering GPU.
- `self-hosted/llvm/` sigue presente como subarbol orientado a LLVM.

## Lo que prueban los artefactos versionados

- **Lanzador por defecto (`bin/souc`)**: codegen nativo self-hosted a ELF/Mach-O; ver `artifacts/omega/selfhost_verification_report.v1.json` y `docs/guide/MINIMUM_VIABLE_SOUNIO.md`.
- **Perfil JIT opcional**: Cranelift JIT habilitado en un artefacto verificado separado — no es la ruta de incorporación por defecto.
- Perfil GPU: GPU codegen habilitado; JIT deshabilitado; emision PTX disponible mediante `build --backend gpu`.
- Plantillas GPU self-hosted: el compilador por defecto (`bin/souc`) compila la sintaxis GPU y ejecuta el fallback de CPU. La CLI `kretikos` construye pequeños drivers de emisor in-tree para plantillas PTX/CUBIN predefinidas: `kretikos emit-ptx` (desde `self-hosted/gpu/ptx.sio`) y `kretikos emit-cubin` (desde `self-hosted/gpu/nvidia_bare.sio`). `kretikos bundle` agrupa esos artefactos con hashes, verificaciones estructurales, validacion opcional de toolchain/runtime y limites explicitos.
- La documentacion debe distinguir por tanto el comportamiento del perfil por defecto,
  el comportamiento del perfil GPU, el comportamiento de las plantillas self-hosted y la
  amplitud de implementacion en el arbol de fuentes.

## Ruta nativa preview v2

El repositorio ahora tambien incluye una ruta preview publica `native-v2` para
el programa de soberania del backend. El alias de compatibilidad
`native-v2-shadow` ya fue retirado. No es un nuevo backend estable para
usuarios finales.

- Sirve para fijar `RuntimeContext`, la politica de registros por objetivo y
  las expectativas de Machine IR en un artefacto legible por maquina.
- La ruta preview actual de `x86-64` ahora baja por un camino real de Machine
  IR + legalizacion, emite ELFs nativos `scalar_core` en la shell self-hosted,
  publica `gc_state` y una tabla de descriptores de objetos gestionados via
  `RuntimeContext`, enruta los objetos heap de native-v2 por una tabla fija de
  handles para acceso `alloc`/field/index, incorpora un modelo ejecutable de GC
  mark-compact guiado por descriptores con escaneo preciso y reglas de pinning,
  y las familias de opcode fuera de ese subconjunto fallan de forma cerrada.
- `AArch64` ya emite el mismo contrato de preview de scalar-core que la salida
  Mach-O, pero sigue siendo un preview solo de compilacion, no un lane nativo
  con atestacion en tiempo de ejecucion.

## Confirmar el conjunto activo de backends

```bash
export SOUC_BIN="$(pwd)/bin/souc"
"$SOUC_BIN" info

export SOUC_GPU_BIN="$(pwd)/artifacts/omega/souc-bin/souc-linux-x86_64-gpu"
"$SOUC_GPU_BIN" info
"$SOUC_GPU_BIN" build examples/kernel_vec_add.sio --backend gpu -o /tmp/kernel_vec_add.ptx

export SOUNIO_NATIVE_V2_CONTRACT_PATH=/tmp/native_backend_v2_contract.v1.json
"$SOUC_BIN" run self-hosted/compiler/main.sio -- --self-test
```

El artefacto canonico protegido por gates es `artifacts/omega/native_backend_v2_contract.v1.json`.

## Como escribir docs de codegen sin que envejezcan

- Describe los directorios de backend cuando hables de arquitectura de implementacion.
- Describe el artefacto JIT versionado cuando hables de la experiencia publica por defecto.
- Describe el artefacto GPU versionado cuando hables de codegen GPU publico.
- Solo documenta rutas de ejecucion de backend que hayas validado con el artefacto y el comando exactos.
