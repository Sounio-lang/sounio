# Scientific Features

La computación científica en Sounio no es un módulo ni un truco aislado. Es una combinación de tipado epistémico, lanes de dominio de la stdlib, matemática hipercompleja, trabajo en GPU, y tests específicos de dominio. Por eso una página completa tiene que mirar todo el sistema, no solo la sintaxis.

## Qué es lo más sólido hoy

- Las lanes científicas de la stdlib respaldadas por gate `fmri` y `darwin_pbpk` están pasando ambas.
- Siete lanes de hyper-ejecución están pasando actualmente en el gate obligatorio.
- El repositorio contiene directorios self-hosted dedicados para `hypercomplex`, `gpu`, `tensor`, y trabajo `distributed`, además de ejemplos y benchmarks específicos de dominio.

## Mapa de fuentes

- `tests/stdlib/fmri/` y `tests/stdlib/darwin_pbpk/` son los puntos de prueba científica pública más sólidos.
- `tests/stdlib/nn/`, `onn/`, `qnn/`, `snn/`, `spnn/`, `quantnn/`, y `math/` mapean las lanes hyper que pasan actualmente.
- `self-hosted/hypercomplex/`, `self-hosted/gpu/`, y `self-hosted/tensor/` son las superficies de implementación self-hosted más evidentes para trabajo de runtime científico.
- `benchmarks/` y `docs/research/` dan contexto más amplio, pero los artefactos y tests siguen siendo la fuente más sólida para afirmaciones de soporte actuales.

## Reproduce la imagen científica respaldada por gate

```bash
bash scripts/stdlib/stdlib_hyper_execution_gate.sh
STDLIB_RUNTIME_REGRESSION_STRICT=1 bash scripts/stdlib_science_pipeline_gate.sh
```

## Guía de documentación

- Empieza con las lanes que pasan y los fixtures validados.
- Trata los módulos científicos deshabilitados o stub como inventario de roadmap.
- Al discutir dominios avanzados como kernels científicos GPU-nativos o backends hipercomplejos profundos, indica claramente si hablas de trabajo de implementación en el árbol de fuente o de comportamiento de artefacto público verificado.
