# Tipos Epistémicos

Sounio está diseñado para computación científica y regulada, donde un valor rara vez es "solo un número". Las mediciones y cantidades derivadas deberían llevar:

- incertidumbre (metrología)
- confianza/credibilidad (trust)
- procedencia (origen + historial de transformaciones)

## Los Cuatro Tipos Epistémicos

Sounio tiene cuatro tipos wrapper epistémicos de primera clase. Todos comparten los campos `.value: T` y `.epsilon: f64` (la puntuación de confianza, 0–1).

### Knowledge\<T\>

Envuelve una medición con incertidumbre y procedencia. Es el tipo epistémico fundamental.

```sio
let dose: Knowledge<mg> = Knowledge(500.0, ε=0.97, prov="run_042")

if dose.epsilon > 0.95 {
  approve_for_decision(dose)
} else {
  request_remeasurement(dose)
}
```

Extraer un `T` puro requiere una operación explícita con una cadena de motivo — no se puede descartar metadatos epistémicos por accidente:

```sio
let raw: mg = dose.unwrap("override manual, auditado")
```

### Validated\<T\>

Un valor que supera una verificación formal de umbral se convierte en `Validated<T>` — un tipo distinto que el compilador trata diferente de un `Knowledge<T>` en bruto.

```sio
let safe: Validated<mg> = validate(dose, threshold: 0.95)

// Validated<T> se puede pasar a funciones que requieren seguridad probada
administer(safe)
```

### Intervention\<T\>

Representa una intervención causal — el operador do-calculus `do(X=x)`. El campo `.epsilon` lleva la confianza en la estimación de la intervención.

```sio
// Intervención causal: do(Treatment = active)
let treated: Intervention<bool> = intervene(true)

if treated.epsilon > 0.90 {
  run_rct_arm(treated)
}
```

### Counterfactual\<T\>

Representa una consulta contrafactual — lo que una variable *habría sido* bajo condiciones diferentes. La confianza en un contrafactual refleja identificabilidad y calidad del modelo.

```sio
// ¿Qué ingresos tendría Alice si hubiera tenido educación?
let cf: Counterfactual<f64> = counterfactual(
  observed: 30000.0,
  under: education_iv
)

if cf.epsilon > 0.90 {
  report_finding(cf)
}
```

## Lo que Funciona Hoy (Realidad del Compilador)

Los cuatro tipos son analizados, verificados por tipo y compilados a través del pipeline completo (HIR → SIR → HLIR → ELF nativo):

- Construcción: `Knowledge(...)`, `validate(...)`, `intervene(...)`, `counterfactual(...)`
- Acceso a campos: `.value`, `.epsilon`
- Gates de confianza: `if x.epsilon > threshold { ... }`
- Unwrap: `.unwrap("motivo")` para extraer un `T` puro

## Especificación vs Implementación

El diseño completo apunta a un comportamiento más rico: propagación de incertidumbre basada en principios, monotonicidad de confianza y procedencia append-only bajo transformaciones puras.

Parte de eso vive en la spec y en los docs de diseño de la stdlib, aunque la aplicación pueda variar según el modo del compilador y feature flags.
