# 快速开始

Sounio 程序是用 `souc` 检查、运行或构建的 `.sio` 文件。当前公开可依赖的入口是仓库中检查过（checked-in）的编译器构件，用 `souc check` 校验，并把仓库里的 gate 与 fixture 当作"现在到底支持什么"的事实来源。

## 今日已验证
- 文档中最安全的入口是位于 `$(pwd)/bin/souc` 的规范启动器（canonical launcher）。
- 首先应该信任的是 `check`，而不是 `run`，因为执行路径会因宿主构件和 backend 支持而不同。
- 本项目中出现两个版本号，指代不同的东西：**2.1.0** 是语言发行版本（README 徽章、`CITATION.cff`、`CHANGELOG.md`），**Madaros v0.80.0** 是 `bin/souc --version` 打印的编译器构建版本（默认引擎 Madaros）。2.0 之前的旧 beta 版本字符串已停用。
- stdlib 端到端数字正在重新测量。已提交的结果文件（`artifacts/stdlib/stdlib_e2e_result.v1.json`，2026-05-12）早于模块私有性检查的实施，因此此处不引用通过率。
- 编译器只面向 Linux x86-64，生成静态 ELF。Cranelift JIT 已不再随附（CHANGELOG 2.1.0）。`souc build --backend gpu` 仅为命名内核模式的骨架生成 PTX，并非通用 GPU 后端；WASM 后端是受阻草案（[#2237](https://github.com/Sounio-lang/sounio/issues/2237)）。参见 [TOUR.md §6](https://github.com/Sounio-lang/sounio/blob/main/TOUR.md)。
- 把 `SOUNIO_STDLIB_PATH` 指向仓库中的 `stdlib/`。
- 先运行 `souc check`，再考虑 `run` 或 `build`。

## 当前限制
- 真实行为取决于具体的 `souc` 二进制，而不只是仓库里有哪些文件。
- 顶层 Cargo 构建已经不再是公共文档里最合适的首次体验。

## 在这个仓库中验证

```bash
export SOUC_BIN="$(pwd)/bin/souc"
export SOUNIO_STDLIB_PATH="$(pwd)/stdlib"

"$SOUC_BIN" --version
"$SOUC_BIN" check examples/hello.sio
"$SOUC_BIN" check tests/run-pass/covid_2020_kernel.sio
"$SOUC_BIN" check tests/run-pass/vancomycin_propagation.sio
"$SOUC_BIN" check tests/compile-fail/vancomycin_low_conf.sio
```
