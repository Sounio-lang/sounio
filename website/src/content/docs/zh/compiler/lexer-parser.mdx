# Lexer & Parser

前端文档仍然重要，但最稳妥的公开承诺是：源码解析仍然活跃，而更深的内部细节应该结合源码和架构说明一起阅读。

## 今日已验证
- 编译器文档更适合作为实现地图和活跃设计工作的说明。
- 阅读更深的内部实现时，应把仓库文档与源码一起看，而不是相信旧的营销文案。
- 测试和 gate 构件比愿景式描述或目录名称更值得信任。

## 当前限制
- LLVM、GPU 和 LSP 等后端能力必须按构件确认，不能只看源码目录。
- 语言规范可能领先于当前公开构件真正执行的能力。
