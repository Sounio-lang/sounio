# Scientific Features

Sounio 中的科学计算不是单一模块或噱头，而是认知类型系统（epistemic typing）、stdlib 领域 lane、超复数数学、GPU 工作以及领域特定测试的组合。因此，一份全面的文档需要审视整个系统，而不仅仅是语法。

## 目前最强的部分

- 有 gate 支撑的 stdlib 科学 lane `fmri` 和 `darwin_pbpk` 都在通过。
- 目前有七条 hyper-execution lane 在必需 gate 中通过。
- 仓库中包含专门的 self-hosted 目录，覆盖 `hypercomplex`、`gpu`、`tensor` 和 `distributed` 工作，另外还有领域特定的示例和基准测试。

## 源码映射

- `tests/stdlib/fmri/` 和 `tests/stdlib/darwin_pbpk/` 是最强的公开科学证明点。
- `tests/stdlib/nn/`、`onn/`、`qnn/`、`snn/`、`spnn/`、`quantnn/` 和 `math/` 映射了目前通过的 hyper lane。
- `self-hosted/hypercomplex/`、`self-hosted/gpu/` 和 `self-hosted/tensor/` 是科学运行时工作中最明显的 self-hosted 实现表面。
- `benchmarks/` 和 `docs/research/` 提供更广泛的背景，但构件和测试仍然是当前支持声明的最强来源。

## 复现 gate 支撑的科学全景

```bash
bash scripts/stdlib/stdlib_hyper_execution_gate.sh
STDLIB_RUNTIME_REGRESSION_STRICT=1 bash scripts/stdlib_science_pipeline_gate.sh
```

## 文档撰写指南

- 优先呈现通过的 lane 和已验证的 fixture。
- 把已禁用或 stub 的科学模块当作路线图库存来对待。
- 在讨论 GPU 原生科学 kernel 或深度超复数后端等高级领域时，清楚说明你在谈论的是源码树中的实现工作，还是已检查的公开构件行为。
