# LSP

LSP支持存在于仓库中，但这是为什么文档必须区分“在树中实现”与“在检查的公共可执行文件中启用”的明显例子。此页面记录了该区分的两边。

## 当前合同

- 检查的公共JIT可执行文件报告LSP已禁用。
- 仓库中仍然包含一个专门的LSP实现表面在`self-hosted/lsp/`下和编辑器集成材料在`editors/vscode/`下。
- 公共文档应描述LSP为功能门控或替代构建能力，而不是默认检查二进制保证的东西。

## 它所在的位置

- `self-hosted/lsp/protocol.sio`映射协议层。
- `self-hosted/lsp/diagnostics.sio`, `hover.sio`, `goto_def.sio`, `completions.sio`, `rename.sio`, 和 `code_actions.sio`展示活跃的功能表面。
- `editors/vscode/`是显而易见的地方来检查编辑器打包和配置。

## 可执行文件检查和实现路径

```bash
export SOUC_BIN="$(pwd)/bin/souc"
"$SOUC_BIN" info
```

仓库还包含LSP集成入口点在：

- `self-hosted/lsp/`
- `tools/lsp/sounio-lsp.sh`
- `editors/vscode/`

那些是实现表面，不是证明检查的公共可执行文件默认启用LSP。此仓库快照也不暴露一个单一的顶层Cargo工作流，该工作流产生启用LSP的主要编译器二进制。

## 文档指导

- 以检查的可执行文件状态开头。
- 然后描述仓库实现路径供贡献者和高级用户查看。
- 避免说“Sounio默认提供LSP”除非你正在记录一个特定的可执行文件，该可执行文件确实启用了它。
