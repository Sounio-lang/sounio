# 開始使用

本指南是當前公開 Sounio 工作流程的實踐入口。假設你從已檢入的編譯器 artifacts 開始，使用 `souc check` 驗證，並將庫存閘道和測試資料視為當前實際支持的來源。

## 當前合同

- 最安全的文檔入口點是 `$(pwd)/bin/souc` 的可onical 啟動器。
- 第一件事是信任 `check`，而不是 `run`，因為執行路徑因主機 artifact 和後端支援而異。
- 本項目出現兩個版本號，指嘅係唔同嘢：**2.1.0** 係語言發行版本（README 標誌、`CITATION.cff`、`CHANGELOG.md`），**Madaros v0.80.0** 係 `bin/souc --version` 印出嘅編譯器構建版本（預設引擎 Madaros）。2.0 之前嘅舊 beta 版本字串已經停用。
- 標準庫端到端數字正在重新量度。已提交嘅結果檔案（`artifacts/stdlib/stdlib_e2e_result.v1.json`，2026-05-12）早過模組私有性檢查實施，所以呢度唔引用通過率。
- 編譯器只支援 Linux x86-64，生成靜態 ELF。Cranelift JIT 已經不再隨附（CHANGELOG 2.1.0）。`souc build --backend gpu` 只係為命名內核模式嘅骨架生成 PTX，唔係通用 GPU 後端；WASM 後端係受阻草案（[#2237](https://github.com/Sounio-lang/sounio/issues/2237)）。參見 [TOUR.md §6](https://github.com/Sounio-lang/sounio/blob/main/TOUR.md)。

## 驗證這些文檔使用的序列

- `"$SOUC_BIN" check examples/hello.sio` 確認基本的 CLI 和標準庫路徑已正確連接到一起。
- `"$SOUC_BIN" check tests/run-pass/covid_2020_kernel.sio` 驗證當前的科學測試資料。
- `"$SOUC_BIN" check tests/run-pass/vancomycin_propagation.sio` 驗證當前的信心傳播路徑。
- `"$SOUC_BIN" check tests/compile-fail/vancomycin_low_conf.sio` 應該以文檔中記錄的信心不匹配失敗，證明拒絕路徑已啟用。

## 在庫中查看下一步

- `examples/` 包含最小的上門程式，但不是每個文件都應該被視為等級生產準備。
- `tests/run-pass/` 和 `tests/compile-fail/` 是今天語言行為的最佳證據。
- `artifacts/stdlib/*.json` 記錄標準庫可靠性、科學路徑和超高效執行路徑的閘道支持狀況。
- `docs/guide/MINIMUM_VIABLE_SOUNIO.md` 解釋了本網站所遵循的保守合同。

## 最小先進程式

```sio
fn main() -> i32 with IO {
    println("Hello, Sounio!")
    return 0
}
```

## 深入之前注意事項

- 不要將頂級的 Cargo 編譯視為主要的公共上門路徑；它不再是此庫存狀態的最清晰故事。
- 不要僅僅因目錄存在而推斷支援。庫存中同時包含活躍的實現、存根、禁用文件和長期實驗。
- 如果你需要的功能超過了檢入的自托管的啟動器所暴露的範圍，使用 `souc info` 或重新構建不同的 artifact 配置文件之前，不要文檔中記錄為可用。
