# 知識類型

知識計算仍然是Sounio中唯一明显地將其區分開的部分。公開合同比完整的研究視覺更狹窄，但它是現實的：檢查的物件、當前的固定項和拒絕測試都給你具體的立足點。

## 目前演示的

- 語言仍然將`知識`式值作為一等概念建模。
- 當前的檢查路徑證明了明確解包邊界和信心基準的拒絕行為。
- 萬古霉素和COVID固定項仍然是此存儲庫中為什麼知識類型在此處重要性的最佳緊湊演示。

## 何處閱讀和驗證

- `docs/reference/KNOWLEDGE_REFERENCE.md`描述了更大的知識API模型。
- `docs/research/vancomycin-uncertainty.md`詳細解釋了最強大的公開案例研究。
- `self-hosted/check/epistemic.sio`是檢查器面向的目錄，以檢查當前的工作。
- `tests/run-pass/vancomycin_propagation.sio`、`tests/run-pass/covid_2020_kernel.sio`以及相關的編譯失敗固定項是當前的證據點。

## 最小知識模式

```sio
let dose = Knowledge { value: 42.0 }
let accepted: f64 = dose.unwrap("demo boundary")
```

## 如何負責地文檔這個領域

- 分離檢查合同和更廣泛的研究模型。
- 使用固定項和拒絕測試來聲明編譯時行為。
- 即使特定物件只暴露了完整模型的一部分，也要將來源、信心和不确定性視為語言故事的一部分。
