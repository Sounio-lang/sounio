# 血统

Sounio中的血统不仅仅是日志问题；它是认知语言中知识承载值保持可审计的一部分。当前的实体并没有在所有地方暴露完整的研究所，但它已经强制执行了重要的边界跨越纪律。

## 当前合约

- 公共表面上的最清晰的血统边界仍然是显式的解包，并给出原因。
- 公共文档应该描述血统作为值的意义的一部分，而不是事后注释。
- 当不确定性和信心很重要时，血统是判断程序是否应该被信任的一部分。

## 在仓库中的位置

- `docs/reference/KNOWLEDGE_REFERENCE.md` 解释了更大的认知数据模型。
- `docs/research/vancomycin-uncertainty.md` 展示了血统和信心如何影响一个实际的临床决策路径。
- `self-hosted/check/epistemic.sio` 是查看当前检查器逻辑的实现面向的地方。

## 边界纪律

```sio
let measured = Knowledge { value: 14.2 }
let plain: f64 = measured.unwrap("最终报告边界")
```

## 文档指南

- 当你文档一个从 `Knowledge` 值派生的简单数值结果时，解释解包发生在哪里以及为什么。
- 如果工作流需要比已检查的实体当前暴露的更强的血统保证，直接这样说。
- 不要在用户面对的文档中将血统、不确定性和信心合并到一个通用的“元数据”桶中。
