# 標準庫

標準庫龐大、活躍且成熟度混雜。標準庫的完整頁面必須解釋不僅僅是什麼存在，還要如何區分活躍可調用的API與虛擬表面和禁用存儲庫。

## 如何安全地閱讀標準庫

- 將 `active_callable` 模塊視為由測試或門檻支持的真實公共表面。
- 將 `stub_surface` 模塊視為僅僅是形狀：適用於路徑圖和兼容性追蹤，而非強大的API承諾。
- 將 `*.sio.disabled` 文件視為未來的作業清單，而非當前支持。

## 在哪裡檢查真相

- `stdlib/` 存儲代碼和模塊佈局。
- `tests/stdlib/` 存儲最重要的執行和契約檢查。
- `artifacts/stdlib/stdlib_reliability_status.v1.json`，`stdlib_science_pipeline_status.v1.json` 和 `stdlib_hyper_execution_status.v1.json` 是可機器讀取的可信狀態文檔。
- `docs/stdlib/STDLIB_REFERENCE.md` 是存儲庫面向的標準庫快照的參考頁面。

## 重複標準庫的主要門檻

```bash
bash scripts/scan_stdlib.sh --json-out artifacts/stdlib/stdlib_inventory.v1.json
bash scripts/stdlib/stdlib_hyper_execution_gate.sh
STDLIB_RUNTIME_REGRESSION_STRICT=1 bash scripts/stdlib/stdlib_science_pipeline_gate.sh
STDLIB_RUNTIME_REGRESSION_STRICT=1 bash scripts/stdlib_reliability_gate.sh
```

## 實踐指導

- 在撰寫文檔或範例時，從活躍測試開始，而非從目錄名稱。
- 如果一個模塊存在，但其最佳當前測試僅僅是導入或形狀檢查，描述它為有限或虛擬表面。
- 使用狀態文檔當你需要的確切數字或線路級別的主張。
