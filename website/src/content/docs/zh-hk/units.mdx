# 度量单位

度量单位仍然是语言模型中一个重要的部分，因为它们将Sounio连接到科学正确性，而不仅仅是语法美学。今天的正确文档立场是，单位存在于语言和检查器设计中，但端到端的执行仍需要保守地描述。

## 当前合同

- 单位和数量语法是语言故事和活跃检查器工作的一部分。
- 被检查的工件以语言特性形式宣传度量单位。
- 公共文档仍然应该将单位执行描述为部分，除非当前工件或测试中已验证了特定路径。

## 模型级单位语法

```sio
unit kg;
unit m;
unit s;

let speed: Quantity[f64, m/s] = 3.0@Quantity[f64, m/s]
```

## 在哪里检查实现工作

- `self-hosted/check/units.sio` 是最直接的地方来检查当前自托管的单位检查工作。
- `docs/compiler/UNIT_RUNTIME_CHECKING.md` 和相关的编译器文档提供了关于预期执行模型的额外上下文。
- 科学示例和测试是查看当前最安全的主张的正确地方，特别是在单位与领域逻辑交互时。

## 文档指南

- 将单位作为语言设计和当前检查器努力的一部分进行教学。
- 避免在每个后端路径上承诺完全的维度不匹配执行，除非您已直接验证。
- 当单位对安全或科学声明很重要时，将文档与实际固定、基准或门工件联系起来。
