# Scientific Features

Το scientific computing στη Sounio δεν είναι ένα module ή ένα gimmick. Είναι συνδυασμός epistemic typing, stdlib domain lanes, hypercomplex μαθηματικών, δουλειάς σε GPU, και domain-specific tests. Μια ολοκληρωμένη σελίδα πρέπει επομένως να κοιτάζει όλο το σύστημα, όχι μόνο τη σύνταξη.

## Τι είναι πιο ισχυρό σήμερα

- Τα gate-backed stdlib science lanes `fmri` και `darwin_pbpk` περνάνε και τα δύο.
- Επτά hyper-execution lanes περνάνε αυτή τη στιγμή στο required gate.
- Το repo περιέχει αφιερωμένους self-hosted φακέλους για `hypercomplex`, `gpu`, `tensor`, και `distributed` εργασία, καθώς και domain-specific παραδείγματα και benchmarks.

## Χάρτης πηγών

- `tests/stdlib/fmri/` και `tests/stdlib/darwin_pbpk/` είναι τα ισχυρότερα δημόσια science proof points.
- `tests/stdlib/nn/`, `onn/`, `qnn/`, `snn/`, `spnn/`, `quantnn/`, και `math/` χαρτογραφούν τα lanes που περνάνε σήμερα.
- `self-hosted/hypercomplex/`, `self-hosted/gpu/`, και `self-hosted/tensor/` είναι οι πιο εμφανείς self-hosted επιφάνειες υλοποίησης για scientific runtime εργασία.
- `benchmarks/` και `docs/research/` δίνουν ευρύτερο context, αλλά τα artifacts και τα tests παραμένουν η ισχυρότερη πηγή για τρέχοντες ισχυρισμούς υποστήριξης.

## Αναπαραγωγή του gate-backed science στιγμιότυπου

```bash
bash scripts/stdlib/stdlib_hyper_execution_gate.sh
STDLIB_RUNTIME_REGRESSION_STRICT=1 bash scripts/stdlib_science_pipeline_gate.sh
```

## Οδηγίες τεκμηρίωσης

- Ξεκινήστε με τα lanes που περνάνε και τα validated fixtures.
- Αντιμετωπίστε τα απενεργοποιημένα ή stub scientific modules ως roadmap inventory.
- Όταν συζητάτε προχωρημένα domains όπως GPU-native scientific kernels ή βαθιά hypercomplex backends, δηλώστε ρητά αν μιλάτε για source-tree implementation εργασία ή για checked public artifact συμπεριφορά.
