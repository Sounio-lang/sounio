# Epistemic Types

Sounio is designed for scientific and regulated computing, where a value is rarely "just a number." Measurements and derived quantities should carry:

- uncertainty (metrology)
- confidence/credibility (trust)
- provenance (origin + transformation history)

## The Four Epistemic Types

Sounio has four first-class epistemic wrapper types. All share `.value: T` and `.epsilon: f64` fields (the confidence score, 0–1).

### Knowledge\<T\>

Wraps a measurement with uncertainty and provenance. This is the foundational epistemic type.

```sio
let dose: Knowledge<mg> = Knowledge(500.0, ε=0.97, prov="run_042")

if dose.epsilon > 0.95 {
  approve_for_decision(dose)
} else {
  request_remeasurement(dose)
}
```

Extracting a plain `T` requires an explicit operation with a reason string — you cannot accidentally drop epistemic metadata:

```sio
let raw: mg = dose.unwrap("manual override, audited")
```

### Validated\<T\>

A value that has passed a formal threshold check becomes `Validated<T>` — a distinct type the compiler treats differently from a raw `Knowledge<T>`.

```sio
let safe: Validated<mg> = validate(dose, threshold: 0.95)

// Validated<T> can be passed to functions that require proven safety
administer(safe)
```

### Intervention\<T\>

Represents a causal intervention — the do-operator `do(X=x)` from Pearl's do-calculus. The `.epsilon` field carries confidence in the intervention estimate.

```sio
// Causal intervention: do(Treatment = active)
let treated: Intervention<bool> = intervene(true)

if treated.epsilon > 0.90 {
  run_rct_arm(treated)
}
```

### Counterfactual\<T\>

Represents a counterfactual query — what a variable *would have been* under different conditions. Confidence on a counterfactual reflects identifiability and model quality.

```sio
// What earnings if Alice had received education?
let cf: Counterfactual<f64> = counterfactual(
  observed: 30000.0,
  under: education_iv
)

if cf.epsilon > 0.90 {
  report_finding(cf)
}
```

## What Works Today (Compiler Reality)

All four types are parsed, type-checked, and lowered through the full pipeline (HIR → SIR → HLIR → native ELF):

- Construction: `Knowledge(...)`, `validate(...)`, `intervene(...)`, `counterfactual(...)`
- Field access: `.value`, `.epsilon`
- Confidence gates: `if x.epsilon > threshold { ... }`
- Unwrap: `.unwrap("reason")` to extract a plain `T`

Automatic uncertainty propagation through arithmetic (e.g., `a * b` where `a: Knowledge<f64>`) is part of the design and partially implemented; enforcement varies by compiler mode.

## Spec vs Implementation

The full design aims for richer behavior: principled uncertainty propagation, confidence monotonicity, and append-only provenance under pure transforms.

Some of that lives in the language spec and stdlib design docs, even if enforcement varies by compiler mode and feature flags today.
