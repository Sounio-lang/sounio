# Custom Effects

User-declared effects are part of the syntax of the [effect system](/learn/effects/) and are not a working feature. You can write an `effect` declaration. The compilers do not give that declaration its own checked effect.

## Parsed, not yet implemented

The parser accepts `effect Name { ... }` in `self-hosted/parser/items.sio`. A semicolon after an operation is optional. The form with a semicolon parses, and so does the form without one. Neither form registers a distinct effect on the checker Madaros runs.

The block below is that syntax. It is not a working program. `Fail` is a held name, so this sketch is not proof that a user effect is checked. Do not copy it as something `souc check` accepts.

```sio
effect Fail {
    fn fail(msg: [u8; 4]) -> !
}

fn main() -> i32 with Fail {
    Fail.fail("demo")
    return 0
}
```

`checker_collect_item_inplace` in `self-hosted/check/check.sio` has no arm for an effect item. The item is skipped. The evidence row is EFF-021 in `docs/spec/2026-10/03-evidence.tsv`. On lean_single, `ety_parse_effect_name` returns 0 for a name outside its built-in list, so a user name does not become its own bit.

`handle` is parsed and has no backend. The [effect system](/learn/effects/) page shows the two repository files that carry this syntax, inside a section marked parsed, not yet implemented, and records the diagnostics.

## What you can declare today

Declare a built-in effect on the function that uses it. IO, Mut, Div and Panic are the common names. The full closed list is 30 names, ids 0-29, in `self-hosted/check/effects.sio`. A named function does not receive those effects by inference. To [declare a custom effect](/learn/effects/#parsed-not-yet-implemented) in the sense of a new checked name, there is no switch to turn on.
