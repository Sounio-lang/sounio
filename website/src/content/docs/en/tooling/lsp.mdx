# Language Server Protocol

Sounio includes a state-of-the-art Language Server Protocol (LSP) implementation that brings the full power of Sounio's type system to your editor.

## Features at a Glance

| Feature | Description |
|---------|-------------|
| **Epistemic Hints** | Confidence badges and provenance tracking |
| **Effect Annotations** | Real-time effect analysis with source tracking |
| **Unit Diagnostics** | Dimensional analysis with physics-aware suggestions |
| **Rich Hover** | Combined type, effect, unit, and epistemic information |
| **Smart Completions** | Context-aware completions for effects and handlers |
| **Code Actions** | Quick fixes for effects, units, and epistemic issues |

## Installation

### VS Code

Install the Sounio extension from the VS Code Marketplace:

```bash
code --install-extension sounio.sounio-vscode
```

Or search for "Sounio" in the Extensions panel.

### Other Editors

The LSP server can be used with any LSP-compatible editor:

```bash
# Start the language server
souc lsp

# Or with debug logging
SOUNIO_LSP_LOG=debug souc lsp
```

## Epistemic Intelligence

The LSP makes Sounio's epistemic type system visible throughout your IDE.

### Confidence Badges

Variables with epistemic types show confidence badges inline:

```sio
let measurement = measure(100.0, uncertainty: 2.5)
//                                              ^-- [🟢 95%]

let estimate = rough_estimate(value)
//                                  ^-- [🟠 45%]
```

**Badge Legend:**
- 🟢 High confidence (95%+)
- 🟡 Good confidence (75-95%)
- 🟠 Medium confidence (50-75%)
- 🔴 Low confidence (25-50%)
- ⚫ Very low confidence (&lt;25%)

### Epistemic Diagnostics

The LSP warns about epistemic issues:

| Code | Description |
|------|-------------|
| `E1001` | Confidence below threshold |
| `E1002` | Missing provenance on derived values |
| `E1003` | Incomplete provenance (no dependencies) |
| `E1004` | Missing evidence citations |
| `E1005` | Wide confidence interval warning |

**Example warnings:**

```sio
// E1001: Low confidence: 'estimate' has 45% confidence (threshold: 75%)
let estimate: Knowledge<f64> = derive_from(uncertain_data)

// E1002: Missing provenance: derived value 'result' lacks lineage
let result = transform(input)  // Suggestion: Use with_provenance(...)
```

### Provenance Hints

For values with provenance tracking, the LSP shows the data lineage:

```sio
let final_result = complex_calculation(a, b, c)
//                                              ^-- [← sensor_reading → normalize → filter]
```

## Effect-Aware Editing

The LSP understands Sounio's algebraic effect system.

### Effect Inlay Hints

Function calls show their effect requirements:

```sio
fn process_data() with IO, Mut {
    let file = read_file("data.csv")  // with IO
    let parsed = parse(file)          // (pure)
    cache.store(parsed)               // with Mut
}
```

### Effect Diagnostics

| Code | Description |
|------|-------------|
| `E0006` | Undeclared effect in function signature |

**Example:**

```sio
fn save(data: Data) {        // Error: E0006
    write_file("out.json", data)
    //         ^-- effect `IO` not declared in function signature
}
```

### Effect Code Actions

The LSP provides quick fixes for effect issues:

1. **Add effect to signature** - Automatically adds `with IO` to the function
2. **Wrap with handler** - Wraps expression in an effect handler block
3. **Extract to effectful function** - Refactors into a separate function

**Handler Templates:**

When you choose "Wrap with handler", the LSP generates effect-specific templates:

```sio
// IO handler
handle IO {
    return {
        your_expression
    }
}

// Panic handler with recovery
handle Panic {
    case panic(msg) => resume(default_value)
    return {
        your_expression
    }
}

// Async handler with blocking
handle Async {
    case await(future) => resume(future.block())
    return {
        your_expression
    }
}
```

## Units of Measure

The LSP provides comprehensive support for dimensional analysis.

### Unit Inlay Hints

Expressions show their inferred or explicit units:

```sio
let force = mass * acceleration
//                             ^-- @kg*m/s^2 (Newton)

let velocity = distance / time
//                            ^-- @m/s
```

### Unit Diagnostics

| Code | Description |
|------|-------------|
| `E0007` | Dimensional mismatch |
| `E0008` | Unexpected dimensionless result |
| `E0009` | Missing unit annotation (hint) |
| `E0010` | Implicit unit conversion warning |
| `E0011` | Incompatible unit operation |
| `E0012` | Potential unit confusion |

**Physics-Aware Suggestions:**

The LSP understands physics and suggests fixes:

```sio
// E0007: Dimensional mismatch
// Expected: m/s (velocity, L/T)
// Got: kg (mass, M)
//
// Suggestion: Did you mean to divide by time? (distance / time = velocity)
let speed = mass  // Should be: distance / time
```

**Common dimensional relationships the LSP knows:**
- Velocity = distance / time
- Force = mass × acceleration
- Energy = force × distance
- Power = energy / time
- Pressure = force / area
- Density = mass / volume

### Unit Confusion Warnings

The LSP warns about mixing similar but incompatible units:

```sio
// E0012: Potential unit confusion: mixing 'mph' and 'km/h' in velocity calculations
let combined = american_speed + european_speed
```

## Completions

The LSP provides context-aware completions:

### Effect-Aware Completions

Inside an effect handler, completions are filtered to relevant operations:

```sio
handle IO {
    // Completions show IO-related functions:
    // - read_file
    // - write_file
    // - print
    // - ...
}
```

### Unit-Aware Completions

When working with dimensional quantities, completions respect unit compatibility.

```json
    "sounio.inlayHints.tensorShapeHints": true,

```

## Performance

The LSP uses a query-based incremental architecture for optimal performance:

| Operation | Target Response Time |
|-----------|---------------------|
| Hover (cached) | &lt;50ms |
| Completions | &lt;100ms |
| Full re-analysis | &lt;500ms |
| Incremental update | &lt;50ms |

The architecture is based on demand-driven queries with automatic cache invalidation, similar to rust-analyzer's approach.

## Troubleshooting

### Enable Debug Logging

```bash
SOUNIO_LSP_LOG=debug souc lsp 2> lsp.log
```

### Common Issues

**LSP not starting:**
- Ensure `souc` is in your PATH
- Check that the LSP feature is enabled: `souc --version` should show `lsp: enabled`

**Missing diagnostics:**
- Verify the file has `.sio` extension
- Check for syntax errors that prevent analysis

**Slow performance:**
- Large files may take longer on first analysis
- Subsequent edits use incremental analysis
