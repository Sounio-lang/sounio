# Pattern Matching

The `match` expression provides exhaustive pattern matching over values. The compiler checks that all cases are covered and warns about unreachable arms.

## Basic matching

```sio
fn describe(x: i32) -> str {
    match x {
        0 => "zero",
        1 => "one",
        _ => "other",
    }
}
```

The wildcard `_` matches any value and is used as a catch-all.

## Matching on enums

```sio
enum Shape {
    Circle(f64),
    Rectangle(f64, f64),
    Triangle(f64, f64, f64),
}

fn area(s: Shape) -> f64 {
    match s {
        Shape::Circle(r) => 3.14159 * r * r,
        Shape::Rectangle(w, h) => w * h,
        Shape::Triangle(a, b, c) => {
            let s = (a + b + c) / 2.0
            sqrt(s * (s - a) * (s - b) * (s - c))
        },
    }
}
```

If you omit a variant, the compiler reports an error about non-exhaustive matching.

## Guards

Pattern arms can include `if` guards for additional conditions:

```sio
fn classify_temp(celsius: f64) -> str {
    match celsius {
        t if t < 0.0 => "freezing",
        t if t < 20.0 => "cold",
        t if t < 35.0 => "comfortable",
        _ => "hot",
    }
}
```

## Matching on structs

```sio
struct Point { x: f64, y: f64 }

fn quadrant(p: Point) -> str {
    match p {
        Point { x, y } if x > 0.0 && y > 0.0 => "I",
        Point { x, y } if x < 0.0 && y > 0.0 => "II",
        Point { x, y } if x < 0.0 && y < 0.0 => "III",
        Point { x, y } if x > 0.0 && y < 0.0 => "IV",
        _ => "on axis",
    }
}
```

## Current limitations

- Tuple destructuring in `let` bindings (`let (a, b) = pair`) is not yet supported. Use `match` instead.
- Nested pattern matching on deeply nested structs works but is not yet exhaustively checked in all cases.
- Or-patterns (`A | B => ...`) are parsed but coverage checking for them is still maturing.
