# Units and Uncertainty

Status: Sounio 3.0 (pre-release).

**Does Sounio have built-in unit checking?** On the committed compiler, adding a length to a time is refused before the program runs. The witness is below.

**How does uncertainty propagate?** `Knowledge<T>` with the first-order law in JCGM 100:2008. The values this page quotes were printed by `./bin/souc` on 20 November 2026. They are not a comparison against another language.

The compiler those commands ran is the committed prebuilt, `bin/madaros-linux-x86_64.gz`, last changed in commit `4b7b96ea2` (31 October 2026). The first `./bin/souc` that day materialised `bin/madaros-linux-x86_64` and reported sha256 prefix `0ff69d86652b`, 131149756 bytes. Source tests that landed after that refresh are named where they matter, and this page does not treat them as results of that ELF.

## A length divided by a time

`tests/run-pass/unit_derived_let_binding_issue_2752.sio` is the same division, with a named `velocity` alias. This shorter program was run with `./bin/souc run` on the committed prebuilt. It printed `10.438413`.

```sio
// souc:run
// expect: 10.438413
fn main() -> i32 with IO, Div {
    let distance: m = 100.0
    let elapsed: s = 9.58
    let speed = distance / elapsed
    print_f64(speed)
    print("\n")
    return 0
}
```

Metres added to seconds is refused. `./bin/souc check` on the committed prebuilt exited non-zero and printed `error[E041]` with `left unit: length^1` and `right unit: time^1`. The same code is what the fence below re-runs.

```sio
// souc:fail
// expect: error[E041]: unit mismatch in arithmetic operation
// expect: left unit: length^1
// expect: right unit: time^1
fn main() -> i32 with IO, Div {
    let distance: m = 100.0
    let elapsed: s = 9.58
    let wrong = distance + elapsed
    print_f64(wrong as f64)
    return 0
}
```

`km + m` is also `error[E041]`, both sides `length^1`, in `tests/compile-fail/diagnostic_e041_unit_meaning.sio`. Equal dimensions still need a conversion. That file was checked on the same prebuilt on 20 November 2026.

`sin` of a length is a later source test, `tests/compile-fail/unit_transcendental_sin_dimensioned.sio`, which asks for `transcendental function argument must be dimensionless`. The committed prebuilt does not implement that refusal. `./bin/souc check` of the program below printed `check: OK` on 20 November 2026, and the fence re-runs that fact.

```sio
// souc:check
// expect: check: OK
fn main() -> i32 with IO, Div {
    let a: m = 4.0
    let invalid = sin(a)
    return 0
}
```

A projectile, a kinetic energy, and a force that do type-check and run are [`examples/showcase/type_safe_units.sio`](https://github.com/Sounio-lang/sounio/blob/main/examples/showcase/type_safe_units.sio). On the same prebuilt, `./bin/souc run` printed `3750.000000` for the kinetic energy and `4200.000000` for the force. Those two lines are the measurement. The file is the program.

## Uncertainty propagation

`Knowledge<T>` is a measured value. The supported path on this prebuilt peels `.value` and then calls `variance_of`. Arithmetic on two `Knowledge` values is refused: a direct `h - h` where `h` is still a `Knowledge<f64>` produced `error[E245]` and `error[E236]` on 20 November 2026.

The program that prints `v_ind=0.050000` and `v_cor=0.090000` is on [Uncertainty](/learn/epistemic/uncertainty/). `tests/run-pass/gum_correlated.sio` printed `PASS` on the same prebuilt. Independent inputs use `0.1² + 0.2² = 0.05`. After `correlate(x, y, 1.0)` the variance is `(0.1 + 0.2)² = 0.09`.

[`examples/science/uncertainty_propagation.sio`](https://github.com/Sounio-lang/sounio/blob/main/examples/science/uncertainty_propagation.sio) ran on that prebuilt. The lines it printed were:

```text
BMI = 23.148148 +/- 0.299946 kg/m^2
Variance: mass=26.470588%, height=73.529412%
BSA = 1.936492 +/- 0.008402 m^2
```

An older draft of this page said the variance split was about 4% mass and 96% height. That split is not what this run printed.

Call-boundary propagation is ahead of this ELF. `docs/compiler/KNOWN_LIMITATIONS.md` KL-11, dated 2026-11-15, describes tangent clones for `f64` helpers and pins `tests/run-pass/gum_fo_tangent_clone_calls.sio`. Running that test on the committed prebuilt printed `FAIL` sentinels (`reassign 0.000000 FAIL`, and the same for `loop`, `lj`, `inner`) and exited 1. This page does not claim those variances from `./bin/souc`.

`Knowledge<f128>` is not implemented (KL-15 in the same ledger).
