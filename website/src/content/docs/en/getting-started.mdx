Start with a compatible compiler, check a small program, then run it. This guide uses the repository's canonical launcher, `./bin/souc`, whose default engine is Madaros. On Linux x86-64 the commands below are the whole path. [INSTALL.md](https://github.com/Sounio-lang/sounio/blob/main/INSTALL.md) repeats them.

## Prerequisites

Linux x86-64 needs:

- `git`
- `bash`
- `gzip` — the first `./bin/souc` decompresses the committed prebuilt
- `sha256sum` from GNU coreutils
- about 2 GB of free disk

Measured on 27 October 2026, Linux x86-64, `main` at `75fd75c587a799169d59954cd50f2f327eed5f4e`: `git clone --depth 1` occupied 1.1 GB. The first `./bin/souc` then wrote `bin/madaros-linux-x86_64` (129,918,841 bytes). The tree was 1.3 GB after that. A clone without `--depth 1` also downloads history and is larger.

macOS ARM64 does not run this Linux ELF. Its tools are in the [macOS ARM64 guide](https://github.com/Sounio-lang/sounio/blob/main/docs/compiler/MADAROS_MACOS_ARM64.md).

## Get the repository

```sh
git clone --depth 1 https://github.com/Sounio-lang/sounio.git
cd sounio
git rev-parse HEAD
uname -sm
```

`--depth 1` fetches the current commit and not the history. Keep the revision that `git rev-parse HEAD` prints, and choose the setup path for your host:

| Host | Setup path |
| --- | --- |
| Linux x86_64 | Continue with the commands in the next two sections. |
| macOS ARM64 (Apple Silicon) | Build and install the native artifact first, following the [macOS ARM64 guide](https://github.com/Sounio-lang/sounio/blob/main/docs/compiler/MADAROS_MACOS_ARM64.md). The Linux ELF does not run natively on macOS. |
| Other hosts | These instructions do not provide a compatible prebuilt. Consult the installation guide before proceeding. |

The macOS source build requires a signed, executable current-source bootstrap seed, Apple command-line tools with C++23-capable `clang++` and `codesign`, `timeout`, and Boost headers. The full installation gate also requires a real Metal device. The [native guide](https://github.com/Sounio-lang/sounio/blob/main/docs/compiler/MADAROS_MACOS_ARM64.md) describes these prerequisites and installs `artifacts/self-hosted/madaros-arm64-macos`, which the launcher prefers on Apple Silicon after explicit overrides. A fresh checkout alone is not enough on that platform.

Neither setup path starts with `cargo build` at the repository root.

## Identify the compiler

On Linux x86-64, from the repository root:

```sh
export SOUNIO_STDLIB_PATH="$PWD/stdlib"
./bin/souc info
./bin/souc --version
```

The committed compiler is stored as `bin/madaros-linux-x86_64.gz`. The first `./bin/souc` decompresses it to `bin/madaros-linux-x86_64` and prints one line on stderr with a sha256 prefix and the byte count. Later runs reuse that file.

`bin/souc` is a launcher, not the compiler binary itself. Inspect the `raw_elf` path reported by `info`: explicit overrides and local artifacts can select a different build from the committed prebuilt. `./bin/souc --version` prints provenance lines on stderr and the version on stdout. Keep that identity with your results. Do not switch engines to work around a platform or setup failure.

The checksum file names `madaros-linux-x86_64` with no directory. Run it from `bin/`, after the first `./bin/souc` invocation. Before that invocation the ELF is not on disk, and the check cannot open it. From the repository root, `sha256sum -c bin/madaros-linux-x86_64.sha256` looks for the ELF in the current directory and fails.

```sh
(cd bin && sha256sum -c madaros-linux-x86_64.sha256)
```

A match prints `madaros-linux-x86_64: OK`.

## Check and run the first example

Once the selected compiler matches your platform:

```sh
./bin/souc check examples/hello.sio
./bin/souc run examples/hello.sio
```

Run the second command only if the check succeeds. `souc --help` does not list `--quiet` or `--silent`. `run` prints compiler log lines and then the program's own output. The expected message is `Hello, Sounio`, with exit status zero. Those log lines are the compiler, not the program.

`./bin/souc compile examples/hello.sio -o hello.elf` writes an ELF and does not print `Hello, Sounio`. You do not need that step to see the message.

Keep the actual output and exit status: a successful check alone does not establish runtime behavior, and these instructions are not a fresh execution report.
