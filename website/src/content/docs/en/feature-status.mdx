# Feature Status

Sounio is rapidly evolving. Below is the current implementation status of our Standard Library and major language features as of v1.0.0-beta.5.

## PLDI 2027 Type System Tracks (Sprint 17-18-19)

These novel type system features were introduced in Sprints 17-19. All four completed tracks have no prior art in any production language.

| Track | Feature | Status |
|-------|---------|--------|
| H6.2 (Track A) | Row-polymorphic effects — effect variables and rows, row-poly function signatures | Complete |
| H6.3 (Track B) | Aleatoric/Epistemic type decomposition — compile-time irreducible vs. reducible uncertainty split | Complete |
| H6.4 (Track D) | Causal effect types + do-calculus — type-level d-separation and Pearl intervention verification | Complete |
| H6.5 (Track C) | Graded modal epistemic effects — uncertainty-graded effect rows fused with algebraic effects | Complete |
| H7 (Sprint 19) | Session types — typed communication protocols with duality and row-poly protocol variables | In Progress |
| H7.1-H7.2 (Sprint 19) | Epistemic session types — Knowledge-wrapped responses with provenance-derived epsilon bounds | In Progress |
| — | User-defined `effect` declarations — parser recognizes `effect` keyword | Complete |

Gates: `artifacts/sprint17/`, `artifacts/sprint18/`, `artifacts/sprint19/epistemic_session_gate.v1.json`.

> **Note**: Some files in the repository carry a `.sio.disabled` suffix (approx. 120 files). These represent features that exist in the codebase but are currently inactive or stubbed out pending compiler stabilization.

## Standard Library Tiers

### Tier 1: Production-Ready
These modules are fully implemented, tested, and reliable for use today.
- **core**: `Option<T>`, `Result<T, E>`
- **collections**: `Vec`, `HashMap`, `HashSet`, `Deque`
- **io**: File I/O, Directory operations, Console
- **iter**: Iterator trait and combinators
- **json**: JSON parsing and serialization
- **test**: Testing framework (assertions, property-based)
- **time**: `Duration`, `DateTime`, `Instant`
- **native codegen**: Self-hosted ELF backend — source-to-binary with SSE2/AVX-512, deterministic bootstrap cycle verified.

### Tier 2: Domain-Specific (Production Quality)
- **epistemic**: All four types implemented and lowered end-to-end: `Knowledge<T>`, `Validated<T>`, `Intervention<T>`, `Counterfactual<T>`. Field access (`.value`, `.epsilon`), confidence gates, and `.unwrap("reason")` all work.
- **autodiff**: Forward and reverse mode automatic differentiation.
- **linalg**: Linear algebra types and BLAS/LAPACK fallbacks.
- **ode**: ODE solvers (Tsit5, RK4, DOPRI5).
- **darwin_pbpk**: PBPK simulation engines.
- **nn**: Neural networks (layers, optimizers).
- **quantum**: Quantum computing (VQE).

### Tier 3: Partially Implemented
These modules contain core structures and parse successfully but may lack full runtime execution paths.
- **wasm backend**: Self-hosted WASM 1.0 emitter (`self-hosted/wasm/`) — IR lowering, LEB128 encoding, section emitters, and 39 inline tests. Not yet integrated into the `souc` CLI. Browser playground requires building assets separately via `scripts/build_playground_wasm.sh`.
- **async**: Traits exist, executor framework sketched.
- **medlang**: MedLang DSL parsing implemented, execution pending.
- **ontology**: Core types and namespaces implemented, reasoning partial.
- **optimize**: Basic algorithms sketched.

### Tier 4: Stubs and Minimal Features
These modules are currently minimal stubs or have their core `.sio` implementations marked as disabled.
- **gpu**: Basic kernel syntaxes parse, but standard library wrappers (e.g., `fft.sio`, `smooth.sio`) are largely stubbed.
- **mem**: Allocators and arenas.
- **ml**: Machine learning components like Random Forests.
- **search**: Search algorithms.
- **stats**, **signal**, **connectivity**, **fusion**, **systems**: Minimal implementation.

## Disabled Modules
You will find many `.sio.disabled` files in the repository, particularly in `nn`, `onn`, `prob`, `ode`, `ontology`, `gpu`, and `medlang`. We keep these in tree to track future functionality that currently lacks full compiler parity. When exploring showcases, please be aware that certain deep integrations may rely on these disabled modules.
