# Feature Status

This page is the compact status board for the public contract. It is comprehensive in the sense that it ties the major public surfaces back to the artifacts that currently decide whether a claim is trustworthy.

## Current snapshot

| Surface | Current status |
| --- | --- |
| Compiler artifacts | `souc 1.0.0-beta.5` checked-in JIT and GPU profiles |
| Default public profile | JIT artifact with Cranelift JIT enabled; LLVM and GPU codegen disabled |
| GPU public profile | GPU artifact with GPU codegen enabled, JIT disabled, and PTX emission via `build --backend gpu` |
| Self-hosted GPU emission | `kretikos emit-ptx` (PTX), `kretikos emit-metal` (MSL), `kretikos emit-spirv` (SPIR-V), `kretikos emulate` (CPU), and `kretikos emit-cubin` (CUBIN) from in-tree emitters |
| Attested GPU compute lanes | CUDA `cuda-sm80`, ROCm `rocm-gfx942` |
| Feature flags in checked artifact | LSP, SMT, ontology, distributed, and pkg disabled |
| Stdlib reliability | `81 pass / 0 fail / 1 skip / 82 total` |
| Stdlib inventory | `604` `.sio` files, `111` disabled files, `44` stub module files, `92` active entrypoints |
| Science lanes | `fmri` and `darwin_pbpk` passing |
| Hyper lanes | 7 required lanes passing |
| Runtime regressions | 4 failures tracked in `soft` mode |

## Why these numbers matter

- They are pulled from committed artifacts, not from aspirational roadmap copy.
- They define what the docs can claim without caveats.
- They explain why some large parts of the repo should still be described as active work, stub surface, or disabled inventory instead of as stable APIs.
