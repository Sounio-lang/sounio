# Scientific Features

A computação científica em Sounio não é um módulo isolado nem um truque. É uma combinação de tipagem epistêmica, lanes de domínio da stdlib, matemática hipercomplexa, trabalho em GPU e testes específicos de domínio. Por isso, uma página abrangente precisa olhar para o sistema inteiro, não só para a sintaxe.

## O que está mais forte hoje

- As lanes científicas da stdlib apoiadas por gate `fmri` e `darwin_pbpk` estão passando.
- Sete lanes de hyper-execução estão passando atualmente no gate obrigatório.
- O repositório tem diretórios self-hosted dedicados para `hypercomplex`, `gpu`, `tensor` e `distributed`, além de exemplos e benchmarks específicos de domínio.

## Mapa de origem

- `tests/stdlib/fmri/` e `tests/stdlib/darwin_pbpk/` são os pontos de prova científica pública mais fortes.
- `tests/stdlib/nn/`, `onn/`, `qnn/`, `snn/`, `spnn/`, `quantnn/` e `math/` mapeiam as lanes hyper atualmente passando.
- `self-hosted/hypercomplex/`, `self-hosted/gpu/` e `self-hosted/tensor/` são as superfícies de implementação self-hosted mais evidentes para trabalho de runtime científico.
- `benchmarks/` e `docs/research/` dão contexto mais amplo, mas os artefatos e testes continuam sendo a fonte mais forte para afirmações de suporte atuais.

## Reproduza o retrato científico apoiado por gate

```bash
bash scripts/stdlib/stdlib_hyper_execution_gate.sh
STDLIB_RUNTIME_REGRESSION_STRICT=1 bash scripts/stdlib_science_pipeline_gate.sh
```

## Orientação de documentação

- Comece pelas lanes que passam e pelos fixtures validados.
- Trate módulos científicos desativados ou stub como inventário de roadmap.
- Ao discutir domínios avançados como kernels científicos GPU-nativos ou backends hipercomplexos profundos, deixe claro se você está falando de trabalho de implementação na árvore-fonte ou de comportamento de artefato público verificado.
