# Geração de Código (*Codegen*)

A geração de código é onde a árvore de fontes é mais ampla do que o que é distribuído. O **workflow público padrão** é o caminho nativo self-hosted verificado por trás do `bin/souc`, que emite ELF estático Linux x86-64, o único alvo distribuído. O Cranelift JIT não é mais distribuído (CHANGELOG 2.1.0); `souc build --backend gpu` emite PTX apenas para um esqueleto de padrões de kernel nomeados; o backend WASM é um rascunho bloqueado ([#2237](https://github.com/Sounio-lang/sounio/issues/2237)). Veja TOUR.md §6.

## Mapeamento atual do código-fonte

- `self-hosted/native/` cobre o lowering nativo, a codificação de instruções, o tratamento de ABI, a alocação de registradores, os formatos de objeto e as suítes de teste.
- `self-hosted/wasm/` cobre o lowering, a codificação e a construção de módulos, além do código de driver para o caminho WASM.
- `self-hosted/gpu/` cobre PTX, SPIR-V, Metal, trabalho voltado a tensores e os caminhos de lowering para GPU.
- `self-hosted/llvm/` continua presente como uma subárvore separada voltada a esse backend.

## O que os artefatos verificados provam

- **Launcher padrão (`bin/souc`)**: geração de código nativa self-hosted para ELF estático Linux x86-64; veja `artifacts/omega/selfhost_verification_report.v1.json` e `docs/guide/MINIMUM_VIABLE_SOUNIO.md`.
- **JIT**: nenhum distribuído. O Cranelift JIT não é mais distribuído (CHANGELOG 2.1.0).
- GPU: `souc build --backend gpu` emite PTX válido apenas para kernels com corpo vazio (sem aritmética, sem acesso à memória): um esqueleto de emissão, não um backend (TOUR.md §6).
- **Templates self-hosted de GPU**: o compilador padrão (`bin/souc`) compila sintaxe de GPU e executa em modo de fallback via CPU. A CLI `kretikos` constrói pequenos drivers de emissão in-tree para templates predefinidos de PTX/CUBIN: `kretikos emit-ptx` (a partir de
  `self-hosted/gpu/ptx.sio`) e `kretikos emit-cubin` (a partir de
  `self-hosted/gpu/nvidia_bare.sio`). `kretikos bundle` agrupa esses artefatos
  com hashes, verificações estruturais, validação opcional de toolchain/runtime e
  fronteiras explícitas.
- A documentação deve, portanto, distinguir o comportamento do perfil padrão,
  o comportamento do perfil de GPU, o comportamento dos templates self-hosted e
  a amplitude de implementação presente na árvore de código-fonte.

## Faixa de preview do nativo v2

O repositório também mantém uma faixa pública de preview `native-v2` para o
programa de soberania de backend. O antigo alias de compatibilidade
`native-v2-shadow` já foi descontinuado. Esta não é uma nova backend estável
para usuários finais.

- Ela existe para fixar o `RuntimeContext`, a política de registradores do
  target e as expectativas do Machine IR em um artefato legível por máquina.
- O artefato agora distingue o conjunto x86 callee-saved alocável
  (`r12`..`r15`) da ordem de alocação real consumida pelo regalloc e pelo
  lowering (`r15`, `r14`, `r13`, `r12`).
- A faixa de preview atual do `x86-64` agora passa por um caminho real de
  Machine IR + legalização, emite ELFs nativos de núcleo escalar estritos na
  shell self-hosted, publica metadados reais de stack-map/deopt mais um bloco
  concreto de `gc_state` e uma tabela de descritores de objetos gerenciados via
  `RuntimeContext`, emite o esquema de stack-map v2 de root-map/deopt-id/
  elegibilidade-OSR, roteia objetos de heap do native-v2 por uma tabela de
  handles de capacidade fixa para acesso a `alloc`/campo/índice, compila
  overflow de alocação em um trap real de slow-path em runtime, e agora carrega
  um modelo executável de GC mark/compact orientado por descritores, com
  varredura precisa de slots de ponteiro e regras de realocação conscientes de
  pinning; famílias de opcode não suportadas falham de forma fechada (fail
  closed).
- Os emissores `AArch64` e Mach-O existem apenas como código de preview, só de compilação, na árvore de fontes; não são alvos distribuídos (apenas Linux x86-64).

## Confirme o conjunto de backends ativo

```bash
export SOUC_BIN="$(pwd)/bin/souc"
"$SOUC_BIN" info

# Templates de artefato self-hosted de GPU
kretikos emit-ptx vec_add     -o /tmp/kretikos_vec_add.ptx
kretikos emit-ptx vec_sub     -o /tmp/kretikos_vec_sub.ptx
kretikos emit-ptx vec_mul     -o /tmp/kretikos_vec_mul.ptx
kretikos emit-ptx vec_div     -o /tmp/kretikos_vec_div.ptx
kretikos emit-ptx vec_add_f64 -o /tmp/kretikos_vec_add_f64.ptx
kretikos emit-ptx fma         -o /tmp/kretikos_fma.ptx
kretikos emit-ptx fma_f64     -o /tmp/kretikos_fma_f64.ptx
kretikos emit-ptx store_u32_const -o /tmp/kretikos_store_u32.ptx
kretikos emit-metal vec_add          -o /tmp/kretikos_vec_add.metal
kretikos emit-metal ossm_oct_step    -o /tmp/kretikos_ossm.metal
kretikos emit-metal sedenion_cd_step -o /tmp/kretikos_sedenion.metal
kretikos emit-cubin vec_add_f32 -o /tmp/kretikos_vec_add.cubin
kretikos bundle -o /tmp/kretikos-bundle
kretikos bundle -o /tmp/kretikos-validated-bundle --validate-toolchain --validate-runtime

# Artefato de GPU (suporte mais amplo de padrões)
export SOUC_GPU_BIN="$(pwd)/artifacts/omega/souc-bin/souc-linux-x86_64-gpu"
"$SOUC_GPU_BIN" info
"$SOUC_GPU_BIN" build examples/kernel_vec_add.sio --backend gpu -o /tmp/kernel_vec_add.ptx

export SOUNIO_NATIVE_V2_CONTRACT_PATH=/tmp/native_backend_v2_contract.v1.json
"$SOUC_BIN" run self-hosted/compiler/main.sio -- --self-test
```

O artefato canônico com respaldo de gate é `artifacts/omega/native_backend_v2_contract.v1.json`.

## Como escrever docs de codegen que não fiquem desatualizados

- Descreva os diretórios de backend ao discutir a arquitetura de implementação.
- Descreva o artefato JIT verificado ao discutir a experiência padrão do usuário.
- Descreva o artefato de GPU verificado ao discutir a geração de código pública para GPU.
- Descreva apenas caminhos de execução de backend que você validou com o
  artefato e o comando exatos que está documentando.
