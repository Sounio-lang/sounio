# Compilador Self-Hosted

O Sounio inclui um compilador *self-hosted* escrito inteiramente em ficheiros `.sio`. Este compilador é capaz de realizar a análise sintática (*parsing*), a verificação de tipos (*type-checking*), a conversão para representação intermédia (redução para IR), a otimização e a emissão direta de binários nativos ELF x86-64 — sem qualquer dependência do LLVM, do Cranelift ou de geradores de código externos.

## Pipeline de Compilação

```
Origem (.sio) → Lexer → Parser → AST
    → ir/lower.sio → IrModule (IR customizada)
    → Passagens de Otimização (E-graphs, etc.)
    → native/codegen.sio → Código de Máquina x86-64
    → native/elf.sio → Binário ELF Final
```

Este pipeline é totalmente independente do caminho HLIR/LLVM utilizado pelo compilador hospedado em Rust. O backend nativo gera binários ELF diretamente, sem a necessidade de produzir ficheiros de objetos intermédios.

## Módulos Principais

| Módulo | Ficheiro | Propósito |
| :--- | :--- | :--- |
| **Lexer** | `self-hosted/lexer/` | Tokenização do código-fonte |
| **Parser** | `self-hosted/parser/` | Construção da Árvore de Sintaxe Abstrata (AST) |
| **Redução para IR** | `self-hosted/ir/lower.sio` | Conversão da AST para IR e seleção de estratégias |
| **Tipos de IR** | `self-hosted/ir/ir.sio` | Definições de `IrFunction`, `IrModule` e `IrInstr` |
| **Otimizador** | `self-hosted/ir/opt_cleanup.sio` | Simplificações, eliminação de código morto (DCE) e redução de força |
| **Perfil (PGO)** | `self-hosted/ir/profile.sio` | Leitura de dados `.sprof` e decisão de estratégias de otimização |
| **Inliner** | `self-hosted/ir/inline.sio` | Integração de funções (*inlining*) orientada por dados de perfil |
| **Layout** | `self-hosted/ir/layout.sio` | Ordenação de funções em memória para otimizar a localidade de cache |
| **E-graph** | `self-hosted/ir/egraph.sio` | Saturação de igualdade para leis e identidades algébricas |
| **Codegen** | `self-hosted/native/codegen.sio` | Geração e emissão de instruções de máquina x86-64 |
| **Frame** | `self-hosted/native/frame.sio` | Desenho do *stack frame* e alocação local de registadores |
| **ELF** | `self-hosted/native/elf.sio` | Estruturação e gravação do ficheiro binário ELF final |
| **Relocações** | `self-hosted/native/reloc.sio` | Ajuste de endereços e interligação de símbolos |
| **Entrada** | `self-hosted/compiler/main.sio` | Orquestração global e interface de linha de comandos (CLI) |

## Passagens de Otimização

O otimizador *self-hosted* executa mais de 20 passos distintos, desenvolvidos de forma incremental ao longo do projeto:

- **Constant folding:** Avalia operações aritméticas de constantes conhecidas em tempo de compilação.
- **Dead code elimination (DCE):** Algoritmo *mark-and-sweep* para detetar e remover instruções cujos resultados nunca são lidos.
- **Strength reduction:** Substitui operações dispendiosas por equivalentes mais velozes (ex: `x * 2^n` por shifts `x << n`, `x % 2^n` por `x & (2^n - 1)`).
- **Copy propagation:** Propaga atribuições diretas de `IrCopy` para expor novas oportunidades de simplificação.
- **Peephole optimization:** Elimina redundâncias locais, tais como `IrCopy(r, r)` para `IrNop` ou cargas redundantes de imediatos.
- **Normalização algébrica:** Simplificações identitárias como `x - x` para `0`, `x ^ x` para `0` e redução de cadeias de constantes como `(x + 3) + 5` para `x + 8`.
- **Saturação de E-graphs:** Aplicação sistemática de associatividade, comutatividade e identidades algébricas para reduzir a complexidade lógica.
- **CSE (Common Subexpression Elimination):** Deduplicação de expressões comuns usando tabelas de dispersão (*hash*) locais.
- **LICM (Loop Invariant Code Motion):** Desloca expressões invariantes (como `IrLoadImm` constantes) para fora de ciclos.
- **GVN (Global Value Numbering):** Atribuição de números de valor únicos a expressões equivalentes para otimização global.
- **Simplificação booleana:** Simplifica negações encadeadas e avaliações redundantes (ex: `(x == 0) == 0` torna-se `x`).
- **Folding de ramificações:** Avalia condições estáticas de saltos transformando `BranchTrue(constante)` em saltos incondicionais ou `IrNop`.

## Alocação de Registadores

O backend nativo adota um alocador de registadores por varrimento linear (*linear-scan*) limitado a 4 registadores de uso geral: `r12`, `r13`, `r14` e `r15` (preservados pelo chamado — *callee-saved*). Quando ocorrem salvaguardas para a pilha (*spills*), o gerador de código adota uma codificação adaptativa `disp8`/`disp32` para reduzir ao mínimo o tamanho do binário gerado.

## Otimização Guiada por Perfil (PGO)

O compilador inclui suporte nativo a um fluxo de otimização baseado em dados de execução real:

1. **Instrumentação:** O compilador injeta opcodes `IrProfCounter` (gerando instruções nativas `INC [RIP+disp32]`) no ponto de entrada das funções.
2. **Gravação de Perfil:** A chamada runtime `__prof_dump` gera ficheiros `.sprof` contendo a frequência de execução exata de cada função.
3. **Seleção de Estratégia:** Funções com elevado tráfego (mais de 1.000 chamadas) são promovidas a `AGGRESSIVE`, enquanto funções moderadas avançam para `PRECISION`.
4. **Inlining Inteligente:** A prioridade de integração de funções incorpora bónus derivados do perfil de execução quente.
5. **Reordenação de Layout:** Funções críticas são agrupadas no início da secção de texto do binário ELF para reduzir falhas de cache de instruções.

## Como Executar o Compilador Self-Hosted

```bash
SOUC=./bin/souc

# Corre os testes internos de conformidade e otimização
$SOUC run self-hosted/compiler/main.sio -- --self-test

# Apenas verificação sintática e semântica (sem geração de código)
$SOUC run self-hosted/compiler/main.sio -- --check

# Dump da representação intermédia (IR) de uma função específica
$SOUC run self-hosted/compiler/main.sio -- --ir-dump --fn=main
```

## Verificação e Conformidade

A estabilidade e robustez do compilador *self-hosted* são validadas continuamente através de mais de 347 testes internos focados em garantir a precisão e a correção de cada passo do otimizador. As diretivas rigorosas de integração impedem a introdução de regressões sem a validação verde de todos os cenários.
