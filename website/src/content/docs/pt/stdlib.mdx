# Biblioteca Padrão

A biblioteca padrão é grande, ativa e de maturidade mista. Uma página abrangente sobre a stdlib precisa explicar não apenas o que está presente, mas também como distinguir APIs ativas e chamáveis de superfícies stub e de inventário desativado.

## Como ler a stdlib com segurança

- Trate módulos `active_callable` como superfície pública real, respaldada por testes ou gates.
- Trate módulos `stub_surface` como apenas forma: úteis para roadmap e rastreamento de compatibilidade, não como promessas fortes de API.
- Trate arquivos `*.sio.disabled` como inventário de trabalho futuro, não como suporte atual.

## Onde inspecionar a verdade

- `stdlib/` contém o código e o layout de módulos.
- `tests/stdlib/` contém as verificações de execução e contrato mais importantes.
- `artifacts/stdlib/stdlib_reliability_status.v1.json`, `stdlib_science_pipeline_status.v1.json` e `stdlib_hyper_execution_status.v1.json` são os artefatos canônicos de status legíveis por máquina.
- `docs/stdlib/STDLIB_REFERENCE.md` é a página de referência voltada ao repositório para o snapshot executável da stdlib.

## Reproduza os principais gates da stdlib

```bash
bash scripts/scan_stdlib.sh --json-out artifacts/stdlib/stdlib_inventory.v1.json
bash scripts/stdlib/stdlib_hyper_execution_gate.sh
STDLIB_RUNTIME_REGRESSION_STRICT=1 bash scripts/stdlib_science_pipeline_gate.sh
STDLIB_RUNTIME_REGRESSION_STRICT=1 bash scripts/stdlib_reliability_gate.sh
```

## Orientação prática

- Ao escrever documentação ou exemplos, comece a partir de testes ativos, não de nomes de diretório.
- Se um módulo está presente, mas seu melhor teste atual é apenas uma checagem de import ou de forma, descreva-o como uma superfície limitada ou stub.
- Use os artefatos de status quando precisar de contagens exatas ou de afirmações no nível de faixa (lane).
