# Tipos Epistêmicos

Sounio foi projetado para computação científica e regulada, onde um valor raramente é "apenas um número". Medições e quantidades derivadas deveriam carregar:

- incerteza (metrologia)
- confiança/credibilidade (trust)
- proveniência (origem + histórico de transformações)

## Os Quatro Tipos Epistêmicos

Sounio tem quatro tipos wrapper epistêmicos de primeira classe. Todos compartilham os campos `.value: T` e `.epsilon: f64` (o score de confiança, 0–1).

### Knowledge\<T\>

Envolve uma medição com incerteza e proveniência. É o tipo epistêmico fundamental.

```sio
let dose: Knowledge<mg> = Knowledge(500.0, ε=0.97, prov="run_042")

if dose.epsilon > 0.95 {
  approve_for_decision(dose)
} else {
  request_remeasurement(dose)
}
```

Extrair um `T` puro exige uma operação explícita com uma string de motivo — você não consegue descartar metadados epistêmicos por acidente:

```sio
let raw: mg = dose.unwrap("override manual, auditado")
```

### Validated\<T\>

Um valor que passou por uma verificação formal de threshold torna-se `Validated<T>` — um tipo distinto que o compilador trata diferentemente de um `Knowledge<T>` bruto.

```sio
let safe: Validated<mg> = validate(dose, threshold: 0.95)

// Validated<T> pode ser passado a funções que exigem segurança comprovada
administer(safe)
```

### Intervention\<T\>

Representa uma intervenção causal — o operador do-calculus `do(X=x)`. O campo `.epsilon` carrega a confiança na estimativa da intervenção.

```sio
// Intervenção causal: do(Treatment = active)
let treated: Intervention<bool> = intervene(true)

if treated.epsilon > 0.90 {
  run_rct_arm(treated)
}
```

### Counterfactual\<T\>

Representa uma consulta contrafactual — o que uma variável *teria sido* em condições diferentes. A confiança em um contrafactual reflete identificabilidade e qualidade do modelo.

```sio
// Qual seria o salário se Alice tivesse educação?
let cf: Counterfactual<f64> = counterfactual(
  observed: 30000.0,
  under: education_iv
)

if cf.epsilon > 0.90 {
  report_finding(cf)
}
```

## O que Funciona Hoje (Realidade do Compilador)

Todos os quatro tipos são analisados, verificados por tipo e compilados pelo pipeline completo (HIR → SIR → HLIR → ELF nativo):

- Construção: `Knowledge(...)`, `validate(...)`, `intervene(...)`, `counterfactual(...)`
- Acesso a campos: `.value`, `.epsilon`
- Gates de confiança: `if x.epsilon > threshold { ... }`
- Unwrap: `.unwrap("motivo")` para extrair um `T` puro

## Especificação vs Implementação

O design completo busca comportamento mais rico: propagação de incerteza com base em princípios, monotonicidade de confiança e proveniência append-only sob transformações puras.

Parte disso vive na spec e nos docs de design da stdlib, mesmo que a aplicação varie por modo do compilador e feature flags hoje.
