# Primeiros Passos

Este guia é o ponto de entrada prático para o workflow público atual do Sounio. Ele parte do princípio de que você está começando pelo artefato do compilador já versionado no repositório, validando com `souc check`, e tratando os gates e fixtures do repositório como a fonte de verdade sobre o que realmente é suportado agora.

## Contrato atual

- O ponto de entrada documentado mais seguro é o launcher canônico em `$(pwd)/bin/souc`.
- A primeira coisa em que confiar é o `check`, não o `run`, porque os caminhos de execução variam conforme o artefato do host e o suporte de backend.
- O launcher verificado reporta `souc 1.0.0-beta.5` atualmente (o badge do README pode indicar `1.0.0-beta.6` durante a reconciliação de release). O workflow público padrão é **nativo self-hosted para ELF/Mach-O** — não um build via Rust/Cargo, e não o Cranelift JIT como história de onboarding.
- O status com respaldo de gate está atualmente forte para a faixa de confiabilidade da stdlib (`251/251` no artefato commitado), para as faixas científicas `fmri` e `darwin_pbpk`, e para as sete faixas de hyper-execution obrigatórias.
- Perfis omega opcionais (Cranelift JIT, GPU) existem separadamente do contrato padrão do `bin/souc`. Confirme a capacidade com `souc info` antes de documentá-la como disponível.

## Faça o bootstrap da toolchain verificada

```bash
git clone https://github.com/sounio-lang/sounio.git
cd sounio

export SOUC_BIN="$(pwd)/bin/souc"
export SOUNIO_STDLIB_PATH="$(pwd)/stdlib"

"$SOUC_BIN" --version
"$SOUC_BIN" info
"$SOUC_BIN" sysroot stdlib-paths
```

## Sequência de validação usada por esta documentação

- `"$SOUC_BIN" check examples/hello.sio` confirma que a CLI básica e o caminho da stdlib estão conectados corretamente.
- `"$SOUC_BIN" check tests/run-pass/covid_2020_kernel.sio` valida uma fixture científica epistêmica atual.
- `"$SOUC_BIN" check tests/run-pass/vancomycin_propagation.sio` valida o caminho atual de propagação de confiança.
- `"$SOUC_BIN" check tests/compile-fail/vancomycin_low_conf.sio` deve falhar com o mismatch de confiança documentado, provando que o caminho de recusa está ativo.

## Onde olhar em seguida no repositório

- `examples/` contém os menores programas de onboarding, mas nem todo arquivo ali deve ser tratado como igualmente pronto para produção.
- `tests/run-pass/` e `tests/compile-fail/` são a melhor evidência do comportamento de linguagem que deveria funcionar hoje.
- `artifacts/stdlib/*.json` registram o status com respaldo de gate para confiabilidade da stdlib, faixas científicas e hyper execution.
- `docs/guide/MINIMUM_VIABLE_SOUNIO.md` explica o contrato conservador que este site segue.

## Primeiro programa mínimo

```sio
fn main() with IO {
    println("Hello, Sounio!")
}
```

## Ressalvas antes de ir mais fundo

- Não trate um build via Cargo no nível raiz como o caminho principal de onboarding público; ele já não é a história mais clara para o estado atual deste repositório.
- Não infira suporte apenas pela presença de um diretório. O repositório contém implementações ativas, stubs, arquivos desativados e experimentos de longo horizonte lado a lado.
- Se você precisar de mais do que o launcher self-hosted verificado expõe, confirme essa capacidade com `souc info` ou reconstruindo um perfil de artefato diferente antes de documentá-la como disponível.
