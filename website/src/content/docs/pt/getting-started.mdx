Comece com um compilador compatível, verifique um programa pequeno e depois execute-o. Este guia usa o inicializador canônico do repositório, `./bin/souc`, cujo compilador padrão é o Madaros. No Linux x86-64 os comandos abaixo são o caminho inteiro. O [INSTALL.md](https://github.com/Sounio-lang/sounio/blob/main/INSTALL.md) (em inglês) repete os mesmos comandos.

## Pré-requisitos

No Linux x86-64 você precisa de:

- `git`
- `bash`
- `gzip` — a primeira invocação de `./bin/souc` descompacta o pré-compilado versionado
- `sha256sum` do GNU coreutils
- cerca de 2 GB de disco livre

Medido em 27 de outubro de 2026, Linux x86-64, `main` em `75fd75c587a799169d59954cd50f2f327eed5f4e`: `git clone --depth 1` ocupou 1,1 GB. O primeiro `./bin/souc` então gravou `bin/madaros-linux-x86_64` (129.918.841 bytes). A árvore ficou em 1,3 GB depois disso. Um clone sem `--depth 1` também baixa o histórico e é maior.

O macOS ARM64 não executa esse ELF de Linux. As ferramentas dele estão no [guia de macOS ARM64](https://github.com/Sounio-lang/sounio/blob/main/docs/compiler/MADAROS_MACOS_ARM64.md) (em inglês).

## Obtenha o repositório

```sh
git clone --depth 1 https://github.com/Sounio-lang/sounio.git
cd sounio
git rev-parse HEAD
uname -sm
```

`--depth 1` busca o commit atual, não o histórico. Guarde a revisão que `git rev-parse HEAD` imprime e escolha a preparação adequada ao seu sistema:

| Sistema | Preparação |
| --- | --- |
| Linux x86_64 | Continue com os comandos das duas seções seguintes. |
| macOS ARM64 (Apple Silicon) | Primeiro compile e instale o artefato nativo, seguindo o [guia de macOS ARM64](https://github.com/Sounio-lang/sounio/blob/main/docs/compiler/MADAROS_MACOS_ARM64.md) (em inglês). O ELF de Linux não roda nativamente no macOS. |
| Outros sistemas | Estas instruções não fornecem um pré-compilado compatível. Consulte o guia de instalação antes de continuar. |

A compilação nativa para macOS exige um executável de bootstrap gerado do código-fonte atual, assinado e com permissão de execução, ferramentas de linha de comando da Apple com `clang++` compatível com C++23 e `codesign`, o comando `timeout` e os cabeçalhos Boost. A validação completa da instalação também exige um dispositivo Metal real. O [guia nativo](https://github.com/Sounio-lang/sounio/blob/main/docs/compiler/MADAROS_MACOS_ARM64.md) detalha esses pré-requisitos e instala `artifacts/self-hosted/madaros-arm64-macos`, preferido pelo inicializador no Apple Silicon após as substituições explícitas de binário. Apenas clonar o repositório não basta nessa plataforma.

Nenhum desses caminhos começa com `cargo build` na raiz do repositório.

## Identifique o compilador

No Linux x86-64, a partir da raiz do repositório:

```sh
export SOUNIO_STDLIB_PATH="$PWD/stdlib"
./bin/souc info
./bin/souc --version
```

O compilador versionado está em `bin/madaros-linux-x86_64.gz`. A primeira invocação de `./bin/souc` descompacta esse arquivo para `bin/madaros-linux-x86_64` e imprime uma linha em stderr com um prefixo sha256 e a contagem de bytes. As execuções seguintes reutilizam o arquivo.

`bin/souc` é um inicializador. Inspecione o caminho `raw_elf` informado por `info`: substituições explícitas e artefatos locais podem selecionar um compilador diferente do pré-compilado versionado. `./bin/souc --version` imprime linhas de proveniência em stderr e a versão em stdout. Guarde essa identidade junto dos resultados. Não troque de compilador para contornar uma falha de plataforma ou de preparação.

O arquivo de checksum nomeia `madaros-linux-x86_64` sem diretório. Execute-o a partir de `bin/`, depois da primeira invocação de `./bin/souc`. Antes disso o ELF não está no disco, e a verificação não consegue abri-lo. Na raiz do repositório, `sha256sum -c bin/madaros-linux-x86_64.sha256` procura o ELF no diretório atual e falha.

```sh
(cd bin && sha256sum -c madaros-linux-x86_64.sha256)
```

Uma correspondência imprime `madaros-linux-x86_64: OK`.

## Verifique e execute o primeiro exemplo

Quando o compilador selecionado for compatível com a sua plataforma:

```sh
./bin/souc check examples/hello.sio
./bin/souc run examples/hello.sio
```

Execute o segundo comando somente se a verificação passar. `souc --help` não lista `--quiet` nem `--silent`. `run` imprime linhas de log do compilador e depois a saída do próprio programa. A mensagem esperada é `Hello, Sounio`, com código de saída zero. Essas linhas de log são do compilador, não do programa.

`./bin/souc compile examples/hello.sio -o hello.elf` grava um ELF e não imprime `Hello, Sounio`. Esse passo não é necessário para ver a mensagem.

Guarde a saída real e o código de saída: passar na verificação não comprova o comportamento em execução, e estas instruções não são um relato de nova execução.
