# Sistema de Modulos

Sounio organiza codigo em modulos. Um arquivo pode se declarar como um module com uma instrucao `module` explicita, ou permanecer no namespace plano se nenhuma declaracao estiver presente.

## Declarando um module

```sio
// file: ir/profile.sio
module ir::profile

fn sprof_parse(data: &str) -> SprofProfile {
    // ...
}

fn sprof_lookup(profile: &SprofProfile, name: &str) -> i64 {
    // ...
}
```

A declaracao `module ir::profile` coloca todas as definicoes deste arquivo sob o namespace `ir::profile`.

## Importando de modulos

Use `use` para trazer nomes ao escopo:

```sio
// Wildcard import — brings all public names into scope
use ir::profile::*

// The functions are now available directly
let profile = sprof_parse(data)
let count = sprof_lookup(profile, "main")
```

Importacoes seletivas tambem sao suportadas:

```sio
use ir::profile::{sprof_parse, sprof_lookup}
```

**Importante:** Importacoes wildcard (`use module::*`) sao atualmente mais confiaveis do que importacoes seletivas para modulos que tem funcoes auxiliares internas. Alguns helpers internos podem falhar na resolucao com importacoes seletivas — prefira wildcard na duvida.

## Arquivos de namespace plano

Arquivos sem uma declaracao `module` estao no namespace plano. Suas definicoes ficam disponiveis diretamente para qualquer arquivo que possa ve-las, sem uma instrucao `use` explicita:

```sio
// file: ir/normalize.sio
// (no module declaration)

fn normalize_instruction(instr: &!IrInstr) {
    // available without import in other flat-namespace files
}
```

Arquivos como `normalize.sio`, `const_prop.sio`, `dce.sio` e `ssa.sio` no compilador self-hosted usam esse padrao.

## Regras de resolucao de modulos

1. Um arquivo com `module X::Y` deve ser importado com `use X::Y::*` ou `use X::Y::{nome}`.
2. Um arquivo sem `module` esta no namespace plano — seus nomes ficam visiveis sem imports.
3. Referencias antecipadas (forward references) nao sao suportadas: helpers devem ser definidos antes dos chamadores no arquivo fonte.
4. Caminhos de modulo mapeiam para caminhos do sistema de arquivos: `module ir::profile` corresponde a `ir/profile.sio`.

## Combinando modulos e arquivos planos

O compilador self-hosted mistura ambos os padroes:

```sio
// main.sio — uses both module and flat-namespace imports
use ir::ir::*           // module import: IrFunction, IrModule, etc.
use ir::profile::*      // module import: SprofProfile, sprof_parse, etc.
use ir::inline::*       // module import: inl_run_pass, etc.

// normalize.sio, const_prop.sio are flat — no import needed
```

## Orientacoes praticas

- Use `module` para bibliotecas e componentes reutilizaveis com interfaces claras.
- Use namespace plano para arquivos de implementacao fortemente acoplados que compartilham muitos helpers internos.
- Sempre use `use parser::ast::*` (wildcard) ao importar tipos AST — importacoes seletivas podem quebrar comparacoes de operadores em variantes de enum.
