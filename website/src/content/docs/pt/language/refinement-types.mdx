# Tipos Refinados (*Refinement Types*)

Um tipo refinado (*refinement type*) estende um tipo base adicionando-lhe um predicado lógico. O compilador utiliza um resolvedor SMT (neste caso, o Z3) para verificar formalmente se os valores atribuídos satisfazem essa restrição lógica em tempo de compilação, prevenindo erros de limites (*out-of-bounds*) e violações físicas antes mesmo de o programa ser executado.

## Sintaxe de Definição

```sio
type Positive = { x: i32 | x > 0 }
type Percentage = { p: f64 | p >= 0.0 && p <= 100.0 }
type NonEmpty<T> = { arr: [T] | len(arr) > 0 }
```

O predicado posicionado após a barra vertical (`|`) deve corresponder a uma expressão booleana pura, composta unicamente por variáveis locais, parâmetros vinculados e valores constantes. O compilador converte esta expressão numa asserção lógica delegada ao resolvedor Z3.

## Aplicação Prática

```sio
fn safe_divide(a: f64, b: { b: f64 | b != 0.0 }) -> f64 {
    a / b
}

fn main() with IO {
    let result = safe_divide(10.0, 3.0)   // Correto: Prova direta de que 3.0 != 0.0
    println(result)

    // safe_divide(10.0, 0.0)  // Erro de Compilação: Impossível provar que 0.0 != 0.0
}
```

Quando é fornecido um valor literal, o resolvedor valida a condição imediatamente. Ao passar uma variável dinâmica, o compilador utiliza os refinamentos conhecidos e preestabelecidos associados à declaração original dessa variável.

## Exemplo em Dosagem Farmacológica

Os tipos refinados revelam-se extremamente vantajosos em contextos científicos e industriais, onde os limites físicos e de segurança operacional são imperativos:

```sio
type ValidDose = { dose: mg | dose > 0.0 && dose <= 2000.0 }

fn administer(patient_id: i64, dose: ValidDose) with IO {
    println("Administrando dose prescrita...")
}

fn main() with IO {
    let dose: mg = 500.0
    administer(1, dose)     // Correto: 500.0 encontra-se dentro do intervalo válido [0, 2000]

    // let bad: mg = 5000.0
    // administer(1, bad)   // Erro de Compilação: 5000.0 ultrapassa o limite de 2000.0
}
```

## Interação com Tipos Epistémicos

Os predicados de refinamento operam em perfeita harmonia com o tipo `Knowledge<T>`: um valor do tipo `Knowledge<ValidDose>` transporta em simultâneo os envelopes de propagação de incerteza e a validação lógica do intervalo. O compilador processa ambos de forma independente: o refinamento atua no valor nominal, enquanto a propagação de confiança avalia as margens de incerteza experimental.

## Estrutura de Implementação

- **Módulo de Verificação:** Localizado em `self-hosted/check/refinements.sio`.
- **Ligação ao SMT:** Implementado em `compiler/src/smt/` (bindings do resolvedor Z3, dependente da flag de compilação `smt`).
- **Artefactos Nativos:** Os binários genéricos distribuídos por omissão (`souc-linux-x86_64`) não incluem o resolvedor SMT ativado para minimizar dependências dinâmicas; a verificação integral de refinamentos requer a compilação local com a flag `--features smt`.

## Limitações Atuais

- **Construção:** A integração nativa com o resolvedor Z3 requer a flag `--features smt` durante a compilação do compilador.
- **Formas Suportadas:** O resolvedor lida de forma estável com relações aritméticas, operadores booleanos clássicos e dimensões básicas de coleções (*arrays*). O suporte a chamadas de funções personalizadas no interior do predicado ainda se encontra em desenvolvimento.
- **Salvaguarda de Execução:** É disponibilizada uma verificação dinâmica em tempo de execução (*runtime assertions*) para os predicados que excedam a capacidade de verificação puramente estática.
