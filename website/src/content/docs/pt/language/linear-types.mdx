# Linear Types & Ownership

Sounio garante seguranca de recursos por meio de linear types (tipos lineares). Um valor linear deve ser usado exatamente uma vez: voce nao pode silenciosamente descartar um file handle, conexao de banco de dados ou buffer de GPU. O compilador rejeita programas que esquecem de consumir recursos lineares.

## Structs lineares

Marque uma struct como `linear` para exigir consumo exatamente uma vez:

```sio
linear struct FileHandle {
    fd: i32
}

fn open_file(path: &str) -> FileHandle with IO {
    // OS-level open; returns a linear handle
    FileHandle { fd: sys_open(path) }
}

fn close_file(handle: FileHandle) with IO {
    sys_close(handle.fd)
    // handle is consumed here — compiler satisfied
}

fn main() with IO {
    let h = open_file("/tmp/data.txt")
    // If we forget close_file(h), the compiler rejects this program.
    close_file(h)
}
```

Se voce remover a chamada `close_file(h)`, o compilador emite um erro: o valor linear `h` nao foi consumido.

## Referencias: compartilhadas vs exclusivas

Sounio usa `&T` para referencias compartilhadas (somente leitura) e `&!T` para referencias exclusivas (mutaveis). Isso nao e o `&mut` do Rust — o sigilo `&!` sinaliza acesso exclusivo.

```sio
fn read_value(r: &i64) -> i64 {
    *r
}

fn increment(r: &!i64) {
    *r = *r + 1
}

fn main() with IO {
    var x = 10
    println(read_value(&x))   // shared borrow
    increment(&!x)            // exclusive borrow
    println(x)                // prints 11
}
```

O compilador impede que uma referencia exclusiva tenha alias com qualquer outra referencia ao mesmo valor.

## Semantica de move

Valores que nao sao `Copy` sao movidos na atribuicao. Apos um move, o binding original deixa de ser valido:

```sio
fn consume(h: FileHandle) with IO {
    close_file(h)
}

fn main() with IO {
    let h = open_file("/tmp/data.txt")
    consume(h)
    // h is no longer valid here — using it is a compile error
}
```

## Relaxamento affine

Alguns tipos sao affine em vez de estritamente lineares: devem ser usados *no maximo* uma vez, mas podem ser descartados silenciosamente. Tipos escalares padrao (`i32`, `i64`, `f64`, `bool`) sao `Copy` e podem ser usados livremente. Structs customizadas sem a palavra-chave `linear` seguem semantica de move, mas nao sao obrigadas a ser consumidas.

## Onde o ownership checking e implementado

O verificador de ownership esta implementado em `self-hosted/check/ownership.sio` e roda apos a verificacao de tipos. Ele rastreia quais bindings foram movidos, quais estao emprestados (borrowed), e aplica o contrato de linearidade para tipos `linear struct`.

## Ressalvas

- Campos lineares aninhados em structs nao-lineares sao rastreados recursivamente.
- O verificador atual ainda nao trata todos os padroes envolvendo valores lineares dentro de arms de `match` ou closures — consulte a pagina de status de features para a cobertura atual.
- Mutacoes via `&!` pelo JIT Cranelift tem uma limitacao conhecida: prefira padroes de retorno por valor para mutacoes que precisam ser visiveis ao chamador.
