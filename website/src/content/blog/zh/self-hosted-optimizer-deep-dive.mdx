# 60次优化冲刺

在过去的60次冲刺中，我们在Sounio中完全用Sounio自身构建了一个完整的优化原生后端。本文将介绍架构、关键优化通过程序以及我们在此过程中学到的知识。

## 起点

第50次冲刺交付了第一个基于配置的函数布局通过程序。到那时，自托编译器可以解析Sounio源代码，将其降低为自定义IR（`IrModule`/`IrFunction`/`IrInstr`），并将x86-64机器代码生成到ELF二进制文件中。但是生成的代码是朴素的：每个值都住在堆栈上，每个常量都被加载成新鲜值，到处都存在死代码。

## 优化栈

我们逐步构建了通过程序，每个通过程序都由一个门脚本验证，该脚本报告了PASS/FAIL/NOT_RUN计数。以下是进展：

### 阶段1：经典数据流（Sprint 51-54）**常量折叠** (`ocp_const_fold`): 通过 `def_at[256]` 和 `val_at[256]` 数组跟踪哪些虚拟寄存器持有已知常量。当 `IrBinOp` 的两个操作数都是已知的，将其折叠为 `IrLoadImm`。这解锁了后续的所有操作。

**死代码消除** (`ocp_dce`): 遍历指令数组。标记所有被任何指令读取的寄存器，然后清除：任何具有未使用的目的寄存器和没有副作用的指令变成 `IrNop`。

**复制传播**: 追踪 `IrCopy` 链，以便 `IrCopy(r5, r3)` 其中 `r3 = IrLoadImm(42)` 允许 `r5` 参与常量折叠。

**微优化**: `IrCopy(r, r)` → `IrNop`。消除重复的 `IrLoadImm`。这些操作在寄存器分配清理 IR 后触发。

### 第 2 阶段：强度减少（Sprint 62-68）

**幂二的算术**: `x * 2^n` → `x << n`, `x / 2^n` → `x >> n`, `x % 2^n` → `x & (2^n - 1)`。常量折叠中的 `def_at` 跟踪告诉我们除数/乘数是一个已知的幂次方。**非2的幂次乘法**：`x * 3` → `(x + x) + x`。小的常数乘法变成移位加序列。

**恒等/湮灭**：`x * 1` → `IrCopy`，`x * 0` → `IrLoadImm(0)`，`x + 0` → `IrCopy`，`x - 0` → `IrCopy`，`x / 1` → `IrCopy`。

### 第3阶段：代数推理（第71至77冲刺）

**同寄存器折叠**：`x - x` → `IrLoadImm(0)`，`x ^ x` → `IrLoadImm(0)`。如果两个操作数都是同一个虚拟寄存器，那么减法或异或的结果总是0。

**关联链折叠**：`(x + 3) + 5` → `x + 8`。当一个加法操作数是另一个加法操作数加上已知常数时，合并常数。

**E-图饱和**：我们实现了一个小的e-图引擎（`EgNode`/`EgClass`/`EgUnionFind`），通过重写规则和并查集发现等价关系，如`x * 0 = 0`。e-图在小型函数（≤8条指令）时激活，以保持编译时间有界。**交换律CSE**：通过按`src1 ≤ src2`排序操作数，标准化交换律操作（加、乘、或、与、异或）。这将CSE哈希表的命中率翻倍。

### 第四阶段：控制流（第75-76、101-106个冲刺）

**条件分支折叠**：`IrBranchTrue(known_const)`，其中常量为1 → `IrJump`。其中常量为0 → `IrNop`。这清理了在常量传播证明条件后分支。

**跳转至返回**：`IrJump(L)`，其中`L+1 = IrReturn`折叠为`IrReturn`。

**布尔简化**：`(x == 0) == 0` → `IrCopy(x)`，`bool != 0` → `IrCopy(bool)`。

**LICM**：将循环不变`IrLoadImm`指令越过回边提升。

**GVN**：使用128项哈希表和值编号分配的全局值编号。

## 寄存器分配

线性扫描分配器针对四个调用者保存寄存器(`r12`-`r15`)使用自适应`disp8`/`disp32`编码进行堆栈溢出。紧凑的帧大小确保函数使用不超过4个活跃值时没有堆栈帧。

## 基于配置的优化完整的PGO流水线：
1. 在受监控函数入口处注入`INC [RIP+disp32]`计数器。
2. `__prof_dump`在退出时将执行计数写入`.sprof`文件。
3. 使用`--use-profile profile.sprof`重新编译以提升热点函数。
4. 基于轮廓引导的展开根据策略加分（AGGRESSIVE加80，PRECISION加40）评估调用者。
5. 布局阶段将热点函数排序到前端以提升指令缓存局部性。

## 验证

每个优化阶段都有一个门脚本。当前测试矩阵在所有阶段共有**347个自测试**，其中FAIL=0，NOT_RUN=1（JIT OOM在全自测试中）。每个门脚本运行时间低于60秒。

## 下一步

基础牢固。原生后端为算术、控制流、函数调用和轮廓仪器化生成正确的ELF二进制文件。下一个前沿是缩小全自托管编译循环的差距——其中自托管编译器自身编译为原生二进制。代码全部在 `self-hosted/` 目录下，包括每个阶段、每个测试、每个网关脚本——都是用 Sounio 编写的。
