# 60回の最適化

過去の60回のスリートでは、Sounio自身で書かれたSounioに書かれたコンパイラのネイティブバックエンドを完全に構築しました。この記事はアーキテクチャ、重要な最適化パス、そしてその過程で学んだことを説明します。

## 開始点

第50回スリートでは最初のプロファイルガイド関数レイアウトパスが交付されました。その時点で、自分に書かれたコンパイラはSounioソースを解析し、カスタムIR (`IrModule`/`IrFunction`/`IrInstr`)に下げ、ELFバイナリにx86-64マシンコードを出力していました。しかし、生成されたコードは単純でした。すべての値はスタックに存在し、すべての定数は新しくロードされ、死コードはどこにあっても残っていました。

## 最適化スタック

パスを増分に構築し、各パスはゲートスクリプトによってパス、失敗、または実行しないと報告されるようにしました。以下は進化の経路です：

### フェーズ1：古典的なデータフロー（スリート51-54）**定数展開** (`ocp_const_fold`): `def_at[256]` と `val_at[256]` 配列を介して、既知の定数を保持する仮想レジスターをトラック。`IrBinOp` の両辺のオペランドが既知の場合、`IrLoadImm` に折らします。これは後ろのすべてを解鎖します。

**無効コード削除** (`ocp_dce`): 指令配列をマークスweepします。すべてのレジスターを使用する指令をマークし、スウィープします: 使用されていない出力と副作用のない指令は `IrNop` になります。

**コピー伝播**: `IrCopy` チェーンをトレースして、`IrCopy(r5, r3)` で `r3 = IrLoadImm(42)` の場合、`r5` が既知の定数への参与を可能にします。

**ピピホール**: `IrCopy(r, r)` → `IrNop`。重複した `IrLoadImm` の削除。常数展開でレジスター割り当ての後に IR を整理する後にこれらが発火します。

### 第2段階: 強度削減 (スプリント 62-68)

**二の冪算術**: `x * 2^n` → `x << n`, `x / 2^n` → `x >> n`, `x % 2^n` → `x & (2^n - 1)`。常数展開での `def_at` トラッキングが除数/乗数が既知の二の冪であることを知らせます。**二乗数の倍**: `x * 3` → `(x + x) + x`。小さな定数の倍はシフト加算の列になります。

**単一値/消滅**: `x * 1` → `IrCopy`, `x * 0` → `IrLoadImm(0)`, `x + 0` → `IrCopy`, `x - 0` → `IrCopy`, `x / 1` → `IrCopy`。

### 第3段: 代数の推理 (スプリント71-77)

**同じレジスターの折り畳み込み**: `x - x` → `IrLoadImm(0)`, `x ^ x` → `IrLoadImm(0)`。加算またはXORの両辺の源レジスタが同じ仮想レジスタである場合、結果は常に0です。

**関連付けの連鎖の折り畳み込み**: `(x + 3) + 5` → `x + 8`。加算の一つのオペランドが既知の定数と組み合わせたものの加算である場合、定数を組み合わせます。

**Eグラフの飽和**: 小さな関数 (≤ 8 指令) を保持するためにコンパイル時間を bounded に保つために、`EgNode`/`EgClass`/`EgUnionFind` という小さな e-グラフエンジンを実装しました。この e-グラフは、`x * 0 = 0` のような等価性を再書きルールと Union-Find を介して発見します。**共帰性CSE**: 共帰性演算 (加算、乗算、または、合取、または、排他積) の値を `src1 ≤ src2` でソートすることで、CSEハッシュテーブルのヒット率を二倍にすることができます。

### フェーズ4: 制御構造 (スプリント75-76、101-106)

**条件分岐の折り縦切り**: `IrBranchTrue(known_const)` で、定数が1の場合は `IrJump` に、定数が0の場合は `IrNop` に変換されます。これは定数伝播が条件を証明した後にブランチを整理することです。

**返り先へのジャンプ**: `IrJump(L)` で、`L+1 = IrReturn` の場合は `IrReturn` に直接変換されます。

**ブール値の単純化**: `(x == 0) == 0` → `IrCopy(x)`、`bool != 0` → `IrCopy(bool)`。

**LICM**: ループ不変の `IrLoadImm` 命令を後ろの辺を超えて上げます。

**GVN**: 128エントリのハッシュテーブルと値番号割り当てを伴うグローバル値番号付けです。

## レジスター割り当て

線形スキャンアロケーターは、適応的 `disp8`/`disp32` エンコーディングを使ってスタックスペイルを伴い、4つの呼び出し元守られたレジスター (`r12`-`r15`) をターゲットにします。コンパクトなフレームサイズにより、4個以下のライブ値を持つ関数は全くスタックフレームを使用しません。

## プロファイルガイドされた最適化全ての PGO パイプライン:
1. インストーイング済み関数の開始時に `INC [RIP+disp32]` カウンターを注入する。
2. `__prof_dump` は終了時に `.sprof` ファイルに実行回数を書き込む。
3. `--use-profile profile.sprof` で再コンパイルすることでホット関数を推進する。
4. プロファイルガイドされたインラインスコアは、戦術補完（AGGRESSIVE の場合 +80、PRECISION の場合 +40）を持つ呼び出し先を評価する。
5. レイアウトパスは、指令キャッシュの局所性を向上させるためにホット関数を先頭に並べる。

## 検証

各最適化パスにはゲートスクリプトがあります。現在のテスト行列は全パスで **347 個の自動化テスト** を持ち、 FAIL=0、NOT_RUN=1（フル自分のテストで JIT OOM が発生する場合）です。各ゲートは 60秒以内で完了します。

## 次のステップ

基礎は固いです。ネイティブバックエンドは算術、制御構造、関数呼び出し、およびプロファイルインストーリングに対する正しい ELF バイナリを生成しています。次のチャレンジは、自分のホストコンパイラが自分自身をネイティブバイナリにコンパイルしたものと同じコンパイルループを閉じることです。コードはすべてリポジトリの`self-hosted/`ディレクトリにあります。 各通過、各テスト、各ゲートスクリプト - すべてSounioで書かれています。
