# Epistemic Computingとは何ですか？

科学の測定はすべて不確実性を伴います。薬局薬師が患者のクリアイネィンコートレイトレベルを1.2 mg/dLで測定したとします。その値は正確ではありません - 試薬の重ね合わせ誤差係数は約5%です。医者が500 mgのバンコミシンを薬方を薬付けしたとしますが、実際の生物利用度は患者の腎功能、体重、そして10数の他の近似した情報に依存します。

多くのプログラミング言語はこれを無視します。`float`は`float`であり、`1.2`は無限の精度で知られていると見なされます。Sounioは異なる方法を取ります。

## 知識 vs データ

Sounioでは、値に**Epistemicメタデータ**が付随することが可能です。型システムは以下のように区別します：

- **データ**: 生の数値(`f64`, `i32`)
- **知識**: 数値とその不确定性(`Knowledge&lt;f64&gt;`)

これの違いは以下のとおりです。
```sio
// 生のデータ — 確率情報なし
let creatinine: f64 = 1.2

// 知識 — 値 + 標準的不確分値
let creatinine: Knowledge<f64> = measure(1.2, uncertainty: 0.06)
```

`measure`関数は、値の最善推定値が1.2で、標準的不確分値が0.06（5%のCV）の`Knowledge&lt;f64&gt;`値を作成します。

## なぜこれが重要ですか？

`Knowledge`値で計算するとき、不確分値は自動的に**伝播します**。創薬素を使用して薬物のクリア率を計算すると、結果にも不確分値が付き、Sounioはそれを追跡します。

```sio
fn cockcroft_gault(age: f64, weight: Knowledge<f64>, scr: Knowledge<f64>) -> Knowledge<f64> {
    // CrCl = (140 - age) * weight / (72 * SCr)
    let numerator = (140.0 - age) * weight
    let denominator = 72.0 * scr
    numerator / denominator
}
```

出力の`Knowledge&lt;f64&gt;`は、両方の`weight`と`scr`からの合計的不確分値を反映します。手動の誤差伝播は必要ありません。

## 効果：副作用の追跡Sounioは、**効果**もトラッキングする。関数がファイルを読み込む場合は、`with IO`を宣言する必要があります。メモリを割り当てる場合は`with Alloc`を宣言します。ゼロで除算できる場合は`with Div`を宣言します。

```sio
fn safe_divide(a: f64, b: f64) -> f64 with Div {
    a / b
}

fn greet(name: string) with IO {
    print("Hello, ")
    print(name)
    print("\n")
}
```

これはドキュメントのみではなく、コンパイラーが**適用する**ものです。`with IO`が宣言されていない関数は`print`を呼び出すことができません。これにより、関数のシグネチャを見ることで、それが行うことが正確に分かることができます。

## あなたが作成するもの

次の4つのレッスンでは、確率的不確分性を伴う薬の投与モデルを完全に作成します。1. **レッスン2**: クリア率、体積、半衰期などのPKパラメータを構造体で定義する
2. **レッスン3**: 不確実な患者測定値をモデル化するための`Knowledge<T>`を使用する
3. **レッスン4**: 不确定性をファーマコキナティックモデルを通して伝播させる
4. **レッスン5**: 確信区間を使って臨床決定を行う

最終的には、この患者の不確実な労働値を与えられたとき、「500 mgの薬量では療効レベルを達成する確信度はどれですか？」という質問に答えることができるプログラムを作成することになります。

## キーポイント

- Sounioの`Knowledge<T>`型は不确定性を第一の概念として追跡する
- 効果（`with IO`、`with Div`、`with Mut`）は副作用を明示的にする
- これらの特徴は、最も危険なバグである静的に悪い仮定の伝播を防ぐことになります。
