Κάθε μέτρηση στην επιστήμη συνοδεύεται από αβεβαιότητα. Όταν ένας φαρμακοποιός μετρά την κρεατινίνη ενός ασθενούς ως 1,2 mg/dL, η τιμή αυτή δεν είναι ακριβής — η εξέταση έχει συντελεστή μεταβλητότητας περίπου 5%. Όταν ένας γιατρός συνταγογραφεί 500 mg βανκομυκίνης, η πραγματικά βιοδιαθέσιμη δόση εξαρτάται από τη νεφρική λειτουργία, το βάρος και μια σειρά ακόμη παραγόντων που γνωρίζουμε μόνο προσεγγιστικά.

Οι περισσότερες γλώσσες προγραμματισμού αγνοούν αυτό το γεγονός. Ένα `float` είναι απλώς ένα `float` και το `1.2` αντιμετωπίζεται σαν να ήταν γνωστό με άπειρη ακρίβεια. Το Sounio ακολουθεί διαφορετική προσέγγιση.

## Γνώση και δεδομένα

Στο Sounio, μια τιμή μπορεί να φέρει **επιστημολογικά μεταδεδομένα** — πληροφορίες για το πόσο βέβαιοι μπορούμε να είμαστε για αυτήν. Το σύστημα τύπων διακρίνει ανάμεσα σε:

- **Δεδομένα**: έναν ακατέργαστο αριθμό (`f64`, `i32`)
- **Γνώση**: έναν αριθμό μαζί με την αβεβαιότητά του (`Knowledge<f64>`)

Η διαφορά φαίνεται εδώ:

```sio
// Raw data — no uncertainty information
let creatinine: f64 = 1.2

// Knowledge — value + standard uncertainty
let creatinine: Knowledge<f64> = measure(1.2, uncertainty: 0.06)
```

Η συνάρτηση `measure` δημιουργεί μια τιμή `Knowledge<f64>`: η καλύτερη εκτίμηση είναι 1,2 και η τυπική αβεβαιότητα είναι 0,06 (συντελεστής μεταβλητότητας 5%).

## Γιατί έχει σημασία;

Όταν υπολογίζετε με τιμές `Knowledge`, η αβεβαιότητα **διαδίδεται αυτόματα**. Αν υπολογίσετε την κάθαρση ενός φαρμάκου από την κρεατινίνη, το αποτέλεσμα φέρει επίσης αβεβαιότητα — και το Sounio την παρακολουθεί για εσάς.

```sio
fn cockcroft_gault(age: f64, weight: Knowledge<f64>, scr: Knowledge<f64>) -> Knowledge<f64> {
    // CrCl = (140 - age) * weight / (72 * SCr)
    let numerator = (140.0 - age) * weight
    let denominator = 72.0 * scr
    numerator / denominator
}
```

Η έξοδος `Knowledge<f64>` αποτυπώνει αυτόματα τη συνδυασμένη αβεβαιότητα των `weight` και `scr`. Δεν χρειάζεται να γράψετε χειροκίνητα τύπους διάδοσης σφάλματος.

## Εφέ: παρακολούθηση παρενεργειών

Το Sounio παρακολουθεί επίσης τα **εφέ** — δηλαδή τι μπορεί να κάνει μια συνάρτηση. Αν μια συνάρτηση διαβάζει από αρχείο, πρέπει να δηλώνει `with IO`. Αν δεσμεύει μνήμη, `with Alloc`. Αν μπορεί να διαιρέσει με το μηδέν, `with Div`.

```sio
fn safe_divide(a: f64, b: f64) -> f64 with Div {
    a / b
}

fn greet(name: string) with IO {
    print("Hello, ")
    print(name)
    print("\n")
}
```

Αυτό δεν είναι απλώς τεκμηρίωση — ο compiler το **επιβάλλει**. Μια συνάρτηση χωρίς `with IO` δεν μπορεί να καλέσει την `print`. Έτσι, από την υπογραφή κάθε συνάρτησης γνωρίζετε ακριβώς τι μπορεί να κάνει.

## Τι θα κατασκευάσετε

Στα επόμενα τέσσερα μαθήματα θα δημιουργήσετε ένα πλήρες μοντέλο δοσολογίας με επίγνωση της αβεβαιότητας:

1. **Μάθημα 2**: Ορίστε παραμέτρους PK (κάθαρση, όγκος, χρόνος ημιζωής) ως structs
2. **Μάθημα 3**: Χρησιμοποιήστε το `Knowledge<T>` για να μοντελοποιήσετε αβέβαιες μετρήσεις ασθενούς
3. **Μάθημα 4**: Διαδώστε την αβεβαιότητα σε ένα φαρμακοκινητικό μοντέλο
4. **Μάθημα 5**: Λάβετε κλινικές αποφάσεις με όρια εμπιστοσύνης

Στο τέλος, το πρόγραμμά σας θα μπορεί να απαντήσει: *«Με βάση τις αβέβαιες εργαστηριακές τιμές αυτού του ασθενούς, πόσο βέβαιοι είμαστε ότι μια δόση 500 mg θα επιτύχει θεραπευτικές συγκεντρώσεις;»*

## Βασικά συμπεράσματα

- Ο τύπος `Knowledge<T>` του Sounio παρακολουθεί την αβεβαιότητα ως έννοια πρώτης τάξης
- Τα εφέ (`with IO`, `with Div`, `with Mut`) κάνουν τις παρενέργειες ρητές
- Μαζί, αυτά τα χαρακτηριστικά εμποδίζουν τη σιωπηλή διάδοση κακών παραδοχών — του πιο επικίνδυνου σφάλματος στην επιστημονική υπολογιστική
