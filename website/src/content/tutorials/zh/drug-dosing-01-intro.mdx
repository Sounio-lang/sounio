# 什么是认知计算？

科学中的每一次测量都带有不确定性。当药剂师测量患者的肌酐水平为1.2 mg/dL时，这个数值并不是精确的——该检测的变异系数大约为5%。当医生开处500 mg的万古霉素时，实际生物可利用剂量的依赖于患者的肾功能、体重以及我们仅知的大约十几个其他因素。

大多数编程语言都忽略了这一点。一个`float`就是一个`float`，`1.2`被当作精确到无穷大的数值处理。Sounio采取了不同的做法。

## 知识与数据

在Sounio中，一个值可以携带**认知元数据**——关于我们对该值有多大的信心。类型系统区分：

- **数据**：一个原始数字(`f64`, `i32`)
- **知识**：一个数字加上它的不确定性(`Knowledge<f64>`)

下面是区别：

```sio
// 原始数据——没有不确定性信息
let creatinine: f64 = 1.2

// 知识——值加上标准不确定性
let creatinine: Knowledge<f64> = measure(1.2, uncertainty: 0.06)
```

`measure`函数创建一个`Knowledge<f64>`值：最佳估计是1.2，标准不确定性是0.06（5% CV）。

## 为什么这很重要？

当你用`Knowledge`值进行计算时，不确定性**自动传播**。如果你从肌酐计算药物清除率，结果也带有不确定性——Sounio为你跟踪它。

```sio
fn cockcroft_gault(age: f64, weight: Knowledge<f64>, scr: Knowledge<f64>) -> Knowledge<f64> {
    // CrCl = (140 - age) * weight / (72 * SCr)
    let numerator = (140.0 - age) * weight
    let denominator = 72.0 * scr
    numerator / denominator
}
```

输出`Knowledge<f64>`自动反映了`weight`和`scr`的组合不确定性。无需手动传播错误。

## 效果：跟踪副作用

Sounio还跟踪**效果**——一个函数能做什么。如果一个函数从文件中读取，它必须声明`with IO`。如果它分配内存，`with Alloc`。如果它能除以零，`with Div`。

```sio
fn safe_divide(a: f64, b: f64) -> f64 with Div {
    a / b
}

fn greet(name: string) with IO {
    print("Hello, ")
    print(name)
    print("\n")
}
```

这不仅仅是文档——编译器**强制执行**它。没有`with IO`的函数不能调用`print`。这意味着你可以查看任何函数签名，确切地知道它可能会做什么。

## 你会构建什么

在接下来的四个课程中，你将构建一个完整的带有不确定性的药物剂量模型：

1. **第2课**：将PK参数（清除率，体积，半衰期）定义为结构体
2. **第3课**：使用`Knowledge<T>`来建模不确定的病人测量
3. **第4课**：通过药代动力学模型传播不确定性
4. **第5课**：用置信界限做出临床决策

到课程结束时，你将拥有一个程序，可以回答：“给定这个病人不确定的实验室值，我们对一个500 mg的剂量达到治疗水平有多大的信心？”

## 关键要点

- Sounio的`Knowledge<T>`类型将不确定性作为一等概念进行跟踪
- 效果(`with IO`, `with Div`, `with Mut`)使副作用显式
- 这些特性一起防止了静默传播错误的假设——科学计算中最危险的bug
