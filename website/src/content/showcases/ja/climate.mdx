# Sounioでの気候科学

## 経営層の読書

このパスが存在するのは、Sounioが速やすい計算だけでなく、不安定な証拠を政策に適した数値に変換することを拒否することを証明するためです。

気候ソフトウェアは、虚張りを試みることが厳しいというストレステストです。常に別の予測を発表することができますが、難しい課題は、合意の分散、モデルの違い合意、またはデータの品質が何らかのくらい薄れて、プログラムが虚假的自信を持って続けるべきかどうかを決定することです。

これが議論の内容です: 言語は確率が洗滌される前に、科学コードが停止する、範囲を縮小するか、拒否を示すことを可能にする必要があります。

## Ensemble aggregation

```sio
struct EpistemicValue {
    value: f64,
    variance: f64,
    conf_alpha: f64,
    conf_beta: f64
}

fn ensemble_mean_5(
    m1: EpistemicValue,
    m2: EpistemicValue,
    m3: EpistemicValue,
    m4: EpistemicValue,
    m5: EpistemicValue
) -> EpistemicValue {
    let n = 5.0
    let mean_value = (m1.value + m2.value + m3.value + m4.value + m5.value) / n
    let within_var = (m1.variance + m2.variance + m3.variance + m4.variance + m5.variance) / n

    // ... between variance calculated ...
    let total_var = within_var + between_var

    return EpistemicValue {
        value: mean_value,
        variance: total_var,
        conf_alpha: 1.0,
        conf_beta: 1.0
    }
}
```この例の目的は、平均化が新鮮ではないことではなく、集計面を通じて不确定性の話題を生きていくことです。それは、それを任意のメタデータとして数値が十分に美しいときに破棄できるものとして扱うのではなく、それを生きていくことにすることです。

## これが言語に与える重要さ

気候は「常に答えを出す」という政治的な失敗モデルの一つの明確な場所です。

ソフトウェアスタックが数値の出力のみを最適化されている場合、出力の続きと知識の続きの区別が難しくなります。不确定性に真剣に取り組んでいる言語は、プログラムに他の選択肢を与える必要があります：狭い範囲、表面の違い合意、または停止することです。

そのため、この方法は、トピックの多様性のためにここにあるわけではなく、拒否が能力の一部となる領域で言語がどのように形われているかを証しているから、GPUやニューロイメージングと一緒に店頭に置かれている理由です。## 持ち疑いの読者を信服するものは何ですか

- 確率的値から次の決定への明確な経路を示すこと
- 幅が広がることがコントロールフローを変更する例を示すこと
- 現在の bounded climate surface の真実的な文書化
- 「興味深い研究圧力」と「予測プラットフォーム」の明確な区別

この経路にはこの標準を持ち続ける必要があります。

## 境界がどこですか

この経路は次のことを主張しません:

- Sounioがすでに完全な気候モデリングプラットフォームです
- 現在の例は、完全な予測スタックの代替として使用できます
- すべてのサイエンスワークフローが既に拒否意識付きコントロールフローとともにエンコードされていること

主張は狭いものです: 気候圧力がなぜサイエンスソフトには確率を保持する言語が必要であるかを示します。
