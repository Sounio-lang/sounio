# Kretikos GPU Compiler

**Kretikos** (Κρητικός) = Cretan. Like Ariadne's thread through the Labyrinth of Knossos,
this compiler gives you a direct, visible line to every warp, every block, every thread.
No CUDA runtime hiding register allocation. No driver API obfuscating memory movement.
You see the bare metal. You control every instruction.

## Executive reading

Most languages wave at GPU ambition and hide the truth behind runtime APIs.
Kretikos does the opposite: it exposes the bare-metal surface as a first-class
language feature, then proves it works with inspectable artifacts.

- Bare-metal builtins compile today: `gpu_thread_id_x()`, `gpu_block_id_x()`, `gpu_block_dim_x()`, `gpu_sync_threads()`
- Multi-dimensional indexing: x, y, z axes for threads, blocks, and dimensions
- PTX emission path exists and produces real artifacts
- CPU fallback path ensures kernels run deterministically without hardware
- The backend source — PTX emitter, SPIR-V lowerer, CUDA ELF generator — lives in-tree at `self-hosted/gpu/`

## What Kretikos proves

A language serious about scientific software must not delegate GPU honesty to a
black-box runtime. Kretikos demonstrates that Sounio can:

- expose thread indexing as source-level syntax, not driver-level magic
- emit PTX that a skeptical reader can inspect instruction-by-instruction
- run kernels on CPU fallback with deterministic thread simulation
- keep the compiler, runtime, and narrative aligned under real pressure

## Bare-metal syntax

```sio
kernel fn vec_add(n: i64) with GPU {
    let tid = gpu_thread_id_x()
    let bid = gpu_block_id_x()
    let bdim = gpu_block_dim_x()
    let i = bid * bdim + tid
    if i >= n { return }
    // This thread owns element i. No runtime hiding the indexing.
}

kernel fn matmul_tile(n: i64) with GPU {
    let tx = gpu_thread_id_x()
    let ty = gpu_thread_id_y()
    let bx = gpu_block_id_x()
    let by = gpu_block_id_y()
    let bdx = gpu_block_dim_x()
    let bdy = gpu_block_dim_y()
    // 2D tile indexing with total control
    let row = by * bdy + ty
    let col = bx * bdx + tx
    if row >= n || col >= n { return }
    gpu_sync_threads()
}

fn main() with GPU, IO {
    let grid = (16, 16, 1)
    let block = (32, 32, 1)
    perform GPU.launch(vec_add, grid, block)(1024)
    perform GPU.launch(matmul_tile, grid, block)(512)
    perform GPU.sync()
}
```

This is not aspirational syntax. These builtins compile through the self-hosted
compiler and execute on the CPU fallback path today.

## Verified commands

```bash
# Compile and run on CPU fallback (no GPU hardware required)
souc examples/kernel_source_level.sio /tmp/kretikos_demo.elf
/tmp/kretikos_demo.elf

```

## Why this matters

GPU work is where language marketing goes to die. It is easy to sketch intrinsics
or promise tensor-core support. It is much harder to keep a self-hosted compiler,
a bare-metal surface, and a storefront narrative aligned while real bugs surface
in stack alignment, launch parameters, and PTX module loading.

Kretikos is valuable not only because it accelerates compute, but because it
forces the language to reveal whether its honesty survives contact with bare metal.

## Support tier

- bare-metal builtins: `gpu_thread_id_{x,y,z}`, `gpu_block_id_{x,y,z}`, `gpu_block_dim_{x,y,z}`, `gpu_sync_threads()` — self-hosted compiler
- PTX emission: `build --backend gpu` — checked GPU artifact
- backend source: `self-hosted/gpu/ptx_advanced.sio`, `self-hosted/gpu/nvidia_bare.sio`, `self-hosted/gpu/spirv_lower.sio`
- attested targets: CUDA `sm_80`, ROCm `gfx942`

## The boundary

Kretikos does **not** claim:
- that every GPU backend is production-complete
- that multi-dimensional kernels emit PTX for all patterns (currently pattern-matched)
- that `gpu.alloc<T>()` or shared-memory abstractions are checked public surface

The honest claim is narrower and therefore stronger: there is a real bare-metal
GPU compiler here, and every claim is bounded by artifacts you can read.
