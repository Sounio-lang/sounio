# Kretikos GPU compiler

> **Σημείωση πεδίου:** Το Kretikos είναι ενεργή ερευνητική διαδρομή. Η κλινική φαρμακολογία (πύλες ε με βανκομυκίνη, demo PBPK της διατριβής) είναι η κύρια δημόσια επιφάνεια επίδειξης αυτού του ιστοτόπου — όχι οι λειτουργίες GPU του storefront.

**Kretikos** (Κρητικός) = αυτός που προέρχεται από την Κρήτη. Όπως ο μίτος της Αριάδνης μέσα στον λαβύρινθο της Κνωσού, είναι η ονομασμένη διαδρομή για την εργασία του Sounio στον GPU compiler: builtins νημάτων σε επίπεδο πηγαίου κώδικα, σειριακό CPU fallback, ενσωματωμένα πρότυπα PTX/CUBIN και bundles artifacts.

## Συνοπτική ανάγνωση

Οι περισσότερες γλώσσες μιλούν αόριστα για GPU φιλοδοξίες και κρύβουν το σημερινό όριο. Το Kretikos κάνει το αντίθετο: εκθέτει μια οριοθετημένη GPU επιφάνεια ως χαρακτηριστικό πρώτης τάξης της γλώσσας και συνδέει κάθε αξίωση με artifact ή εντολή που μπορεί να επιθεωρηθεί.

- Τα ελεγμένα builtins του άξονα x μεταγλωττίζονται σήμερα: `gpu_thread_id_x()`, `gpu_block_id_x()`, `gpu_block_dim_x()`, `gpu_sync_threads()`
- Τα spellings των y/z builtins αναγνωρίζονται· το native CPU fallback επιστρέφει ντετερμινιστικά stubs
- Τα προκαθορισμένα πρότυπα PTX είναι ενεργά μέσω του `kretikos emit-ptx`, με τον in-tree emitter `self-hosted/gpu/ptx.sio`
- Τα προκαθορισμένα πρότυπα CUBIN είναι ενεργά μέσω του `kretikos emit-cubin`, με τον in-tree emitter `self-hosted/gpu/nvidia_bare.sio`
- Τα δομικά bundles artifacts είναι ενεργά μέσω του `kretikos bundle`, με hashes PTX/CUBIN και ρητές μη-αξιώσεις
- Το Kretikos εξαρτάται από τον ενεργό compiler `bin/souc`/`souc-linux-x86_64` για την κατασκευή των μικρών emitter drivers
- Η διαδρομή CPU fallback είναι ντετερμινιστική και σειριακή· δεν είναι παράλληλος GPU simulator
- Ο κώδικας του backend — PTX emitter, SPIR-V lowerer και CUDA ELF generator — βρίσκεται in-tree στο `self-hosted/gpu/`

## Τι αποδεικνύει το Kretikos

Μια γλώσσα που παίρνει στα σοβαρά το επιστημονικό λογισμικό δεν πρέπει να παραδίδει την ειλικρίνεια της GPU σε ένα black-box runtime. Το Kretikos δείχνει ότι το Sounio μπορεί:

- να εκθέτει indexing νημάτων ως σύνταξη επιπέδου πηγαίου κώδικα και όχι ως μαγεία του driver
- να εκπέμπει προκαθορισμένα πρότυπα PTX και CUBIN από αυτοφιλοξενούμενο κώδικα
- να εκτελεί kernels σε ντετερμινιστικό σειριακό CPU fallback για smoke tests σύνταξης και χρόνου εκτέλεσης
- να κρατά ευθυγραμμισμένα τον compiler, το runtime και την αφήγηση όταν εμφανίζονται πραγματικές δυσκολίες

## Σύνταξη χαμηλού επιπέδου

```sio
kernel fn vec_add(n: i64) with GPU {
    let tid = gpu_thread_id_x()
    let bid = gpu_block_id_x()
    let bdim = gpu_block_dim_x()
    let i = bid * bdim + tid
    if i >= n { return }
    // This thread owns element i.
}

fn main() with GPU, IO {
    let grid = (16, 1, 1)
    let block = (64, 1, 1)
    perform GPU.launch(vec_add, grid, block)(1024)
    perform GPU.sync()
}
```

Αυτή είναι η ελεγμένη δημόσια μορφή σήμερα: indexing μίας διάστασης και ντετερμινιστικό CPU fallback. Το ευρύτερο lowering y/z και οι πλουσιότερες επιφάνειες μνήμης ανήκουν σε ξεχωριστές διαδρομές προαγωγής.

## Επαληθευμένες εντολές

```bash
# Compile and run on serial CPU fallback (no GPU hardware required)
souc examples/kernel_source_level.sio /tmp/kretikos_demo.elf
/tmp/kretikos_demo.elf

# Emit predefined PTX templates (self-hosted, no GPU required)
kretikos emit-ptx vec_add     -o /tmp/kretikos.ptx
kretikos emit-ptx vec_sub     -o /tmp/kretikos.ptx
kretikos emit-ptx vec_mul     -o /tmp/kretikos.ptx
kretikos emit-ptx vec_div     -o /tmp/kretikos.ptx
kretikos emit-ptx vec_add_f64 -o /tmp/kretikos.ptx
kretikos emit-ptx fma         -o /tmp/kretikos.ptx
kretikos emit-ptx fma_f64     -o /tmp/kretikos.ptx
kretikos emit-ptx store_u32_const -o /tmp/kretikos.ptx

# Emit predefined Metal/MSL templates (self-hosted, no macOS required)
kretikos emit-metal vec_add          -o /tmp/kretikos.metal
kretikos emit-metal ossm_oct_step    -o /tmp/kretikos.metal
kretikos emit-metal sedenion_cd_step -o /tmp/kretikos.metal

# Emit the predefined vec_add_f32 CUBIN template
kretikos emit-cubin vec_add_f32 -o /tmp/kretikos.cubin

# Emit a structural artifact bundle with hashes and boundaries
kretikos bundle -o /tmp/kretikos-bundle

# Add optional toolchain/runtime validation when the host exposes those tools
kretikos bundle -o /tmp/kretikos-validated-bundle --validate-toolchain --validate-runtime

# Build PTX with the checked GPU artifact (broader pattern support)
export SOUC_GPU_BIN="$(pwd)/artifacts/omega/souc-bin/souc-linux-x86_64-gpu"
"$SOUC_GPU_BIN" build examples/kernel_source_level.sio --backend gpu -o /tmp/kretikos.ptx
```

## Γιατί έχει σημασία

Η εργασία GPU είναι το σημείο όπου πεθαίνει το marketing των γλωσσών. Είναι εύκολο να σχεδιάσει κανείς intrinsics ή να υποσχεθεί υποστήριξη tensor cores. Πολύ δυσκολότερο είναι να κρατήσει ευθυγραμμισμένους έναν αυτοφιλοξενούμενο compiler, μια οριοθετημένη GPU επιφάνεια και μια δημόσια αφήγηση, ενώ εμφανίζονται πραγματικά σφάλματα σε ευθυγράμμιση στοίβας, παραμέτρους εκκίνησης και φόρτωση PTX modules.

Το Kretikos είναι πολύτιμο όχι μόνο επειδή επιταχύνει υπολογισμούς, αλλά επειδή αναγκάζει τη γλώσσα να δείξει αν η ειλικρίνειά της επιβιώνει όταν έρχεται σε επαφή με artifacts του backend.

## Επίπεδο υποστήριξης

- ελεγμένα builtins: `gpu_thread_id_x`, `gpu_block_id_x`, `gpu_block_dim_x`, `gpu_sync_threads` — αυτοφιλοξενούμενος compiler
- αναγνωρισμένα CPU-fallback stubs: τα y/z thread και block IDs επιστρέφουν `0`, ενώ οι y/z block dimensions επιστρέφουν `1`
- πρότυπα PTX: `kretikos emit-ptx` με 6 patterns (vec_add, vec_sub, vec_mul, vec_div, vec_add_f64, fma)· ευρύτερη εκπομπή PTX μέσω `build --backend gpu` (ελεγμένο GPU artifact)
- πρότυπα MSL: `kretikos emit-metal` με 3 patterns (vec_add, ossm_oct_step, sedenion_cd_step) από in-tree αυτοφιλοξενούμενο emitter
- πρότυπα CUBIN: `kretikos emit-cubin` (in-tree αυτοφιλοξενούμενος emitter)
- bundle artifact: το `kretikos bundle` εκπέμπει PTX+CUBIN και `sounio.kretikos.bundle.v1`
- προαιρετικοί έλεγχοι προαγωγής: το `--validate-toolchain` καταγράφει τεκμήρια `ptxas`/`nvdisasm`, ενώ το `--validate-runtime` επιχειρεί το rung του CUDA Driver API με ακριβείς λόγους `not_run` σε hosts χωρίς GPU
- κώδικας backend: `self-hosted/gpu/ptx.sio`, `self-hosted/gpu/ptx_advanced.sio`, `self-hosted/gpu/nvidia_bare.sio`, `self-hosted/gpu/spirv_lower.sio`
- attested targets: CUDA `sm_80`, ROCm `gfx942`

## Το όριο

Το Kretikos **δεν** ισχυρίζεται:

- ότι κάθε GPU backend είναι πλήρως έτοιμο για παραγωγή
- ότι kernels πολλών διαστάσεων εκπέμπουν PTX για όλα τα patterns (σήμερα γίνεται pattern matching)
- ότι το `gpu.alloc<T>()` ή οι αφαιρέσεις shared memory αποτελούν ελεγμένη δημόσια επιφάνεια
- ότι το CPU fallback προσομοιώνει ένα παράλληλο GPU grid

Η ειλικρινής αξίωση είναι στενότερη και γι’ αυτό ισχυρότερη: υπάρχει εδώ μια διαδρομή GPU compiler, και το σημερινό bundle artifact του Kretikos CLI είναι επιφάνεια προκαθορισμένων templates, όχι αυθαίρετο lowering kernels που γράφει ο χρήστης. Η επικύρωση toolchain και runtime εφαρμόζεται μόνο στα επιλεγμένα templates· δεν επικυρώνει αυθαίρετους GPU kernels γραμμένους από τον χρήστη.
