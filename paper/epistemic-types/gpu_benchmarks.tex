\subsection{GPU Code Generation}
\label{sec:gpu-perf}

To evaluate the \sounio GPU backend, we measure the performance of
compiler-generated PTX against cuBLAS SGEMM on an NVIDIA~L4 (Ada
Lovelace, SM~8.9, 30.3~TFLOPS peak FP32, 23~GB VRAM).  The \sounio
compiler generates PTX targeting SM~7.0 (forward-compatible with Ada
Lovelace via NVIDIA's ISA compatibility guarantees), dispatched via the
CUDA Driver API with CUDA event timing.

The kernel uses a tiled SGEMM implementation: $64\times64$ tiles,
$16\times16$ thread blocks, $4\times4$ register blocking, with 16
\texttt{fma.rn.f32} instructions in the inner loop.
Table~\ref{tab:gpu-perf} reports results across four matrix dimensions.

The Sounio-generated kernel achieves a median of 5.3~TFLOPS at
$4096^3$, corresponding to 17.3\% of the L4's peak FP32 throughput.
Against the cuBLAS SGEMM baseline measured on the same hardware with
identical timing methodology, the geometric mean overhead is
$2.19\times$.  This overhead reflects the maturity gap between a
research compiler's tiled GEMM and NVIDIA's highly-optimized cuBLAS
library, which employs double-buffered shared memory, tensor core
dispatch, and sophisticated occupancy tuning.

Performance scales from 1024 to 8192 without degradation below the
500~GFLOPS threshold, confirming that the compiler-generated PTX is
functionally correct across a range of problem sizes.  Memory bandwidth
measured at 115~GB/s (DtoD) confirms the kernel is compute-bound rather
than memory-bound at all tested dimensions.

\paragraph{Epistemic shadow registers.}
The \sounio GPU codegen supports an \texttt{epistemic\_enabled} mode
that emits four shadow registers per value---the GUM standard
uncertainty~$\eps$, a validity predicate, and a provenance tag---with
full uncertainty propagation in the inner loop
(Section~\ref{sec:formal}).  The self-hosted GPU codegen for this mode
is implemented (2{,}400+ lines in \texttt{self-hosted/gpu/}) and its
soundness is verified in Lean~4
(\texttt{formal/EpistemicGemm.lean}).  Benchmarking the
shadow-enabled kernel on GPU hardware, and decomposing the overhead
into register pressure versus GUM arithmetic, remains as future work.
