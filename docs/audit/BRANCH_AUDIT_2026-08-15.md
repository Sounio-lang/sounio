**`handoff/1678-seed-fix`**

Two commits fixing #1678: a one-opcode silent-miscompile in lean_single.sio's mutable-borrow-of-array-element codegen path (self-hosted/compiler/lean_single.sio, compile_postfix_tail). For aggregate-typed array elements (stored pointer-per-slot), the borrow path emitted `lea` (address-of-pointer-cell) instead of `mov` (load-element-pointer, matching the value path), so mutation through a borrowed aggregate element silently wrote to/zeroed the wrong memory. Ships with scripts/dev/seed-1678/ (README + 4 .sio reproducers, including a severe case where a mutable borrow zeroes the target element), a refreshed bin/souc-lean-single-x86_64 fixed-point ELF, and documented bootstrap (gen2==gen3) and 2948-test regression-suite parity evidence. Confirmed absent from origin/main: the unpatched `lea rax,[rcx+rdx*8]` line and the `#1678` comment are still verbatim on main, and scripts/dev/seed-1678/ does not exist there.

*Proximo passo:* Self-contained (~340 lines including docs/tests, one real source hunk of ~14 lines), already carries its own bootstrap/regression evidence and an explicit handoff note ("Cherry-pick, rewrite or discard as suits that lane"). A human/agent owning the Madaros fixed-point lane should cherry-pick both commits (source fix + ELF refresh must land together per the canonical_compiler_gate.sh constraint noted in commit 20010ab07a), then re-verify gen2==gen3 and the canonical gate on current main before merging, since the seed ELF baseline may have moved since Aug 8.
