# Madaros forensic dispatch — `rc=13` 256 KiB ELF cap blocks Level-3 SMT corpus

Date: 2026-06-28
Branch: `recover/solver-gpu-arc` (tip `23745887b`; madaros rebuilt `e274d1e8`, `test_smt` 6/6 green)
Class: hard capacity ceiling (LOUD failure — `rc=13`, no miscompile)
Status: root-caused + reproduced; fix proposed, NOT yet applied (this is the §8 precursor)

## Symptom

The solver Level-3 external-corpus harnesses (`use theorem::smt::*`, generated by
`scripts/research/generate_sounio_dimacs_harness.py`) fail to compile to a native
ELF at corpus scale, blocking any Sounio-vs-external SAT crosscheck row. The
user-visible error is the generic wrapper:

```
error: multimodule native thin-link compilation failed
```

which **swallows** the real return code. Full-output compile shows the truth:

```
imported_compile: lower_done
Merged IR: 117 functions
Error: Failed to write native binary to <out> rc=13
```

The merged module lowers completely (117 functions = 43 `add_block_*` + `theorem::smt`
bodies + `main`); the failure is purely at ELF *emission*.

## Reproduction (deterministic, offline, on this branch)

```bash
# 1. craft a max-size DIMACS within the harness limits (<=1024 vars, <=4096 clauses, width<=8)
python3 - <<'PY'
import random,hashlib,csv
rng=random.Random(42); nv,nc=1024,4096
open("/tmp/big.cnf","w").write(f"p cnf {nv} {nc}\n"+"".join(
  " ".join(str((lambda v: v if rng.random()<.5 else -v)(rng.randint(1,nv))) for _ in range(3))+" 0\n"
  for _ in range(nc)))
PY
# (write a 1-row manifest: instance_id=local_big_4096,domain=sat,status=OK,local_path=/tmp/big.cnf,expected=SAT,sha256=...)
# 2. generate the corpus-shaped harness (96-clause block fns)
python3 scripts/research/generate_sounio_dimacs_harness.py --manifest /tmp/manifest.csv --out-dir /tmp/harness
# 3. compile -> rc=13
./bin/souc compile /tmp/harness/local_big_4096.sio -o /tmp/big.elf   # => rc=13
```

Calibration: the working `test_smt` harnesses emit ELFs of **131–147 KiB** (≈half the
cap), which is why they pass; the 4096-clause corpus harness exceeds **262144** bytes
and trips the guard.

## Root cause

`self-hosted/native/codegen_x86_linux.sio`, `native_v2_write_min_elf64_to_file`
(def `:9426`):

- `:9427` — `var bytes: [i8; 262144]` — the in-place ELF staging buffer (256 KiB).
- `:9452` — `if file_len <= 64 || file_len > 262144 { return 13 }` — the guard.
- `:9472` — `fn native_v2_build_elf_image_into(bytes: &! [i8; 262144], …)` — builds the
  ELF header + program headers + segment payloads into that buffer.
- `:9466` — `write_file(output_path, bytes, file_len)` does the actual write.

Buffer width and guard are **consistent at 262144 here** (unlike the `feat/hyper-epistemic-mul`
line, where an earlier scout saw `131072`). So this is a clean hard ceiling, not a
buffer/guard mismatch: any merged module whose `text+rodata+data` ELF image exceeds
256 KiB returns 13 with no partial write.

## ⚠ The fix is COUPLED — a file-buffer-only widen creates a SILENT MISCOMPILE

There are TWO 256 KiB ceilings on the ELF path, and they must move together:

- **Cluster A — the file staging buffer** (`:9427` `var bytes`, the `put_*`/`emit_phdr`
  helpers `:9392–9415`, build-into `:9472`, copy-loop bounds `:9512/9525/9531/9539`).
  Verified DECOUPLED from the text mirror: the `put_*` helpers are called only with
  `buf`/`bytes`; `NATIVE_V2_TEXT_BUF` is never passed to them.
- **Cluster B — the `.text` source mirror** (`:45` `var NATIVE_V2_TEXT_BUF: [i8; 262144]`
  global + `NATIVE_V2_TEXT_LEN`; legacy fallback `(*nc).code.bytes[i]` capped at 131072).

The copy loop at `:9512` sources `.text` bytes from `NATIVE_V2_TEXT_BUF` (`i < NATIVE_V2_TEXT_LEN`)
else `(*nc).code.bytes` (`i < 131072`), **else leaves `tb = 0`**:

```
while i < code_len && (text_offset + i) < 262144 {
    if i < NATIVE_V2_TEXT_LEN { tb = NATIVE_V2_TEXT_BUF[i] }
    else if i < 131072        { tb = (*nc).code.bytes[i] }
    (*bytes)[text_offset + i] = tb        // tail beyond both caps => ZERO
}
```

So if Cluster A alone is widened to 1 MiB, a corpus whose `.text` exceeds 256 KiB would
write a full-size ELF whose code tail is **zero-filled** — i.e. the LOUD `rc=13` becomes
a SILENT miscompile (binary writes, `.text` corrupt). **Do not ship a Cluster-A-only
widen.** This is the single most important constraint in this dispatch.

## Proposed fix (coupled, matching the `io_write_*_binary` 1 MiB / 2 MiB precedent)

Widen Cluster A **and** Cluster B consistently to 1 MiB (`1048576`):

1. Cluster A: `:9427` buffer, `:9392/9398/9403/9410/9415` `&![i8; 262144]` params,
   `:9393` bound, `:9452` guard, `:9472` build-into param, `:9512/9525/9531/9539`
   copy-loop bounds → all `262144` → `1048576`. (NOT a blanket replace — leave `:7890`
   `native_v2_driver_state_data_len`, the `:104–911`/`:9726` `131072` result path, and
   bare unrelated `262144` literals untouched.)
2. Cluster B: `:45` `NATIVE_V2_TEXT_BUF: [i8; 262144]` → `[i8; 1048576]` (a bare global
   i8 array → 1 MiB BSS, zero-init; NOT the by-value `CodeBuffer` struct whose prior
   256 KiB widening failed typecheck — so the documented aggregate-pressure risk does
   not apply here, but VERIFY the self-hosted build still typechecks). Widen the
   text-mirror fill path (`:1338–1357` `262144`/`131072` bounds) so up to 1 MiB of
   `.text` is actually captured into the mirror, and the `:9516` `else if i < 131072`
   fallback so it can't silently zero-fill between 131072 and the new cap.
3. Audit the `:7459` / `:9690` call sites and any sibling emitter for stray caps.

### Verify (do not assume sufficient)

`.code`/`.rodata`/`.data` inside `NativeCompiler` may be the NEXT cap after the mirror.
The fix is only "done" once the 4096-clause harness compiles AND runs to a real
SAT/UNSAT result with a non-zero, correct `.text` (spot-check the binary actually
executes the solver, not just that an ELF was written).

## Verification gate (after the fix, build-locked)

1. Rebuild madaros: `bash scripts/ci/build_modular_madaros.sh artifacts/self-hosted/madaros`.
2. No-regression: `./scripts/run_sio_test_suite.sh test_smt --verbose --jobs 1` → **6/6**.
3. Repro now passes: the 4096-clause harness compiles to an ELF **and** runs, printing
   `SOUNIO_DIMACS_RESULT … 0|1` (not rc=13).
4. Add a permanent gate: a corpus-scale harness in `tests/` (or a CI script) that would
   re-trip rc=13 on regression, so the cap can't silently return.

## Related finding (SEPARATE bug — own dispatch warranted)

While reproducing this, an unrolled (straight-line) `theorem::smt` `main` with 800 /
1500 / 2500 inline clause blocks produced **byte-distinct but identically-sized
(167944 B) ELFs**, and `SOUNIO_NV2_IR_TRACE=1` reported `name=main instr_count=1024`
regardless of source size. `IR_MAX_INSTRS = 1024` (`self-hosted/ir/ir.sio:13`; arrays
`:711`, `:3478`) **silently truncates** any function body exceeding 1024 IR instructions
— the truncated binary runs, exits 0, and never reaches its tail logic (a SILENT
miscompile, the worst class for an epistemic language). The DIMACS generator *dodges*
this by splitting clauses into 96-clause `add_block_*` functions, so it is orthogonal
to the rc=13 corpus blocker — but it is a latent soundness landmine that should get its
own forensic dispatch + a loud-overflow-or-grow fix.
