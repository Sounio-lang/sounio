# EISA v2 — architecture: qd128 err lane, format v2, receipt v3

Date: 2026-07-05
Status: draft for adversarial review — v0 (E0–E5) and v1 (V1a–V1e) are
complete and gated; nothing here changes v0/v1 semantics or bytes.
Lineage: extends `eisa-v1-plan-2026-07-05.md` and
`eisa-stack-architecture-2026-07-05.md`. Word offsets, receipt fields and
opcode numbers below are relative to those documents.

v1 shipped control flow (branches, fuel, frail counting, I6) over the
3-lane machine whose `err` lane is a double-double (`Dd64`, ~106 bits).
v2 has one scientific goal: **make the err lane deep enough that the
receipt can pin the exact value of a catastrophically cancelling kernel**
— concretely, Rump 1988 at (77617, 33096), whose exact value is
−54767/66192 = −0.8273960599468213…, requiring ≈122 bits of effective
precision. dd64 cannot reach it (measured: `test_dd64_cancellation.sio`);
quad-double (~212 bits) can, with margin.

Substrate: `stdlib/math/qd128.sio` (W1) — Hida–Li–Bailey ARITH-15 (2001)
quad-double with Priest renormalisation, accurate addition, 13-term
multiplication boxes, long division, Newton sqrt.

## 1. Semantics — the v2 err lane contract

v0/v1 err propagation is *formulaic*: each op combines operand err lanes
by first-order rules plus the EFT residual of the val-lane op. v2
strengthens this to a *closure* contract:

```
true(z) := qd(z.val) + z.err                    (a Qd128 quantity)

v2 contract:  true(z) = round_qd( true(x) op true(y) )
```

For each arithmetic op the EVM computes the operation **in qd128 over the
true values** and defines the err lane as the difference against the
IEEE-double val lane:

```
val_z = fl64(x.val op y.val)          # unchanged: what plain hardware does
t     = qd_op( qd(x.val) + x.err ,  qd(y.val) + y.err )
err_z = qd_sub(t, qd_from_f64(val_z))
```

Consequences, in order of importance:

1. **The val lane is untouched.** It remains the bit-exact IEEE-754
   double result — the machine still *runs* the computation a plain CPU
   would run; the err lane is a correction trail, not a redefinition.
2. **eadd/esub/emul are exact to qd precision**; ediv/esqrt are correctly
   rounded to qd by the HLB algorithms' guarantees (division: 5-term
   quotient expansion; sqrt: Newton on the inverse root). The v0
   invariant "true equals exact up to second-order terms" becomes "up to
   round_qd", uniformly, with no dropped cross terms (v0/v1 dropped
   x.err·y.err in emul; v2 keeps it inside qd_mul).
3. **Rump becomes receipt-pinnable.** Every intermediate true value in
   the Rump kernel is an integer or dyadic rational representable well
   inside 212 bits until the final division; the receipt's val+err
   reconstruction lands on −54767/66192 correctly rounded to qd.
4. The u lane (GUM first-order) is **unchanged** — depth of the roundoff
   trail is orthogonal to input uncertainty propagation.

### Poison and frail over qd

- **I3 (err overflow):** poison iff any of the four err components is
  non-finite. Renormalised qd guarantees |x1| ≤ ulp(x0)/2 etc., so
  checking x0 alone would *almost* suffice — but intermediate
  accumulation boxes can overflow transiently; the check is on the
  stored, renormalised result (all four words), same placement as v1.
- **Frail predicate (unchanged shape):** band = max(u, |err.x0|);
  |err.x0| equals |err| to within one qd renormalisation ulp, so the
  band's leading term is what it was in v1 — only deeper.
  Boundary rule stays: |val| == band counts frail; band == 0 (both
  operands exact so far) never frail.
- **Gate policy (10x/100x) unchanged**, with roundoff := |err| collapsed
  to f64 = |err.x0| (x1..x3 contribute < 1 ulp of the leading term).
- **HLB honesty caveat carried verbatim from W1:** necessary conditions
  for Priest renormalisation to always succeed are not known; sufficiency
  holds for ≤51-bit overlap, which the HLB operators maintain. The v2
  spec inherits this assumption explicitly rather than claiming a proof.
  Adopted from adversarial review (2026-07-05): the failure mode must be
  *observable*, not silent — the conformance harness (`eisa_evm_run`)
  verifies the non-overlap bound on every receipt's reconstructed
  roundoff0..3 (|x_{i+1}| ≤ ulp(x_i)/2 + slack) and fails the lane on
  violation. Harness-level, so neither executor's machine semantics
  changes and the bridge needs no extra templates.

## 2. Format v2 (`.eisax`)

Minimal delta — the deepening is semantic, not structural:

- `version` word = **2**. The version field is a full i64 word (word 0
  of the header, as in v0/v1); values 0 and 1 select dd64 err-lane
  semantics, value 2 selects qd128 — stated explicitly so a future v3
  (arbitrary precision, posit lanes) has an unambiguous dispatch point.
  Code/const/provenance layout, the fuel word, and all opcode numbers
  are **identical to v1**. There are no new opcodes: every v1 program is
  expressible in v2 by flipping the version word.
- EISA-hash: same v1 mixing (fuel included); the version word is already
  mixed, so a v1 image and its v2 twin have different hashes — receipts
  cannot be confused across depth regimes. No hash algorithm change.
- Validator: v2 accepts the v1 opcode set and v1 structural rules,
  rejects version > 2 (`eisax_version_err`), keeps the v1 fuel cap.
- **Fuel remains a semantic step count.** A v2 step costs more host
  cycles (qd ops are ~10–30 f64 ops) but fuel counts instructions, not
  cycles — same as v1, documented so nobody "optimises" fuel into a
  cycle proxy later. Corollary (review, 2026-07-05): v1 and v2 steps are
  **not interchangeable** for any future real-time or gas-metering use;
  a fuel scheduler must treat the version word as part of the cost model.

## 3. Receipt v3

The v2 receipt must expose the full qd err lane — a leading-term-only
`roundoff` would silently discard exactly the depth v2 pays for:

```
eisa-receipt: v=3 prog=<hash> gate=<n> reg=e<r> val=<s,e,m>
              roundoff0=<s,e,m> roundoff1=<s,e,m> roundoff2=<s,e,m> roundoff3=<s,e,m>
              u=<s,e,m> poisoned=<0|1> frail=<count> [stop=fuel]
```

- All four err components in sign/exponent/mantissa integer
  decomposition (same `f64_parts` discipline as v1/v2 receipts).
  Zero-sign rule, per component: `f64_parts` maps both +0.0 and −0.0 to
  `s0e0m0`, so the sign of a zero component is unobservable in receipts
  *by design* — same as v1; −0.0 bit-fidelity witnesses stay
  division-based (1/x sign), never receipt-based.
- `roundoff0` of a v3 receipt is field-compatible with `roundoff` of v2
  receipts for tooling that only reads the leading term. Parsers must
  treat roundoff0..3 as an **atomic unit**: the gate comparison and any
  hash over receipt text covers all four fields or none — a partial read
  silently reintroduces the leading-term-only blindness v3 exists to
  remove.
- v3 is emitted **only** by version-2 images; v0 images keep v=1
  receipts, v1 images keep v=2 receipts, byte-for-byte (regression
  gates already pin this).
- The exact-Rump witness reads: reconstruct val+roundoff0..3 as a qd sum
  and compare against −54767/66192 correctly rounded to qd — an
  assert on *derived* bits, not a tolerance fitted to output.

## 4. EVM v2

- `EvmMachine` err storage widens from 2 words (`reg_ehi/reg_elo`) to 4
  (`reg_e0..reg_e3`) per register; v0/v1 execution paths keep using the
  first two words with dd semantics, version-dispatched exactly like the
  v1 branch/fuel dispatch (`evm_is_v1` gains an `evm_is_v2`).
- Arithmetic steps on the v2 path call `math::qd128` directly (the EVM is
  Sounio; no assembly here). Reference semantics get a v2 module
  (`stdlib/eisa/core_v2.sio`, `EReg2 { val: f64, err: Qd128, u: f64 }`)
  so the v0 reference (`core.sio`) stays frozen as the v0 oracle.
- Differential obligation unchanged: EVM v2 vs reference-v2 chains on
  the corpus, plus **regression lanes proving v0 and v1 images produce
  byte-identical receipts before/after the widening** (the storage
  change touches shared state, so the regression lane is load-bearing,
  not ceremonial).

## 5. Bridge v2 (x86-64 AOT)

The v1 bridge inlines per-op templates. qd128 templates are too large to
inline per instruction; v2 introduces **called subroutines** (SSE2
scalar: addsd/subsd/mulsd/divsd/sqrtsd + branchless renorm skeleton) laid
out once per ELF, with per-instruction call sites. Requirements:

- **Byte-identity of stdout receipts** (v3) against the EVM on every
  corpus lane — same standard as v0/v1; the subroutine boundary must not
  introduce any x87/FMA contamination (SSE2 scalar only, no `-ffast`
  anything, no fused ops: qd EFTs are *wrong* under FMA contraction
  unless the algorithm variant expects it — v2 uses the non-FMA HLB
  variants to match the Sounio-side qd128 exactly).
- State layout: 4 err words per register (state grows by 2×64 words);
  **this is the same layout migration that segfaulted the V1d/V1e
  high-register attempt** — it lands only together with the W4 template
  refactor (full-file offset audit, `c_state_size` recomputed first,
  micro-steps with ELF-sha snapshots between each group, per decision
  record; rollback rule: any segfaulting micro-step is reverted before
  the next).
- v1 residuals close here as prerequisites: full-arithmetic templates
  for e16..e63 and the dynamic fuel-stop receipt for high registers.

## 6. Corpus v2 (differential gate)

New lanes on top of the 16 existing (all of which must stay green and
byte-identical):

| lane | content | witness |
|---|---|---|
| v2-basic | v1-loop twin with version=2 | receipt v3 shape; roundoff1..3 present |
| v2-cancel | E5 cancellation kernel at depth | err lane captures full residual |
| v2-rump-qd | full Rump 1988, version=2 | val+err reconstructs −54767/66192 to qd |
| v2-rump-dd | same kernel, version=1 (dd64) | **failure lane**: receipt visibly wrong at ~122 bits |
| v2-regress-v0/v1 | pre-v2 golden images | byte-identical receipts after widening |

The dd-failure lane is mandatory scientific content, not decoration: the
math-review corollary (2026-07-05, decisions #15) is that the boundary
evidence — dd64 failing where qd128 succeeds, in the same executable
format under the same gate — is not superseded by the success lane.

## 7. Phasing (unchanged from the W-plan)

W2 is this document + adversarial review. W3 = format v2 + EVM v2 +
core_v2 reference + regression lanes. W4 = bridge v2 under the
micro-step/snapshot discipline. W5 = Rump showcase, CADNA/Verificarlo
positioning (deterministic EFT-measured residual vs stochastic
estimation; the honest one-line framing from the V1e math-review), docs
as-built.

## 8. Known risks, stated up front

1. **Priest renormalisation assumption** (§1) — inherited, documented,
   not proved here.
2. **Bridge state migration** — the one operation with a demonstrated
   segfault history; mitigated by the W4 discipline, not by optimism.
   (A reviewer-suggested "layout migration stamp" in the ELF was
   considered and set aside: bridge ELFs are self-contained — state is
   allocated and used inside one emitted binary, never loaded across
   binaries — so a version stamp has nothing to protect against.)
3. **Receipt growth** — v3 receipts are ~2× longer; the parser in
   `eisa_evm_run.sio` and the gate's comparison remain byte-oriented, so
   no schema drift is possible without tripping the gate.
4. **Performance** — qd ops in the EVM (interpreted Sounio) will be
   ~20–50× slower per step than v1; acceptable for the corpus scale
   (all lanes < 10³ steps). Not a target for optimisation in v2.
