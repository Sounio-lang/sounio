## 1. Question and answer

The previous full-source C1 machine left one concrete next action: test whether
resetting the C1 representation after each Poincare return could prevent the
six-return derivative enclosure from wrapping at source-cover scale without
altering the rigorous C0 state.

The answer from three bounded edge configurations over two physical source
tiles is **no for the tested reset family**. Canonical reboxing makes the
normalized derivative width between `9.65x` and `11.54x` worse than the direct
six-return baseline on these three edge configurations. A point dyadic right
scaling improves canonical reboxing
for the two target normalizations of the same N0 source tile, but is slightly
worse than canonical for N1-to-N0; it remains between `9.86x` and `11.36x`
worse than direct. The
single-run timings vary too much to support a runtime conclusion.

This is useful negative knowledge. It falsifies only the narrower proposition
that this implemented synchronized canonical C1 rebox resolves
`BLK-20260730-cs6-c1-full-source-scaling` on the tested tiles. It does not close
the full-source scaling blocker or untested reset families, and proves no cone,
hyperbolicity, or attractor statement.

## 2. The API distinction that controls soundness

After

```cpp
poincare(set, flowDerivative, returnTime, 1)
```

CAPD returns the event image and event derivative, but mutates `set` to its
post-section state. Injecting `computeDP(image, flowDerivative, returnTime)`
back into that set would combine an event-resident derivative with a
post-section C0 carrier. The probe forbids that operation.

Instead it uses

```text
RESET_SEMANTICS=REPRESENTATION_PRESERVING_CUMULATIVE_JRAW_REBOX
CALL_PATTERN=6xP1_SAME_MUTABLE_SET
LOCAL_FACTOR_CHAIN=false
PREFIX_DP_PRODUCT_FORBIDDEN=true
FINAL_DP=PREFIX_6_ONLY
```

The six emitted `computeDP` matrices are cumulative prefixes from one initial
tangent seed. They are diagnostics, not local factors. Multiplying them would
count earlier returns repeatedly. Only prefix six is the final derivative.

## 3. Atomic reset contract

Let the physical cumulative tangent enclosure be represented by

```math
J_k \subseteq K_k E_k, \qquad E_0=I.
```

After returns `1,...,5`, choose a positive point diagonal dyadic chart
`S_k=diag(s_0,s_1,1)` and set

```math
K_k^+ = K_k S_k^{-1}, \qquad E_k=S_k E_{k-1}.
```

Because the factors are normal binary powers of two, the implemented scaling
and inverse are exact binary operations, and the verifier checks entrywise

```math
K_k^+E_k = K_kE_{k-1}.
```

The reset derives `K_k` only from the post-section `m_currentMatrix`. It builds a
fresh one-argument `C1BaseSet`, explicitly sets `m_invBjac=I`, and synchronizes
`m_currentMatrix`. It requires both the semantic current matrix and the C1
doubleton to contain the candidate. It also checks that the third tangent
column remains exactly zero.

The following state is preserved exactly across each reset:

- the complete C0 doubleton, `currentSet`, time, and last C0 enclosure;
- scratch buffers and reorganization policy;
- `m_lastMatrixEnclosure`, which remains the last physical flow-step Jacobian.

`m_lastMatrixEnclosure` is neither zeroed nor replaced by identity nor
reparameterized. The worker computes those comparisons, while the ledger
records their booleans. These fields are therefore worker-attested, not
independently reconstructed from the receipt. The runner hashes and retains the
worker for replay, and promotion remains false.

## 4. Exact verifier

The verifier accepts only a closed ASCII grammar with exact record order and
cardinalities. A success ledger has four results, eighteen C1 prefixes, ten
resets, six Liouville prefixes, one status, and one summary. The explicit C0
nontransversality mode requires the same complete C1 records but exactly five
Liouville prefixes and the frozen failure status. Unknown keys, duplicate
records, non-finite values, reordered prefixes, and trailing free-form content
fail.

Every interval endpoint is an outward-expanded hexadecimal binary64. The
verifier removes exactly that one serialization ULP, converts the recovered
binary values to exact `Fraction` objects, and independently checks:

- the embedded worker-source SHA-256, frozen order 8, signed-int32 bounds, and
  source tile reconstructed from its indices and frozen h-set geometry;
- positive, strictly ordered cumulative return times;
- positive section-normal velocities and section-coordinate containment;
- exact `POST=PRE/S`, exact external-chart chaining, and unchanged physical
  tangent carriers;
- normal, positive power-of-two scales with the third chart coordinate fixed;
- exact zero third tangent columns and `POST subset BOX`;
- C1 determinants recomputed from every prefix matrix;
- tight normalized result enclosures recomputed from `DP`, with width ratios
  derived only from those recomputed matrices rather than reported `A` fields;
- Liouville determinants recomputed from retained `EXP_ELL`, the initial and
  final normal velocities, and the oriented source frame;
- joint, not merely pairwise, intersection of all four final lanes;
- joint C1 derivative intersection at each return, and joint C1/Liouville
  intersection of time, state, normal velocity, and determinant.

Liouville is reject-only. It never clips or replaces a C1 enclosure. The
transcendental enclosure `ELL -> EXP_ELL` remains inside the retained CAPD
worker; the Python verifier recomputes its downstream algebra but does not
claim an independent directed-rounding exponential implementation. Exact
receipt hashes and the embedded worker-source hash bind that TCB boundary; the
runner still declares that dependency hashes are incomplete and that no remote
attestation exists. The repository retains each v5 run manifest and verification
transcript, plus the CAPD flags, library flags, version, preprocessor macros, and
effective compiler options used by all four runs.

## 6. Next machine-level opening

The next credible route is not another cumulative C1 canonicalization. It is a
**section-resident C0/C1 return carrier** that exposes a rigorous structured set
at the event before CAPD advances the mutable set past the section. Such an
interface would permit, in one frame:

1. C0 recentering or structured subdivision where transversality is evaluated;
2. a genuinely local return derivative rather than cumulative-prefix reuse;
3. synchronized C0 and C1 charts without event/post-section state mixing;
4. an adaptive cover driven first by C0 transversality and only then by C1
   width.

That interface is a CAPD integration/research task, not a property exposed by
the current public `PoincareMap` call. A valid prototype must overlap the direct
baseline at every prefix, preserve the Liouville checks, and close an exact
adaptive cover with no dropped or duplicated leaves.

The two AMD U250 boards are not installed and were not used. Once available,
they may schedule independent accepted leaves or evaluate frozen chart
candidates, but CPU outward-rounded CAPD and exact aggregation remain the
authoritative proof path. FPGA throughput does not repair a missing rigorous
section-resident state.
