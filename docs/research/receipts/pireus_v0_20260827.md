## Established Capability

Pireus v0 reuses Sounio's existing `TripleStore`, triple patterns, solution
bindings, and SPARQL-like executor. It adds a hardware-domain vocabulary and
can distinguish exact source-count and lane-count requirements.

The positive result is protected by two negative controls:

- The one-source result contains no two-source capability.
- A two-source query retrieves the explicit two-source control, showing it is
  present and therefore meaningfully rejected by the one-source query.
- An unsupported sixteen-lane shape produces zero matches.

## Evidence Boundary

Both catalog individuals carry `SyntheticSounioWitness` evidence and a
synthetic architecture. The store contains zero real material capabilities.
Therefore this receipt supports no x86, AArch64, Apple Silicon, encoding,
latency, throughput, or instruction-selection claim.

Missing material evidence remains different from unsupported hardware.

## Compiler Routing Boundary

The default canonical ontology query gate compiled and executed successfully.
Direct public-wrapper `check` of the imported query module reported pre-existing
cross-module `Seq` method/index failures on this branch. The rebuilt/current-
source ontology wrapper then reported unanimous `verdict=ok` for the imported
Pireus closure and compiled and executed it successfully.

Work used the rebuilt/current-source wrapper as the primary semantic validation
path. It did not use the failing direct-import check as evidence against the
ontology kernel, and it did not silently fall back to a separate Pireus store.
