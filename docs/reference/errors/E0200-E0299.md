# Effect Errors (E0200-E0299)

This section documents errors related to Sounio's algebraic effect system. Effects track computational side effects like I/O, mutation, allocation, and more.

---

## E0200: Effect Not Declared

**Diagnostic Code**: `effect::undeclared`

### Description

A function performs an effectful operation without declaring the effect in its signature.

### Example

```sio
fn log_message(msg: string) {
    println(msg)  // Error: IO effect not declared
}
```

**Error Message**:
```
error[E0200]: Effect `IO` not declared in function signature
  --> example.sio:2:5
   |
 1 | fn log_message(msg: string) {
   |    ----------- function does not declare this effect
 2 |     println(msg)
   |     ^^^^^^^^^^^^ this operation has effect `IO`
   |
   = help: add `with IO` to the function signature
```

### Solution

Declare the effect in the function signature:

```sio
fn log_message(msg: string) with IO {  // Added effect declaration
    println(msg)
}
```

## E0201: Unhandled Effect

**Diagnostic Code**: `effect::unhandled`

### Description

An effect escapes from a computation without being handled.

### Example

```sio
fn main() {
    let result = read_file("config.txt")  // Error: IO effect unhandled
    println(result)
}
```

**Error Message**:
```
error[E0201]: Unhandled effect `IO`
  --> example.sio:2:18
   |
 2 |     let result = read_file("config.txt")
   |                  ^^^^^^^^^^^^^^^^^^^^^^^ effect `IO` escapes here
   |
   = help: either handle this effect with `with handler { ... }`
           or add it to the function signature
```

### Common Causes

1. **Calling an effectful function** from a pure context
2. **Effect not propagated** to calling function
3. **Missing effect handler**

### Solution

Either propagate the effect:

```sio
fn main() with IO {  // Propagate IO effect
    let result = read_file("config.txt")
    println(result)
}
```

Or handle it explicitly:

```sio
fn main() {
    handle {
        let result = read_file("config.txt")
        println(result)
    } with IOHandler { }
}
```

## E0202: Effect Mismatch

**Diagnostic Code**: `effect::mismatch`

### Description

The effects of an expression don't match the expected effects.

### Example

```sio
fn pure_compute() -> i32 {  // Declares no effects
    return compute_with_alloc()  // Error: has Alloc effect
}

fn compute_with_alloc() -> i32 with Alloc {
    let buffer = Vec::new()
    return buffer.len()
}
```

**Error Message**:
```
error[E0202]: Effect mismatch
  --> example.sio:2:12
   |
 1 | fn pure_compute() -> i32 {
   |    ------------ expected no effects
 2 |     return compute_with_alloc()
   |            ^^^^^^^^^^^^^^^^^^^^ has effect `Alloc`
```

### Solution

Propagate the effect to the caller:

```sio
fn pure_compute() -> i32 with Alloc {  // Added Alloc effect
    return compute_with_alloc()
}
```

## E0203: Effect In Pure Context

**Diagnostic Code**: `effect::pure_context`

### Description

An effectful operation is performed in a context that requires purity.

### Example

```sio
const COMPUTED: i32 = compute_at_runtime()  // Error: const must be pure

fn compute_at_runtime() -> i32 with IO {
    // reads from file
}
```

**Error Message**:
```
error[E0203]: Cannot perform `IO` in pure context
  --> example.sio:1:23
   |
 1 | const COMPUTED: i32 = compute_at_runtime()
   |                       ^^^^^^^^^^^^^^^^^^^^ effectful operation here
   |
   = note: constant expressions must be pure (no effects)
```

### Pure Contexts in Sounio

- `const` declarations
- Type-level computations
- Generic bounds evaluation
- Compile-time assertions

### Solution

Use a runtime binding instead:

```sio
// Compute at runtime instead
fn get_computed() -> i32 with IO {
    compute_at_runtime()
}
```

## E0204: Handler Type Mismatch

**Diagnostic Code**: `effect::handler_mismatch`

### Description

An effect handler doesn't match the effect it's trying to handle.

### Example

```sio
effect Logger {
    fn log(msg: string);
}

handler BadHandler for Logger {
    log(msg) => {
        // Missing: resume call
        println(msg)
    }
}
```

**Error Message**:
```
error[E0204]: Handler type mismatch
  --> example.sio:6:5
   |
 6 |     log(msg) => {
   |     ^^^^^^^^ handler for `log` must call `resume`
   |
   = note: effect operations that return must call `resume` with a value
```

### Solution

Call `resume` with the appropriate value:

```sio
handler GoodHandler for Logger {
    log(msg) => {
        println(msg)
        resume(())  // Resume with unit value
    }
}
```

## E0205: Unknown Effect

**Diagnostic Code**: `effect::unknown`

### Description

An effect name was used that is not defined.

### Example

```sio
fn process() with Logging {  // Error: Logging is not defined
    log("processing")
}
```

**Error Message**:
```
error[E0205]: Unknown effect `Logging`
  --> example.sio:1:19
   |
 1 | fn process() with Logging {
   |                   ^^^^^^^ effect not found
   |
   = help: did you mean `IO`?
   = note: built-in effects are: IO, Mut, Alloc, Panic, GPU, Prob, Async, Div
```

### Built-in Effects

| Effect | Description |
|--------|-------------|
| `IO` | Input/output operations |
| `Mut` | Mutable state operations |
| `Alloc` | Heap allocation |
| `Panic` | May panic or abort |
| `GPU` | GPU compute operations |
| `Prob` | Probabilistic operations |
| `Async` | Async operations |
| `Div` | May diverge (infinite loop) |

### Solution

Define the custom effect or use a built-in:

```sio
effect Logging {
    fn log(msg: string);
}

fn process() with Logging {
    perform Logging.log("processing")
}
```

## E0206: Conflicting Effect Handlers

**Diagnostic Code**: `effect::conflicting_handlers`

### Description

Multiple handlers for the same effect are provided in the same scope.

### Example

```sio
fn main() {
    handle {
        effectful_code()
    } with Logger1 { }
      with Logger1 { }  // Error: duplicate handler
}
```

**Error Message**:
```
error[E0206]: Conflicting effect handlers
  --> example.sio:5:7
   |
 4 |     } with Logger1 { }
   |            ------- first handler here
 5 |       with Logger1 { }
   |            ^^^^^^^ duplicate handler for `Logger`
```

### Solution

Use only one handler per effect:

```sio
fn main() {
    handle {
        effectful_code()
    } with Logger1 { }
}
```

## E0207: Effect Not Resumable

**Diagnostic Code**: `effect::not_resumable`

### Description

The `resume` keyword was used in a context where resumption is not possible.

### Example

```sio
effect Abort {
    fn abort(msg: string) -> !;  // Never returns
}

handler AbortHandler for Abort {
    abort(msg) => {
        println(msg)
        resume(())  // Error: abort never returns
    }
}
```

**Error Message**:
```
error[E0207]: Effect not resumable
  --> example.sio:8:9
   |
 3 |     fn abort(msg: string) -> !;
   |                              - effect operation has return type `!`
   ...
 8 |         resume(())
   |         ^^^^^^^^^ cannot resume an operation that never returns
```

### Solution

Don't call resume for non-resumable effects:

```sio
handler AbortHandler for Abort {
    abort(msg) => {
        println(msg)
        exit(1)  // Terminate instead of resuming
    }
}
```

## E0208: Effect Parameter Type Mismatch

**Diagnostic Code**: `effect::param_mismatch`

### Description

The types in an effect handler don't match the effect definition.

### Example

```sio
effect State<T> {
    fn get() -> T;
    fn put(value: T);
}

handler IntState for State<i32> {
    get() => resume(self.value),
    put(value: string) => {  // Error: expected i32, got string
        self.value = value
        resume(())
    }
}
```

**Error Message**:
```
error[E0208]: Effect parameter type mismatch
  --> example.sio:8:10
   |
 4 |     fn put(value: T);
   |                   - in effect definition, this is `i32`
   ...
 8 |     put(value: string) => {
   |               ^^^^^^ expected `i32`, found `string`
```

### Solution

Match the types in the effect definition:

```sio
handler IntState for State<i32> {
    get() => resume(self.value),
    put(value: i32) => {  // Correct type
        self.value = value
        resume(())
    }
}
```

## E0209: Missing Effect Operation Handler

**Diagnostic Code**: `effect::missing_op_handler`

### Description

An effect handler doesn't implement all operations defined by the effect.

### Example

```sio
effect State<T> {
    fn get() -> T;
    fn put(value: T);
}

handler PartialState for State<i32> {
    get() => resume(self.value),
    // Error: missing handler for `put`
}
```

**Error Message**:
```
error[E0209]: Missing effect operation handler
  --> example.sio:6:1
   |
 6 | handler PartialState for State<i32> {
   | ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ missing handler for `put`
   |
   = note: effect `State<i32>` requires handlers for: get, put
```

### Solution

Implement all effect operations:

```sio
handler CompleteState for State<i32> {
    get() => resume(self.value),
    put(value) => {
        self.value = value
        resume(())
    }
}
```

## E0210: Perform Outside Effect Context

**Diagnostic Code**: `effect::perform_outside_context`

### Description

The `perform` keyword was used outside of an effectful context.

### Example

```sio
fn pure_function() -> i32 {  // No effects declared
    perform Logger.log("test")  // Error: perform in pure function
    return 42
}
```

**Error Message**:
```
error[E0210]: Perform outside effect context
  --> example.sio:2:5
   |
 1 | fn pure_function() -> i32 {
   |    ------------- function has no effect declarations
 2 |     perform Logger.log("test")
   |     ^^^^^^^^^^^^^^^^^^^^^^^^^^ `perform` requires an effect context
   |
   = help: add the effect to the function signature with `with Logger`
```

### Solution

Declare the effect in the function signature:

```sio
fn effectful_function() -> i32 with Logger {
    perform Logger.log("test")
    return 42
}
```

## E0211: Effect Shadowing

**Diagnostic Code**: `effect::shadowing`

### Description

A local effect definition shadows a built-in or outer-scope effect.

### Example

```sio
effect IO {  // Error: shadows built-in IO
    fn custom_io();
}
```

**Error Message**:
```
error[E0211]: Effect shadowing
  --> example.sio:1:8
   |
 1 | effect IO {
   |        ^^ shadows built-in effect `IO`
   |
   = note: built-in effects cannot be redefined
   = help: use a different name for your custom effect
```

### Solution

Use a different name:

```sio
effect CustomIO {
    fn custom_io();
}
```

## Summary

| Code | Name | Quick Fix |
|------|------|-----------|
| E0200 | Effect Not Declared | Add `with Effect` to signature |
| E0201 | Unhandled Effect | Handle or propagate the effect |
| E0202 | Effect Mismatch | Match expected effects |
| E0203 | Effect In Pure Context | Move to runtime context |
| E0204 | Handler Type Mismatch | Fix handler implementation |
| E0205 | Unknown Effect | Define or import the effect |
| E0206 | Conflicting Handlers | Use one handler per effect |
| E0207 | Not Resumable | Don't resume non-returning ops |
| E0208 | Param Type Mismatch | Match effect type parameters |
| E0209 | Missing Op Handler | Implement all operations |
| E0210 | Perform Outside Context | Declare effect in signature |
| E0211 | Effect Shadowing | Use a different name |
