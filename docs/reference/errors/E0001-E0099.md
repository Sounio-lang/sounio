# Syntax Errors (E0001-E0099)

This section documents syntax errors that occur during lexical analysis and parsing.

---

## E0001: Unexpected Token

**Diagnostic Code**: `parse::unexpected_token`

### Description

The parser encountered a token that was not expected at the current position. This usually indicates a syntax error where the code structure doesn't match what Sounio expects.

### Example

```sio
fn add(a: i32 b: i32) -> i32 {  // Error: missing comma
    return a + b
}
```

**Error Message**:
```
error[E0001]: Unexpected token: expected `,`, found `b`
  --> example.sio:1:15
   |
 1 | fn add(a: i32 b: i32) -> i32 {
   |               ^ unexpected token here
```

### Common Causes

1. **Missing comma** between function parameters or struct fields
2. **Missing operator** between expressions
3. **Typo in keyword** (e.g., `funcion` instead of `fn`)
4. **Wrong delimiter** (e.g., using `(` where `{` is expected)

### Solution

Check the indicated location and add the missing token or fix the syntax:

```sio
fn add(a: i32, b: i32) -> i32 {  // Fixed: added comma
    return a + b
}
```

## E0002: Unclosed Delimiter

**Diagnostic Code**: `parse::unclosed_delimiter`

### Description

An opening delimiter (`(`, `[`, or `{`) was never closed with its matching closing delimiter.

### Example

```sio
fn process(data: &[i32] {  // Error: missing )
    for i in 0..len(data) {
        println(data[i])
    }
}
```

**Error Message**:
```
error[E0002]: Unclosed delimiter `(`
  --> example.sio:1:11
   |
 1 | fn process(data: &[i32] {
   |           ^ unclosed `(`
   |                        ^ expected `)` here
```

### Common Causes

1. **Forgot to close** a function parameter list
2. **Forgot to close** an array literal
3. **Forgot to close** a block
4. **Mismatched delimiters** (e.g., opened with `(`, tried to close with `}`)

### Solution

Add the missing closing delimiter:

```sio
fn process(data: &[i32]) {  // Fixed: added )
    for i in 0..len(data) {
        println(data[i])
    }
}
```

## E0003: Invalid Character

**Diagnostic Code**: `parse::invalid_char`

### Description

The lexer encountered a character that is not valid in Sounio source code.

### Example

```sio
let price = 100$  // Error: $ is not a valid character in this context
```

**Error Message**:
```
error[E0003]: Invalid character `$`
  --> example.sio:1:16
   |
 1 | let price = 100$
   |                ^ invalid character
   |
   = note: valid operators include +, -, *, /, %, etc.
```

### Common Causes

1. **Copy-paste from document** with smart quotes or special characters
2. **Using unsupported operators** from other languages
3. **Encoding issues** in the source file

### Solution

Replace the invalid character with valid Sounio syntax:

```sio
let price = 100  // Removed invalid character
```

## E0004: Unterminated String

**Diagnostic Code**: `parse::unterminated_string`

### Description

A string literal was started but never closed with a matching quote.

### Example

```sio
let message = "Hello, world
let x = 42
```

**Error Message**:
```
error[E0004]: Unterminated string literal
  --> example.sio:1:15
   |
 1 | let message = "Hello, world
   |               ^ string started here, but never closed
   |
   = help: add a closing `"` at the end of the string
```

### Common Causes

1. **Forgot to close** the string with `"`
2. **Line break in string** without proper escaping
3. **Unescaped quote** inside the string

### Solution

Close the string properly:

```sio
let message = "Hello, world"
let x = 42
```

For multi-line strings, use proper escaping:

```sio
let message = "Hello,\nworld"  // Use \n for newline
```

## E0005: Invalid Number Literal

**Diagnostic Code**: `parse::invalid_number`

### Description

A number literal has an invalid format.

### Example

```sio
let hex = 0xGHI    // Error: invalid hex digits
let bin = 0b102    // Error: 2 is not a binary digit
```

**Error Message**:
```
error[E0005]: Invalid number literal
  --> example.sio:1:11
   |
 1 | let hex = 0xGHI
   |           ^^^^^ invalid hexadecimal literal
   |
   = note: hexadecimal literals use digits 0-9 and letters a-f (or A-F)
```

### Common Causes

1. **Invalid digits** for the number base (hex, binary, octal)
2. **Multiple decimal points** in a float
3. **Invalid suffix** on a number literal

### Solution

Use valid digits for the number base:

```sio
let hex = 0xABC    // Valid hex
let bin = 0b101    // Valid binary
let oct = 0o777    // Valid octal
let dec = 12345    // Valid decimal
let flt = 3.14     // Valid float
```

## E0006: Missing Semicolon

**Diagnostic Code**: `parse::missing_semicolon`

### Description

A statement is missing its terminating semicolon.

### Example

```sio
fn main() {
    let x = 5
    let y = 10  // Error may appear here
    return x + y
}
```

**Error Message**:
```
error[E0006]: Expected `;` after statement
  --> example.sio:2:14
   |
 2 |     let x = 5
   |              ^ expected `;` here
   |
   = help: Add a semicolon `;` at the end of the statement
```

### Common Causes

1. **Forgot semicolon** after a let/var statement
2. **Copied code** from a language that doesn't require semicolons

### Solution

Add the semicolon:

```sio
fn main() {
    let x = 5;
    let y = 10;
    return x + y
}
```

Note: Return statements and expression-as-statements at the end of blocks do not require semicolons.

## E0010: Refinement Type Not Implemented

**Diagnostic Code**: `P0010`

### Description

Refinement type syntax was attempted but is not yet fully implemented.

### Example

```sio
type Positive = { x: i32 | x > 0 }  // Refinement type syntax
```

**Error Message**:
```
error[E0010]: Refinement type syntax not yet implemented
  --> example.sio:1:17
   |
 1 | type Positive = { x: i32 | x > 0 }
   |                 ^^^^^^^^^^^^^^^^^^ refinement type syntax attempted here
   |
   = help: The syntax `{ x: Type | constraint }` is planned but not yet available.
           Consider using a regular type with runtime validation for now.
```

### Solution

Use runtime validation instead:

```sio
struct Positive {
    value: i32
}

impl Positive {
    fn new(x: i32) -> Option<Positive> {
        if x > 0 {
            return Some(Positive { value: x })
        }
        return None
    }
}
```

## E0011: Wrong Mutable Reference Syntax

**Diagnostic Code**: `P0011`

### Description

Rust-style `&mut` was used instead of Sounio's `&!` syntax for mutable references.

### Example

```sio
fn increment(x: &mut i32) {  // Error: wrong syntax
    *x = *x + 1
}
```

**Error Message**:
```
error[E0011]: Sounio uses `&!` for mutable references, not `&mut`
  --> example.sio:1:17
   |
 1 | fn increment(x: &mut i32) {
   |                 ^^^^ use `&!` instead of `&mut`
   |
   = help: Replace `&mut T` with `&!T` for exclusive/mutable references.
           Sounio uses `&T` for shared references and `&!T` for mutable references.
```

### Solution

Use Sounio's `&!` syntax:

```sio
fn increment(x: &!i32) {  // Correct: &! for mutable reference
    *x = *x + 1
}
```

## E0012: Tuple Destructuring Not Supported

**Diagnostic Code**: `P0012`

### Description

Tuple destructuring in patterns is not supported.

### Example

```sio
let (x, y) = get_point()  // Error: tuple destructuring
```

**Error Message**:
```
error[E0012]: Tuple destructuring in patterns is not yet implemented
  --> example.sio:1:5
   |
 1 | let (x, y) = get_point()
   |     ^^^^^^ tuple destructuring pattern here
   |
   = help: Instead of `let (a, b) = tuple`, use:
             let a = tuple.0;
             let b = tuple.1;
```

### Solution

Access tuple elements individually:

```sio
let point = get_point()
let x = point.0
let y = point.1
```

## E0013: Rust Macro Not Supported

**Diagnostic Code**: `P0013`

### Description

Rust-style macros are not supported in Sounio.

### Example

```sio
fn main() {
    println!("Hello, world")  // Error: Rust macro syntax
}
```

**Error Message**:
```
error[E0013]: Rust-style macros are not supported in Sounio
  --> example.sio:2:5
   |
 2 |     println!("Hello, world")
   |     ^^^^^^^^ Rust macro syntax not supported
   |
   = help: Use the IO effect with print functions:
             fn main() with IO { print("message"); }
```

### Common Macros and Alternatives

| Rust Macro | Sounio Alternative |
|------------|-------------------|
| `println!()` | `println()` with `IO` effect |
| `print!()` | `print()` with `IO` effect |
| `assert!()` | `assert()` function |
| `vec![]` | Array literal `[1, 2, 3]` |
| `panic!()` | `panic()` with `Panic` effect |

### Solution

```sio
fn main() with IO {
    println("Hello, world")  // Correct: no ! needed
}
```

## E0014: Rust Attribute Not Supported

**Diagnostic Code**: `P0014`

### Description

Rust-style attributes are not supported.

### Example

```sio
#[derive(Debug, Clone)]  // Error: Rust attribute
struct Point {
    x: f64,
    y: f64,
}
```

**Error Message**:
```
error[E0014]: Rust-style attribute syntax is not supported
  --> example.sio:1:1
   |
 1 | #[derive(Debug, Clone)]
   | ^^^^^^^^^^^^^^^^^^^^^^^ unsupported attribute
   |
   = help: Sounio does not have automatic derive. Implement traits manually.
```

### Solution

Implement traits manually:

```sio
struct Point {
    x: f64,
    y: f64,
}

impl Debug for Point {
    fn debug(&self) -> string {
        return format("Point {{ x: {}, y: {} }}", self.x, self.y)
    }
}
```

## E0015: Closure Tuple Destructuring Not Supported

**Diagnostic Code**: `P0015`

### Description

Tuple destructuring in closure parameters is not supported.

### Example

```sio
let pairs = [(1, 2), (3, 4)]
let sums = pairs.map(|(a, b)| a + b)  // Error
```

**Error Message**:
```
error[E0015]: Tuple destructuring in closure parameters is not supported
  --> example.sio:2:22
   |
 2 | let sums = pairs.map(|(a, b)| a + b)
   |                      ^^^^^^^^ closure with tuple destructuring
   |
   = help: Instead of `|(a, b)| expr`, use:
             |pair| { let a = pair.0; let b = pair.1; expr }
```

### Solution

```sio
let pairs = [(1, 2), (3, 4)]
let sums = pairs.map(|pair| pair.0 + pair.1)  // Correct
```

## E0021: Invalid Module Level Item

**Diagnostic Code**: `P0021`

### Description

An item was placed at module level that is not valid there.

### Example

```sio
x + y  // Error: expression at module level
```

**Error Message**:
```
error[E0021]: Invalid item at module level
  --> example.sio:1:1
   |
 1 | x + y
   | ^^^^^ unexpected item
   |
   = help: Only declarations (fn, struct, enum, trait, etc.) are allowed at module level
```

### Solution

Place expressions inside functions:

```sio
fn main() {
    let result = x + y  // Correct: inside a function
}
```

## E0030: Unexpected End of File

**Diagnostic Code**: `parse::unexpected_eof`

### Description

The file ended unexpectedly while parsing an incomplete construct.

### Example

```sio
fn main() {
    let x = 5
// File ends here without closing brace
```

**Error Message**:
```
error[E0030]: Unexpected end of file
  --> example.sio:2:14
   |
 2 |     let x = 5
   |              ^ expected more tokens
   |
   = note: did you forget to close a block with `}`?
```

### Solution

Complete the construct:

```sio
fn main() {
    let x = 5
}  // Added closing brace
```
