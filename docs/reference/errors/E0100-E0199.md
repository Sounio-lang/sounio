# Type Errors (E0100-E0199)

This section documents errors related to the type system, including type mismatches, inference failures, and generic constraint violations.

---

## E0100: Type Mismatch

**Diagnostic Code**: `typecheck::mismatch`

### Description

The type of a value does not match the expected type at a given location.

### Example

```sio
fn add_numbers(a: i32, b: i32) -> i32 {
    return a + b
}

fn main() {
    let result = add_numbers(5, "ten")  // Error: string is not i32
}
```

**Error Message**:
```
error[E0100]: Type mismatch: expected `i32`, found `string`
  --> example.sio:6:33
   |
 6 |     let result = add_numbers(5, "ten")
   |                                 ^^^^^ expected `i32`
   |
   = help: convert the string to an integer with `parse()`
```

### Common Causes

1. **Wrong argument type** passed to a function
2. **Assigning a value** to a variable with a different type
3. **Return type** doesn't match function signature
4. **Operator applied** to incompatible types

### Solution

Ensure types match:

```sio
fn main() {
    let result = add_numbers(5, 10)  // Correct: both i32
}
```

Or convert the type:

```sio
fn main() {
    let ten: i32 = parse("10")?
    let result = add_numbers(5, ten)
}
```

## E0101: Cannot Infer Type

**Diagnostic Code**: `typecheck::annotation_required`

### Description

The compiler cannot determine the type of an expression and requires a type annotation.

### Example

```sio
fn main() {
    let items = []  // Error: cannot infer element type
}
```

**Error Message**:
```
error[E0101]: Cannot infer type
  --> example.sio:2:9
   |
 2 |     let items = []
   |         ^^^^^ cannot infer type
   |
   = help: add a type annotation: `let x: Type = ...`
```

### Common Causes

1. **Empty collections** with no type context
2. **Generic functions** called without enough type information
3. **Closures** with ambiguous parameter types

### Solution

Add a type annotation:

```sio
fn main() {
    let items: Vec<i32> = []  // Explicit type annotation
}
```

Or provide type context through usage:

```sio
fn main() {
    let items = []
    items.push(42)  // Compiler can now infer Vec<i32>
}
```

## E0102: Missing Type Annotation

**Diagnostic Code**: `typecheck::annotation_required`

### Description

A type annotation is required but was not provided.

### Example

```sio
fn process(data) {  // Error: parameter type missing
    return data
}
```

**Error Message**:
```
error[E0102]: Missing type annotation
  --> example.sio:1:12
   |
 1 | fn process(data) {
   |            ^^^^ cannot infer type
   |
   = help: add a type annotation: `data: Type`
```

### Common Causes

1. **Function parameters** without type annotations
2. **Struct fields** without types
3. **Static/const declarations** without types

### Solution

Add the required type annotation:

```sio
fn process(data: &[i32]) -> i32 {  // Added type annotations
    return data[0]
}
```

## E0103: Invalid Type for Operation

**Diagnostic Code**: `typecheck::invalid_op`

### Description

An operator or operation was applied to a type that doesn't support it.

### Example

```sio
fn main() {
    let name = "Alice"
    let result = name * 2  // Error: cannot multiply string
}
```

**Error Message**:
```
error[E0103]: Invalid type for operation
  --> example.sio:3:18
   |
 3 |     let result = name * 2
   |                  ^^^^^^^^ cannot apply `*` to `string` and `i32`
   |
   = note: the `*` operator requires numeric types
   = help: use `repeat()` to repeat a string
```

### Common Causes

1. **Arithmetic on non-numeric types**
2. **Comparison of incompatible types**
3. **Indexing a non-collection type**
4. **Calling a non-function value**

### Solution

Use the appropriate operation for the type:

```sio
fn main() {
    let name = "Alice"
    let result = name.repeat(2)  // "AliceAlice"
}
```

## E0104: Generic Constraint Not Satisfied

**Diagnostic Code**: `typecheck::constraint_not_satisfied`

### Description

A type parameter does not satisfy the required trait bounds.

### Example

```sio
fn print_debug<T: Debug>(value: T) {
    println(value.debug())
}

struct Secret {
    data: i32
}

fn main() {
    let s = Secret { data: 42 }
    print_debug(s)  // Error: Secret doesn't implement Debug
}
```

**Error Message**:
```
error[E0104]: Generic constraint not satisfied
  --> example.sio:11:5
   |
11 |     print_debug(s)
   |     ^^^^^^^^^^^^^^ `Secret` does not implement `Debug`
   |
   = note: required by bound `T: Debug` in `print_debug`
```

### Solution

Implement the required trait:

```sio
impl Debug for Secret {
    fn debug(&self) -> string {
        return format("Secret {{ data: {} }}", self.data)
    }
}
```

## E0105: Unification Failed

**Diagnostic Code**: `typecheck::unification_failed`

### Description

Two types cannot be unified during type inference.

### Example

```sio
fn main() {
    let x = if true { 5 } else { "five" }  // Error: branches have different types
}
```

**Error Message**:
```
error[E0105]: Cannot unify `i32` with `string`
  --> example.sio:2:13
   |
 2 |     let x = if true { 5 } else { "five" }
   |             ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ type mismatch here
   |
   = note: if-else branches must have the same type
```

### Solution

Ensure all branches return the same type:

```sio
fn main() {
    let x = if true { 5 } else { 0 }  // Both branches return i32
}
```

Or use an enum to represent the choice:

```sio
enum Value {
    Int(i32),
    Str(string),
}

fn main() {
    let x = if true { Value::Int(5) } else { Value::Str("five") }
}
```

## E0106: Undefined Type

**Diagnostic Code**: `resolve::undefined_type`

### Description

A type name was used that has not been defined.

### Example

```sio
fn process(data: Listint) -> Listint {  // Typo: should be List<int>
    return data
}
```

**Error Message**:
```
error[E0106]: Undefined type `Listint`
  --> example.sio:1:18
   |
 1 | fn process(data: Listint) -> Listint {
   |                  ^^^^^^^ type not found
   |
   = help: did you mean `List<i32>`?
```

### Common Causes

1. **Typo** in the type name
2. **Missing import** for the type
3. **Type not defined** in scope

### Solution

Fix the type name or import it:

```sio
import std::collections::List

fn process(data: List<i32>) -> List<i32> {
    return data
}
```

## E0107: Recursive Type Without Indirection

**Diagnostic Code**: `typecheck::infinite_type`

### Description

A type is defined recursively without using a pointer or box for indirection.

### Example

```sio
struct Node {
    value: i32,
    next: Node,  // Error: infinite size
}
```

**Error Message**:
```
error[E0107]: Recursive type without indirection
  --> example.sio:3:5
   |
 3 |     next: Node,
   |           ^^^^ recursive without indirection
   |
   = note: recursive types must use a pointer for indirection
   = help: use `Option<Box<Node>>` or `&Node`
```

### Solution

Use a pointer type for indirection:

```sio
struct Node {
    value: i32,
    next: Option<Box<Node>>,  // Box provides indirection
}
```

## E0108: Mismatched Array Lengths

**Diagnostic Code**: `typecheck::array_length_mismatch`

### Description

An array literal or assignment has a length that doesn't match the expected array type.

### Example

```sio
fn main() {
    let arr: [i32; 3] = [1, 2, 3, 4, 5]  // Error: expected 3, got 5
}
```

**Error Message**:
```
error[E0108]: Mismatched array lengths
  --> example.sio:2:25
   |
 2 |     let arr: [i32; 3] = [1, 2, 3, 4, 5]
   |                         ^^^^^^^^^^^^^^ expected 3 elements, found 5
```

### Solution

Match the array length to the type:

```sio
fn main() {
    let arr: [i32; 5] = [1, 2, 3, 4, 5]  // Correct length
}
```

## E0109: Expected Function Type

**Diagnostic Code**: `typecheck::not_callable`

### Description

A value was called as a function, but it is not a function type.

### Example

```sio
fn main() {
    let x = 42
    let result = x(5)  // Error: i32 is not callable
}
```

**Error Message**:
```
error[E0109]: Expected function type
  --> example.sio:3:18
   |
 3 |     let result = x(5)
   |                  ^^^^ `i32` is not callable
   |
   = note: only function types and types implementing `FnOnce` can be called
```

### Solution

Call a function instead:

```sio
fn double(n: i32) -> i32 {
    return n * 2
}

fn main() {
    let result = double(5)  // Correct: calling a function
}
```

## E0110: Return Type Mismatch

**Diagnostic Code**: `typecheck::return_mismatch`

### Description

The return type of a function body doesn't match the declared return type.

### Example

```sio
fn get_name() -> i32 {
    return "Alice"  // Error: returning string, declared i32
}
```

**Error Message**:
```
error[E0110]: Return type mismatch
  --> example.sio:2:12
   |
 1 | fn get_name() -> i32 {
   |                  ^^^ expected `i32` because of return type
 2 |     return "Alice"
   |            ^^^^^^^ found `string`
```

### Solution

Return the correct type or fix the signature:

```sio
fn get_name() -> string {  // Fixed return type
    return "Alice"
}
```

## E0111: Missing Return Value

**Diagnostic Code**: `typecheck::missing_return`

### Description

A function with a non-unit return type doesn't return a value in all paths.

### Example

```sio
fn absolute(x: i32) -> i32 {
    if x < 0 {
        return -x
    }
    // Error: missing return when x >= 0
}
```

**Error Message**:
```
error[E0111]: Missing return value
  --> example.sio:1:1
   |
 1 | fn absolute(x: i32) -> i32 {
   | ^^^^^^^^^^^^^^^^^^^^^^^^^^ function must return `i32` in all paths
   |
   = note: not all code paths return a value
```

### Solution

Add return statements for all paths:

```sio
fn absolute(x: i32) -> i32 {
    if x < 0 {
        return -x
    }
    return x  // Added missing return
}
```

## E0112: Invalid Cast

**Diagnostic Code**: `typecheck::invalid_cast`

### Description

A type cast was attempted that is not valid.

### Example

```sio
fn main() {
    let name = "Alice"
    let num = name as i32  // Error: cannot cast string to i32
}
```

**Error Message**:
```
error[E0112]: Invalid cast
  --> example.sio:3:15
   |
 3 |     let num = name as i32
   |               ^^^^^^^^^^^ cannot cast `string` to `i32`
   |
   = help: use `parse()` to convert a string to a number
```

### Valid Casts

| From | To | Valid |
|------|-----|-------|
| Numeric | Numeric | Yes |
| `char` | `u32` | Yes |
| Reference | Raw pointer | Yes |
| Enum | Integer | Yes |
| `string` | `i32` | No (use `parse()`) |

### Solution

Use conversion functions:

```sio
fn main() {
    let name = "42"
    let num = parse::<i32>(name)?  // Correct: use parse
}
```

## E0115: Duplicate Type Parameter

**Diagnostic Code**: `typecheck::duplicate_type_param`

### Description

A type parameter name is used more than once in the same generic declaration.

### Example

```sio
fn process<T, T>(a: T, b: T) -> T {  // Error: T used twice
    return a
}
```

**Error Message**:
```
error[E0115]: Duplicate type parameter `T`
  --> example.sio:1:15
   |
 1 | fn process<T, T>(a: T, b: T) -> T {
   |            -  ^ duplicate type parameter
   |            |
   |            first definition here
```

### Solution

Use unique type parameter names:

```sio
fn process<T, U>(a: T, b: U) -> T {
    return a
}
```
