# Ownership Errors (E0300-E0399)

This section documents errors related to ownership, borrowing, and linear/affine type checking in Sounio.

---

## E0300: Use of Moved Value

**Diagnostic Code**: `ownership::use_after_move`

### Description

A value was used after it was moved to another location.

### Example

```sio
fn main() {
    let data = Vec::new()
    process(data)      // data is moved here
    println(data.len())  // Error: data was already moved
}

fn process(v: Vec<i32>) {
    // v is consumed here
}
```

**Error Message**:
```
error[E0300]: Use of moved value `data`
  --> example.sio:4:13
   |
 3 |     process(data)
   |             ---- value moved here
 4 |     println(data.len())
   |             ^^^^ value used here after move
```

### Common Causes

1. **Passing owned value** to a function that takes ownership
2. **Assigning owned value** to another variable
3. **Returning owned value** from a function and then using it

### Solution

Option 1: Clone the value before moving:
```sio
fn main() {
    let data = Vec::new()
    process(data.clone())  // Clone before passing
    println(data.len())    // Original still available
}
```

Option 2: Use a reference instead:
```sio
fn main() {
    let data = Vec::new()
    process(&data)         // Pass reference
    println(data.len())    // Original still available
}

fn process(v: &Vec<i32>) {
    // Borrows v, doesn't consume
}
```

## E0301: Borrow of Moved Value

**Diagnostic Code**: `ownership::borrow_after_move`

### Description

An attempt was made to borrow a value that has already been moved.

### Example

```sio
fn main() {
    let data = create_data()
    consume(data)       // data is moved
    let ref = &data     // Error: cannot borrow moved value
}
```

**Error Message**:
```
error[E0301]: Borrow of moved value `data`
  --> example.sio:4:15
   |
 3 |     consume(data)
   |             ---- value moved here
 4 |     let ref = &data
   |               ^^^^^ cannot borrow after move
```

### Solution

Borrow before moving:
```sio
fn main() {
    let data = create_data()
    let ref = &data     // Borrow first
    use_ref(ref)        // Use the borrow
    consume(data)       // Then move
}
```

## E0302: Cannot Borrow as Mutable

**Diagnostic Code**: `ownership::already_borrowed`

### Description

Cannot borrow a value as mutable because it is already borrowed.

### Example

```sio
fn main() {
    let data = Vec::new()
    let r1 = &data         // Shared borrow
    let r2 = &!data        // Error: cannot borrow as mutable
    println(r1.len())
}
```

**Error Message**:
```
error[E0302]: Cannot borrow `data` as mutable because it is already borrowed
  --> example.sio:4:14
   |
 3 |     let r1 = &data
   |              ----- previous borrow here
 4 |     let r2 = &!data
   |              ^^^^^^ cannot borrow as mutable
 5 |     println(r1.len())
   |             -- previous borrow used here
```

### Borrowing Rules

Sounio's borrowing rules (similar to Rust):
- You can have multiple shared references (`&T`) to a value
- You can have ONE exclusive reference (`&!T`) to a value
- You cannot have both shared and exclusive references at the same time

### Solution

End the shared borrow before taking a mutable one:
```sio
fn main() {
    let data = Vec::new()
    let r1 = &data
    println(r1.len())   // Use and end shared borrow

    let r2 = &!data     // Now safe to borrow mutably
    r2.push(42)
}
```

## E0303: Cannot Borrow Twice as Mutable

**Diagnostic Code**: `ownership::double_mut_borrow`

### Description

Cannot create two mutable borrows of the same value at the same time.

### Example

```sio
fn main() {
    var data = Vec::new()
    let r1 = &!data    // First mutable borrow
    let r2 = &!data    // Error: second mutable borrow
    r1.push(1)
    r2.push(2)
}
```

**Error Message**:
```
error[E0303]: Cannot borrow `data` as mutable more than once
  --> example.sio:4:14
   |
 3 |     let r1 = &!data
   |              ------ first mutable borrow here
 4 |     let r2 = &!data
   |              ^^^^^^ second mutable borrow here
 5 |     r1.push(1)
   |     -- first borrow used here
```

### Solution

Use borrows sequentially:
```sio
fn main() {
    var data = Vec::new()
    let r1 = &!data
    r1.push(1)
    // r1's borrow ends here

    let r2 = &!data    // Now safe
    r2.push(2)
}
```

Or use different parts:
```sio
fn main() {
    var data = [1, 2, 3, 4]
    let (left, right) = data.split_at_mut(2)
    left[0] = 10      // Mutate left half
    right[0] = 30     // Mutate right half simultaneously
}
```

## E0304: Cannot Mutate Through Shared Reference

**Diagnostic Code**: `ownership::mutate_shared`

### Description

An attempt was made to mutate data through a shared reference.

### Example

```sio
fn increment(x: &i32) {
    *x = *x + 1  // Error: cannot mutate through shared reference
}
```

**Error Message**:
```
error[E0304]: Cannot mutate through shared reference
  --> example.sio:2:5
   |
 1 | fn increment(x: &i32) {
   |                 ---- shared reference
 2 |     *x = *x + 1
   |     ^^ cannot assign through shared reference
   |
   = help: use `&!i32` for a mutable reference
```

### Solution

Use an exclusive reference:
```sio
fn increment(x: &!i32) {  // Changed to &!
    *x = *x + 1
}
```

## E0310: Linear Value Used Multiple Times

**Diagnostic Code**: `linear::multiple_use`

### Description

A linear type value was used more than once. Linear types must be used exactly once.

### Example

```sio
linear struct Connection {
    fd: i32
}

fn main() {
    let conn = Connection { fd: 5 }
    process(conn)   // First use
    cleanup(conn)   // Error: second use of linear value
}
```

**Error Message**:
```
error[E0310]: Linear value `conn` used more than once
  --> example.sio:8:13
   |
 7 |     process(conn)
   |             ---- first use here
 8 |     cleanup(conn)
   |             ^^^^ second use here
   |
   = help: linear values must be used exactly once
```

### Solution

Use the linear value only once:
```sio
fn main() {
    let conn = Connection { fd: 5 }
    let conn = process(conn)  // Returns a new Connection
    cleanup(conn)             // Use the returned value
}
```

## E0311: Linear Value Not Consumed

**Diagnostic Code**: `linear::not_consumed`

### Description

A linear type value went out of scope without being consumed.

### Example

```sio
linear struct FileHandle {
    fd: i32
}

fn main() {
    let handle = FileHandle { fd: open("file.txt") }
    // Error: handle goes out of scope without being consumed
}
```

**Error Message**:
```
error[E0311]: Linear value `handle` not consumed
  --> example.sio:6:9
   |
 6 |     let handle = FileHandle { fd: open("file.txt") }
   |         ^^^^^^ linear value declared here
 7 | }
   | - goes out of scope here without being consumed
   |
   = help: linear values must be explicitly consumed before going out of scope
```

### Solution

Explicitly consume the linear value:
```sio
fn main() {
    let handle = FileHandle { fd: open("file.txt") }
    handle.close()  // Explicitly consume
}

impl FileHandle {
    fn close(self) {  // Takes ownership, consuming the value
        close(self.fd)
    }
}
```

## E0312: Affine Value Used Multiple Times

**Diagnostic Code**: `affine::multiple_use`

### Description

An affine type value was used more than once. Affine types can be used at most once.

### Example

```sio
affine struct TempBuffer {
    data: *u8
}

fn main() {
    let buf = TempBuffer { data: alloc(1024) }
    process(buf)   // First use - OK
    process(buf)   // Error: second use
}
```

**Error Message**:
```
error[E0312]: Affine value `buf` used more than once
  --> example.sio:8:13
   |
 7 |     process(buf)
   |             --- first use here
 8 |     process(buf)
   |             ^^^ second use here
```

### Difference from Linear Types

- **Linear**: Must be used exactly once
- **Affine**: Must be used at most once (zero or one times)

### Solution

```sio
fn main() {
    let buf = TempBuffer { data: alloc(1024) }
    process(buf)   // Use only once
    // buf is implicitly dropped if not used
}
```

## E0315: Cannot Move Out of Reference

**Diagnostic Code**: `ownership::move_from_ref`

### Description

An attempt was made to move a value out of a reference.

### Example

```sio
fn extract(data: &Container) -> Inner {
    return data.inner  // Error: cannot move out of reference
}
```

**Error Message**:
```
error[E0315]: Cannot move out of reference
  --> example.sio:2:12
   |
 2 |     return data.inner
   |            ^^^^^^^^^^ cannot move out of `&Container`
   |
   = help: consider cloning the value or taking ownership
```

### Solution

Option 1: Clone the value:
```sio
fn extract(data: &Container) -> Inner {
    return data.inner.clone()
}
```

Option 2: Take ownership of the container:
```sio
fn extract(data: Container) -> Inner {
    return data.inner
}
```

Option 3: Return a reference:
```sio
fn extract(data: &Container) -> &Inner {
    return &data.inner
}
```

## E0316: Dangling Reference

**Diagnostic Code**: `ownership::dangling`

### Description

A reference would outlive the data it refers to.

### Example

```sio
fn get_reference() -> &i32 {
    let local = 42
    return &local  // Error: local is dropped at end of function
}
```

**Error Message**:
```
error[E0316]: Dangling reference
  --> example.sio:3:12
   |
 2 |     let local = 42
   |         ----- binding created here
 3 |     return &local
   |            ^^^^^^ reference would outlive `local`
 4 | }
   | - `local` dropped here
```

### Solution

Return an owned value instead:
```sio
fn get_value() -> i32 {
    let local = 42
    return local  // Return owned value
}
```

Or ensure the referenced data lives long enough:
```sio
fn get_reference(data: &i32) -> &i32 {
    return data  // Reference to parameter, which outlives the call
}
```

## E0320: Invalid Drop

**Diagnostic Code**: `ownership::invalid_drop`

### Description

A value that cannot be dropped is being dropped.

### Example

```sio
linear struct MustUse {
    value: i32
}

fn main() {
    let x = MustUse { value: 42 }
    drop(x)  // Error: linear types cannot be dropped
}
```

**Error Message**:
```
error[E0320]: Invalid drop
  --> example.sio:7:5
   |
 7 |     drop(x)
   |     ^^^^^^^ cannot drop linear type `MustUse`
   |
   = note: linear types must be consumed, not dropped
```

### Solution

Consume the linear type properly:
```sio
impl MustUse {
    fn consume(self) {
        // Proper consumption logic
    }
}

fn main() {
    let x = MustUse { value: 42 }
    x.consume()  // Proper consumption
}
```

## E0325: Reference Escapes Closure

**Diagnostic Code**: `ownership::ref_escapes_closure`

### Description

A reference captured by a closure would escape the closure's scope.

### Example

```sio
fn create_closure() -> fn() -> i32 {
    let value = 42
    return || value  // Error: value doesn't live long enough
}
```

**Error Message**:
```
error[E0325]: Reference escapes closure
  --> example.sio:3:12
   |
 2 |     let value = 42
   |         ----- captured variable
 3 |     return || value
   |            ^^^^^^^^ closure may outlive `value`
```

### Solution

Move the value into the closure:
```sio
fn create_closure() -> fn() -> i32 {
    let value = 42
    return move || value  // Move value into closure
}
```

## Summary

| Code | Name | Quick Fix |
|------|------|-----------|
| E0300 | Use of Moved Value | Clone or use reference |
| E0301 | Borrow of Moved Value | Borrow before moving |
| E0302 | Cannot Borrow as Mutable | End shared borrow first |
| E0303 | Double Mutable Borrow | Use borrows sequentially |
| E0304 | Mutate Through Shared Ref | Use `&!T` instead of `&T` |
| E0310 | Linear Multiple Use | Use exactly once |
| E0311 | Linear Not Consumed | Explicitly consume |
| E0312 | Affine Multiple Use | Use at most once |
| E0315 | Move Out of Reference | Clone or take ownership |
| E0316 | Dangling Reference | Return owned value |
| E0320 | Invalid Drop | Consume properly |
| E0325 | Reference Escapes Closure | Use `move` closure |

## Ownership Quick Reference

### Type Categories

| Category | Can Copy | Can Drop | Uses |
|----------|----------|----------|------|
| Copy | Yes | Yes | Unlimited |
| Move | No | Yes | Once |
| Affine | No | Yes | 0 or 1 |
| Linear | No | No | Exactly 1 |

### Reference Types

| Syntax | Name | Allows |
|--------|------|--------|
| `&T` | Shared reference | Read only |
| `&!T` | Exclusive reference | Read and write |

### Borrowing Rules

1. Multiple `&T` allowed simultaneously
2. Only one `&!T` allowed at a time
3. Cannot have `&T` and `&!T` simultaneously
4. References must not outlive the referent
