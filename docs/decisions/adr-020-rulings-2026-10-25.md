# ADR-020: Eight rulings from the 2026-10-25 decision session

**Status**: accepted (implementation pending)
**Date**: 2026-10-25
**Decided by**: the founder, choosing among the options recorded in `PENDING.md`

## Context

These eight items were open in [`PENDING.md`](PENDING.md). Each carried a question, its options, a recommendation, a discriminating test and a localised cause. Each one touches either a printed number or the set of programs that compile, so under [ADR-018](adr-018-release-cycle-and-versioning.md) its release class has to be known before the 3.0 train ships. Every ruling below takes the recommended option. The measurements behind them are in the original `PENDING.md` sections, which this ADR replaces.

## Decision

| § | Ruling | Release class (ADR-018) | Train |
|---|--------|-------------------------|-------|
| D-22 | PBPK blood/plasma: **convert** whole-blood AUC to plasma by dividing by `rb_ratio` at the six coupling points of `stdlib/darwin_pbpk/scenarios/steady_state_runner.sio`. | `numerical-correction` | 3.0 |
| D-27 | Chemistry goldens: **accept** correctly rounded literals in `lean_single`. Regenerate the goldens and **re-derive** `benchmarks/chemistry/RESULTS.md`; the founder checks the paper numbers. | `numerical-correction` | 3.0 |
| D-24 | A dimensionless value passed to a unit-bearing parameter is **an error on both engines**. This is consistent with KL-13, already in 3.0. | `refusal` | 3.0 |
| D-25 | `n as string` is **permanently E270**. Text comes from an explicit formatting function. | none: already the behaviour | 3.0 (record only) |
| D-20 | A type error in an imported module becomes **fatal in `lean_single`**, but only after the 121 files it would refuse have been classified as corpus defects or regressions. | `refusal` (dev engine) | 3.1 |
| D-15 | The empty effect row is spelled **`with ()`**: `fn apply(f: fn(f64) -> f64 with (), x: f64)` checks on both engines. | `added` | 3.1 |
| D-16 | Keywords are **valid as field names, contextually**. `lean_single` accepts every keyword that Madaros accepts, and spec §2.2 is amended. | `added` | 3.1 |
| D-26 | Implicit borrows at a call **only for identifiers**. Temporaries and fields need an explicit `&`, so `lean_single` refuses as Madaros already does. | `refusal` (dev engine) | 3.1 |

## Acceptance

Each ruling is closed by the discriminating test recorded for it, run on both engines:

1. **D-22**: haloperidol (`rb_ratio = 1`) is bit-identical before and after, and the rapamycin AUC scales by exactly `1/0.58`.
2. **D-27**: `bash scripts/ci/chemistry_probe_golden_gate.sh` is green against the regenerated goldens, and `RESULTS.md` is consistent with them.
3. **D-24**: `tests/run-pass/unit_parameter_representation_issue2874.sio` and `tests/multimodule/unit_representation_2874` pass a value with its unit. The same call without the unit is refused on both engines.
4. **D-25**: `tests/compile-fail` contains `println(n as string)` expecting E270 on both engines.
5. **D-20**: a classification of the 121 newly refused corpus files is committed. Then `helper.sio` with `let x: i64 = true`, imported by `main.sio`, makes `check` and `run` exit non-zero on `lean_single`.
6. **D-15**: the `apply` signature above checks on both engines, and `examples/higher_order.sio` stops over-declaring `with Mut, Panic, Div`.
7. **D-16**: `struct G { mu: f64, var: f64 }` with `g.var`, and fields named `type`, `fn`, `let` and `module`, print the same value on both engines.
8. **D-26**: `getw(make_w())` and `sum2(o.inner, ..)` get the same verdict (refused) on both engines.

## Consequences

- D-22 and D-27 change printed numbers. They ship as `numerical-correction` fragments that cite their oracles, the `rb_ratio` identity and the correctly rounded literal, and they go into the 3.0 CHANGELOG under *Numerical corrections*.
- D-24 is a source break, allowed in 3.0 as a major and consistent with KL-13. A program that passes a bare number to a unit-bearing parameter must state the unit.
- D-20 and D-26 refuse programs only on `lean_single`, the development engine; the shipped Madaros already behaves this way. They are scheduled for 3.1 with `refusal` fragments.
- D-15 and D-16 are additions and do not break existing programs.

## Implementation

One board card per ruling, under EPIC · Decisions owed, each with the acceptance test above. D-25 needs no code change; its card closes when the compile-fail test is committed.
