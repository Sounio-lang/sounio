# ADR-028: Rulings from the 2026-11-09 decision session

**Status**: accepted (implementation pending)
**Date**: 2026-11-09
**Decided by**: the founder, choosing among the options recorded in `PENDING.md` and in the 2026-10-23 decision brief
**Replaces**: every open section of [`PENDING.md`](PENDING.md) (D-01–D-14, D-17–D-19, D-21, D-23, D-28–D-32, D-34)

## Context

`PENDING.md` held 25 open decisions, last validated on 2026-10-13. Before each ruling the section was re-measured against `main` at `5db16503`; where the state had moved, the ruling below is taken against the current state, not the one recorded in the section. Two sections had already been decided in earlier sessions and only lacked a record (D-03, D-17). D-34 had been decided on 2026-10-24 in ADR-019 (reserved by PR #3101, not yet on `main`); this session confirms it and adds one target.

The same session also closed the questions of the 2026-10-23 decision brief that are language decisions: the `Mut` effect (recorded here as D-35) and the prohibition of field resolution by name hash (recorded as an amendment to [ADR-026](adr-026-phase-arenas.md)).

Release classes follow [ADR-018](adr-018-release-cycle-and-versioning.md).

## Decision

### Formal verification and trust

**D-01 — Model of `Float` in the Lean proofs.** The axioms `float_le_refl`, `float_le_trans` and `float_add_le_add` (`formal/TypeCheckerSoundness.lean:47–53`, `formal/Epistemic.lean:277–286`, `formal/SecondOrderGUM.lean:153–156`) quantify over every Lean `Float`, NaN included. Since `NaN ≤ NaN` is false and decidable in Lean, each of the three files derives `False`. Documenting the restriction (option A of the section) does not remove the inconsistency. **Ruling:** the proofs stop reasoning about Lean `Float`. They reason over an exact model — `Rat` extended by ±∞, the model ADR-019 already uses, so the core tree stays inside the [ADR-011](adr-011-mathlib-scope-in-formal-verification.md) boundary — and the correspondence with IEEE 754 is a separate, explicit bridge theorem. The three axioms are deleted. Class: `internal`. Train: 3.1.

**D-10 — Bootstrap chain `stage0 → boot4`.** `boot4.elf` no longer parses the current `lean_single.sio` (`nd_cap = 262143` against 362,541 tokens; `BAD NODE` loop, rc 124 after 181 s; `boot4_a1.elf` rc 139), yet `bootstrap/README.md:14,35,48` says it does. The gen2 = gen3 fixed point of ADR-006 proves self-consistency, not the absence of a trusting-trust payload in the seed. **Ruling:** now, `bootstrap/README.md` names the committed seed as the provenance root (`bin/souc-lean-single-x86_64.SeedReceipt.json` verified by `verify_lean_seed.sh SOUNIO_SEED_DDC=1`) and states that boot4 does not parse the current compiler; `Makefile:32-33` stops using `./bin/souc-linux-x86_64`. Rebuilding the C chain up to the current fixed point is a standing trust requirement in the backlog. Class: `internal`.

**D-29 — macOS ARM64 seed.** **Ruling:** the arm64 seed is built natively on an Apple M-series host and published with a `SeedReceipt` JSON sidecar that mirrors the x86-64 one; a gate verifies it. Every published seed carries a verifiable receipt (consistent with D-10). Class: `internal`.

### Foreign function interface

**D-04 — `LibraryId` as a first-class FFI entity.** `native_v2_dynlink_soname_for_lib_id` (`self-hosted/native/codegen_x86_linux.sio:2101`) is a fixed table of seven libraries and returns `libkl14b_probe.so`, a test library, for any unknown id. **Ruling:** first, an unknown library id is refused (fail-closed, no fallback); then `extern "C" from "<soname>" { … }` becomes user-declarable and the fixed table is removed. Class: `refusal`, then `added`.

**D-05 — Symbol interposition.** Once D-04 makes `from "<lib>"` a statement of the source, global ELF symbol scope can contradict it. **Ruling:** a symbol declared `from "X"` always resolves in X — per-library isolation (symbol versioning or `dlopen(RTLD_LOCAL)` + `dlsym` on X's handle; the mechanism is an implementation choice). Depends on D-04 step 2. Class: `semantics`.

### Repository and corpus

Class: `removed`.

**D-07 — Source-fresh aliasing / associator line.** The three commits are preserved by tags (`archive/2026-10-05/codex/psychiatric-inference-main-20260724`, `archive/2026-10-05/codex/psychiatric-state-aliasing-20260724`, `archive/2026-10-24/d-07-epistemic-receipts-1573ca2bf`) and the original blocker is resolved. **Ruling:** reland — cherry-pick `1d96a35d8`, `0a8131abf`, `1573ca2bf` onto `main`. Class: `added`.

**D-09 — EISA-H hardware repository.** **Ruling:** the three pending partition certificates and their review are done in `sounio-hardware`, which publishes a receipt; `Sounio-lang/sounio` gains a gate in `scripts/ci` that reads that receipt and fails if it is missing or disagrees with the reference detector. Class: `internal`.

**D-14 — Reachability census.** **Ruling:** recount with the complete root list (including drivers compiled directly by gates, e.g. `compiler/native_compile_driver.sio` via `epistemic_witness_gate.sh:35` and `epistemic_monotonicity_gate.sh:45`), then decide module by module from a table (module, lines, last commit, what it defines, whether it has tests): remove (preserved under an `archive/` tag), reconnect to an importer, or keep with a stated reason. Class: `internal`.

### Test infrastructure and CI

**D-11 — Engine-neutral `compile-fail` suite.** **Ruling:** assertions by neutral E-code where both engines agree; `//@ requires:` only for single-engine behaviour; the whole suite also runs with `SOUNIO_TEST_SOUC_BIN=bin/madaros-linux-x86_64`. Each divergence found is classified as an engine bug (fixed) or a legitimate difference (scoped). Class: `internal`.

**D-12 — Corpus regression gate.** The gate once stayed red for twelve days on a stale baseline (`witness_declares_its_sabotage_gate.sh:351`). **Ruling:** it runs in the nightly layer of [ADR-027](adr-027-layered-ci-graph-and-receipts.md); `tests/madaros_corpus_baseline.txt` is regenerated only by a job on `main`, never by hand; the #2354/#2355 crashers stay as baseline entries; a new regression against `main`'s baseline blocks the next merge until fixed or explicitly accepted. Class: `internal`.

**D-18 — Tuple-array return aliasing.** **Ruling:** closed as not reproducible; the probe `i1582b.sio` becomes a `run-pass` test on both engines with `bad=0`. Class: none.

### Compiler pipeline

**D-13 — The two `-O` pipelines.** `compile_multimodule_native`, `_advanced`, `_with_ir` (`module_loader.sio` and `module_native_driver.sio`) and `_maybe_streaming` (`module_loader.sio:1896` and `module_native_streaming.sio:167`) are each defined twice. **Ruling:** first remove the shadow copies (one symbol each, no behaviour change); then the multi-module path runs the full `-O` pipeline (inline, LICM, TCO), and any printed number that changes ships as `numerical-correction`. Class: `internal`, then `performance`.

**D-21 — SOIR magic and version collision.** **Ruling:** the legacy `ir/serialize.sio` gets a distinct magic (or version ≥ 0x80) now; its five users (`main.sio`, `compiler/main.sio`, `compiler/module_loader.sio`, `ir/verify.sio`, `ir/disasm.sio`) then migrate to the sectioned v6 format and the legacy serializer is removed, with the v5 shadow in `ir/soir_writer.sio` if it is left without users. Class: `fixed`, then `removed`.

**D-30 — Precise roots for the handle GC.** **Ruling:** implement now. Precise root maps in the live backend (`codegen_x86_linux.sio:247`, `precise_stack_maps` true with real maps) and `native_v2_emit_gc_empty_frame_reset` (`:3559`) wired into the active backend. ADR-026 covers the compiler; this covers user programs. Class: `fixed`.

### Language semantics

**D-02 — Opaque authority capabilities.** E259 already holds on both engines (#2927, 2026-10-14). **Ruling:** (1) `lean_single` enforces E039 for cross-module linear use; (2) dedicated capability types — attenuation, freshness/revocation, unforgeability by cast or serialization, enforced by the compiler on both engines — enter the 3.1 train, starting with a design proposal in `docs/proposals/` that states the acceptance test of each guarantee. Class: `refusal` (dev engine), then `added`.

**D-03 — Basis-support certificate `Q` (E251).** Already decided on 2026-09-01: option (b), support-refined `Knowledge` (∪ for `+`, XOR closure for `*`) with affine-support `Q` propagated through the types and lowering validation kept separate. Not implemented on `main` (`self-hosted/check/check.sio:9733` still emits E251 unconditionally). Class: `added`.

**D-17 — Payload enum variants.** Already decided on 2026-10-30: payload enums are in 3.0. Madaros closed non-generic enums on 2026-10-30 (KL-20); `lean_single` and generic enums remain and are tracked by KL-20. #645 closes as superseded. Class: `added`.

**D-19 — `Knowledge<T where {...}>`.** **Ruling:** option (c). The predicate is a proof obligation in the design of [ADR-016](adr-016-epistemic-merge-and-provenance-trust.md) §11 ("search outside, certificates inside"), evaluated over the certified enclosure of D-34. An obligation discharged by a certificate is a static guarantee with no run-time cost; a value known only at run time gets a compiler-inserted guard. E269 stays until this is implemented. Class: `added`.

**D-23 — `Knowledge ⊗ Knowledge` and NaN beyond the unrolling ceiling.** **Ruling:** (1) E245 is retired with the rules ADR-016 already fixes — provenance by the trust semiring product (§12), first-order GUM with exact correlation through shared provenance keys (§6), log domain when positivity is proven (§8–9); (2) recursion deeper than the unrolling ceiling is a compile-time error naming the function and the depth reached. NaN is never produced. Class: `added`; `refusal`.

**D-28 — Infix `!` and `~`.** **Ruling:** infix `!` is refused permanently. `~` gets a meaning: distributional declaration (`x ~ Normal(μ, σ)`), the reading the standard library already uses in comments. First step: a proposal in `docs/proposals/` that settles what `x` becomes in the type system (relation to `Knowledge<T>` and to the GUM Type A/B budget), declaration versus expression, the primitive distributions, and the interaction with provenance and with the certified enclosure. Until that proposal becomes an ADR, the current refusal stands. Class: `added` (future).

**D-31 — Reborrow aliasing through `&!` parameters.** **Ruling:** (a). `&(*p)` and `&!(*p)` count as borrows of `p`'s underlying place on both engines (E037/E038). The `&!Lowerer` migration (#3040) must pass under this rule. Class: `refusal`.

**D-32 — `spawn {}`, `.await`, `async fn`.** The specification (`docs/spec/2026-10/03-effects-handlers-and-concurrency.md` §6, ASYNC-001…005) shows that the `lean_single` `PASS` on `tests/run-pass/async_spawn.sio` is fake concurrency: `spawn { … }` runs as an ordinary block. **Ruling:** (1) now, both engines refuse with a diagnostic that names `spawn`/`.await`/`async fn`, and `async_spawn.sio` moves to `compile-fail`; (2) design: `Async` as an algebraic effect, with `spawn`/`await` as its operations and the scheduler as a handler, so functions have no colour. The proposal decides the fate of `ir/async_lower.sio` and `vm/green_threads.sio` and states the test that distinguishes real concurrency from inline evaluation. Class: `refusal`, then `added`.

**D-35 — `Mut` and local reassignment (new).** Raised by #2834. Per `docs/spec/S06_EFFECTS_ROWS.md` §6.1–6.6, no checker decision consults `Mut`, and 80 % of 57,752 signatures declare only `Mut`/`Div`/`Panic`/`Alloc`; `fn sin` in `stdlib/math/pure.sio` carries `with Mut` because of a loop. **Ruling:** reassigning a local `var` is not an effect. `Mut` means mutation observable outside the function (through `&!` or global state). This changes `lean_single` as well. The broader §6.6 question — separating observable effect from mechanism for `Div`/`Panic`/`Alloc` — stays open. The IO half of #2834 (`read_file`, `print`) is a bug of the same class as #2760 and is fixed through the builtin effect table. Class: `added` (accepts programs refused today). Train: 3.1.

**D-34 — Certified interval primitive.** Decided on 2026-10-24 and recorded in ADR-019 (PR #3101). Confirmed in this session: D2 separate `u` and `e`, with `e_to_typeB(…)` explicit and its assumed distribution recorded in provenance; D3 interval Jacobian by default, point Jacobian only via `assume_point`; D6 explicit interval FMA only; D10 compile-time refusal of a possibly-true `if`, with explicit `hull_branches`. **Change to D11:** AArch64 joins Marco 0, with `FPCR.RMode`/`FPCR.FZ` handled as an effect the way RVV's `frm` is (D7). ADR-019 must carry this change before #3101 merges.

### Research

**D-08 — Sedenion-brain Hessian null result.** **Ruling:** the hypothesis "ASD has more null directions than ADHD" is recorded as refuted (`Null dims = 0/16` in both groups on both engines, agreement to ≥ 6 significant figures). Trace and anisotropy (ASD trace `24.594517`, ADHD `−9.941127`) are not reported as findings of this experiment, because the metric was chosen after the data were seen. They become a new hypothesis, written and dated before it is run — metric, direction of effect, rejection criterion — and tested under an independent condition (other topology, seed or dataset).

## Acceptance

1. **D-01**: `#print axioms` on the headline theorems of the three files lists no axiom about `Float`.
2. **D-02**: `lin3.sio` gives E039 on both engines; the capability proposal exists with one test per guarantee.
3. **D-04**: an unknown library id is refused; `extern "C" from "libm.so.6" { fn cbrt }` produces `NEEDED libm.so.6`.

6. **D-07**: `stdlib/epistemic/state_aliasing_receipts.sio`, `stdlib/epistemic/parenthesization_receipts.sio` and `scripts/ci/epistemic_receipt_source_fresh_gate.sh` exist on `main` and pass on both engines.

10. **D-12**: the gate runs nightly against a baseline written only by `main`.

17. **D-29**: `artifacts/self-hosted/souc-self-hosted-arm64-macos` with a verified receipt.
18. **D-30**: a program keeping more than 2^22 handles live across escaping returns finishes without rc 182.

20. **D-32**: both engines refuse `async_spawn.sio` with a diagnostic naming the construct.
21. **D-35**: a helper that only reassigns a local `var` checks without `with Mut` on both engines; a helper that writes through `&!` without `with Mut` is refused on both.

## Consequences

- `PENDING.md` is empty after this ADR. New open decisions are added there in the same format.
- D-01, D-10 and D-29 make the trust story explicit: proofs never assume a model of `Float` they cannot justify, and every published seed carries a receipt.
- D-04, D-05, D-23, D-30 and D-32 remove places where the compiler produced a plausible answer instead of the true one: a wrong library, a wrong symbol, NaN, an unreclaimed heap, sequential code labelled concurrent.
- D-35 accepts programs that `lean_single` refuses today; D-02, D-31 and D-32 refuse programs that are accepted today.
