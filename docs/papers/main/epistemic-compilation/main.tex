\begin{abstract}
% ============================================================================
When a compiler is written in the language it compiles, the bootstrap stages
must tolerate partial knowledge: some types are known precisely, some are only
partially characterized, and some checks cannot yet be discharged.
Existing gradual typing, refinement typing, provenance-aware languages, and
uncertainty-aware systems each address parts of this problem, but they are
usually presented separately.

We introduce \emph{epistemic gradual compilation} (EGC), a compiler-oriented
synthesis in which types and intermediate values carry explicit confidence,
measurement uncertainty, and guarded admissibility.
Rather than treating uncertainty as a library concern, EGC makes it visible
to the compiler: low-confidence sites remain compilable under guards, while
high-confidence sites lower directly to ordinary machine code.

We implement EGC in \sounio, a self-hosted systems language with epistemic
values and confidence-aware checking, and evaluate it on the \lean compiler
source as a demanding case study.
Across self-hosted generations, confidence rises monotonically as inference
and checking rules are added; by Generation~11 all 8,883 call sites emit
direct code and all 75,924 tracked expression tokens exceed the direct-code
threshold.
Later generations add per-token confidence export, a separate
\textsc{MEAS\_CONF} measurement-quality channel, and mechanized checks for key
monotonicity and preservation properties.
Our claim is not that prior work lacked uncertainty, provenance, or gradual
adoption in isolation, but that bringing these ideas together at the
language/compiler boundary yields a practical path from partial knowledge to
self-hosted compilation.
\end{abstract}

\section{Introduction}
\label{sec:intro}
% ============================================================================

\subsection{The Bootstrapping Paradox}

Self-hosting a compiler is a rite of passage for programming languages.
When a language is mature enough to express its own compiler, the toolchain
becomes self-sustaining: the compiler compiles itself, and the fixed-point
test---\emph{does compilation produce a bit-identical binary across two
generations?}---provides a continuous regression guarantee stronger than
any unit test suite.

Type checkers complicate this picture.
A sufficiently rich type system---inference, polymorphism, dependent types---
cannot be fully applied to the compiler source until the type system itself
is implemented.
The standard engineering response is to write the compiler without the type
checker, then switch it on once the language is complete enough.
This is the \emph{bootstrapping paradox}: the very mechanism designed to
ensure program correctness is unavailable during the most critical phase
of development, when the compiler itself is being written.

Existing approaches resolve the paradox by making the unknown a special
case.
In gradual typing~\cite{siek2006gradual}, the dynamic type~$\mathord{?}$
acts as an escape hatch: anything typed~$?$ is consistent with everything
else, and casts are inserted at boundaries.
Gradual type systems are sound---they catch inconsistencies at runtime---
but binary: a type is either known or unknown.
For our target setting, there is no direct mechanism to express that a type is
\emph{mostly} known,
that confidence has been \emph{increasing}, or that 90\% of the compiler's
expressions are already fully typed while 10\% remain uncertain.

\subsection{Quantified Uncertainty as the Answer}

Measurement science has faced an analogous problem for decades.
The Guide to the Expression of Uncertainty in Measurement
(GUM)~\cite{jcgm2008gum} introduced a foundational distinction:
uncertainty is not binary.
A laboratory measurement does not simply \emph{know} or \emph{not know}
the value of a quantity---it assigns a probability distribution,
characterized by a best estimate and a standard uncertainty.
Multiple uncertain quantities combine by the law of propagation of
uncertainty: independent sources add in quadrature; serial dependencies
compound.

We apply the same principle to compilation.
Every type in \sounio carries a \emph{confidence} $c \in [0, 1000]$
and an \emph{uncertainty} $u \in [0, 1000]$, both on a fixed-point
integer scale.
A literal \texttt{42\,:\,i32} has confidence~1000 (fully known).
A forward reference to a struct field that has not yet been resolved
has confidence~0.
As inference rules fire---for variables, function calls, let-bindings,
parameters---confidence rises.
At the gate threshold of~950, the compiler emits direct machine code
with zero overhead.
Below the threshold, it emits a 2-byte NOP guard \texttt{66~90} that
marks the site for later enforcement.

This approach has a remarkable property we call the \emph{Patient Zero
test}: the compiler itself is an unusually demanding client of
the epistemic type system.
If the type system works, the compiler's own expressions should reach
high confidence as more inference rules are added.
If the system is wrong---if it assigns confidence to things it should
not, or fails to propagate---the compiler's own confidence numbers
will reveal the error.
The validator and the validated are the same artifact.

\subsection{Contributions}

This paper makes the following contributions:

\begin{enumerate}

\item \textbf{Epistemic gradual compilation} (\S\ref{sec:egc}): a type
  system extension in which every type carries GUM-compliant confidence
  and uncertainty values, replacing the binary known/unknown distinction
  of gradual typing with a quantified lattice.
  We define the GUM product rule for serial confidence composition and the
  RSS rule for uncertainty combination, and prove that confidence is
  monotone non-decreasing across inference passes.

\item \textbf{The bootstrapping protocol} (\S\ref{sec:bootstrap}):
  a 15-generation self-hosting experiment in which \lean (the \sounio
  self-hosted compiler, 16,700+ lines) applies its own epistemic engine
  to its own source.
  Confidence rises from 26\% at Generation~0 to 100\% at Generation~11,
  with bit-identical fixed points at every generation.
  Each generation adds exactly one category of inference rules,
  demonstrating monotone convergence toward full typing.
  Generation~11 closes the engine: all 75,924 expression tokens
  carry full confidence.
  Generation~12 adds observability: the Epistemic Inspector exports
  per-file confidence breakdowns, token-level JSON, and the first
  compile-time bridge to runtime \know{T} measurement uncertainty.
  Generation~13 adds the MEAS\_CONF dual channel, propagating GUM
  measurement quality through arithmetic independently of type-system certainty.
  Generation~14 adds four-tier confidence stratification, exposing the
  fine structure within the certainty threshold.

\item \textbf{Codegen gates} (\S\ref{sec:gates}): a practical
  mechanism that makes quantified uncertainty visible in the binary.
  High-confidence sites emit direct instructions; low-confidence
  sites emit 2-byte NOP guards.
  At Generation~11, 100\% of call sites and 100\% of expression tokens
  are direct; overhead reaches zero---the NOP guard never fires.

\item \textbf{Self-referential validation} (\S\ref{sec:selfref}):
  the Patient Zero test closes the validation loop.
  The epistemic engine's own confidence in its own types is the primary
  correctness signal.
  We show that the remaining 3\% of uncertain expressions are precisely
  the hardest cases---multi-level struct field chains, higher-kinded
  generics, recursive closures---that are documented as incomplete,
  confirming that confidence is a faithful proxy for type system
  completeness.

\end{enumerate}

\section{Background}
\label{sec:background}
% ============================================================================

\subsection{The GUM and Propagation of Uncertainty}

The Joint Committee for Guides in Metrology's \emph{Guide to the
Expression of Uncertainty in Measurement}~\cite{jcgm2008gum} (GUM)
is the international standard for quantifying and combining measurement
uncertainty.
Its central result---the law of propagation of uncertainty---states that
for a function $y = f(x_1, \ldots, x_N)$ of uncorrelated input quantities,
the combined standard uncertainty is:
\begin{equation}
u_c^2(y) = \sum_{i=1}^{N} \left(\frac{\partial f}{\partial x_i}\right)^2 u^2(x_i).
\label{eq:gum-lpu}
\end{equation}
This root-sum-of-squares (RSS) formula is exact for linear functions and
provides the standard first-order approximation for nonlinear ones.

The GUM also introduces the concept of \emph{degrees of freedom}
associated with an uncertainty estimate, characterizing how well the
uncertainty itself is known.
We adopt a simplified version: our \emph{confidence} $c \in [0, 1000]$
plays the role of the inverse of relative uncertainty---high confidence
means the type is well-characterized.

\subsection{Gradual Typing}

Gradual type systems~\cite{siek2006gradual} extend a static type system
with a distinguished dynamic type~$?$ that is \emph{consistent} with
every other type.
Consistency is a reflexive, symmetric but non-transitive relation:
$? \sim \tau$ and $\tau \sim ?$ for all~$\tau$, but $\tau_1 \sim \tau_2$
does not hold in general.
At compile time, casts are inserted at consistency boundaries;
these casts may fail at runtime.

The gradual guarantee~\cite{siek2015refined} requires that adding or
removing type annotations does not break a previously-passing program.
This is a soundness property for the $?$-to-known direction:
more annotations cannot introduce new failures.

EGC extends gradual typing in two ways.
First, confidence replaces the binary known/$?$ distinction with a
continuous lattice.
Second, confidence propagates following GUM rules rather than being
assigned statically.
The gradual guarantee holds: adding an inference rule can only raise
confidence, never lower it.

\subsection{Self-Hosting Compilers and the Fixed-Point Test}

A compiler is \emph{self-hosting} if it is written in the language it
compiles, and if it can reproduce itself: compiling the compiler source
with the compiler binary produces a new binary; compiling again produces
an identical binary.
This fixed-point test, attributed to Ken Thompson's
\emph{Reflections on Trusting Trust}~\cite{thompson1984trusting},
is the gold standard for self-hosting correctness.

Fixed-point tests are binary in existing compilers: either the binaries
match (fixed point) or they do not.
They offer no insight into \emph{how much} of the compiler is
correctly typed, or which constructs remain uncertain.
EGC adds a continuous dimension: the confidence percentage at each
generation measures progress toward full typing, independent of whether
the fixed-point test passes.

\section{Epistemic Gradual Types}
\label{sec:egc}
% ============================================================================

\subsection{Types and Confidence}

\sounio's epistemic type system augments every type with two fixed-point
integers, both in $[0, 1000]$:

\begin{itemize}
\item $\conf{\tau}$: the \emph{confidence} of type~$\tau$.
  A confidence of~1000 means the type has been fully inferred by static
  analysis.
  A confidence of~0 means the type is entirely unknown.
  Intermediate values arise from partial information: a struct field whose
  containing type is known (confidence~800) but whose own type is a
  forward reference not yet resolved (confidence~0) might yield composite
  confidence~400.

\item $\unc{\tau}$: the \emph{GUM uncertainty} of~$\tau$.
  This tracks how much the confidence estimate itself may vary,
  following GUM's treatment of uncertainty-in-uncertainty.
  For fully inferred types, $\unc{\tau} = 0$.
  For types inferred from ambiguous overloads or unresolved generics,
  $\unc{\tau}$ records the spread.
\end{itemize}

The type pool is represented as flat parallel arrays
\texttt{ETY\_KIND}, \texttt{ETY\_CONF}, \texttt{ETY\_UNC},
and \texttt{ETY\_HASH}, indexed by type ID.
This representation avoids heap allocation, which is critical during the
compiler's own bootstrap where the allocator may not yet be available.
Expression-level epistemic data lives in parallel arrays
\texttt{EXPR\_ETY}, \texttt{EXPR\_CONF}, and \texttt{EXPR\_GATE}.

\subsection{GUM Propagation Rules}

Confidence and uncertainty propagate through expressions following
two rules derived from the GUM.

\paragraph{Product rule (serial composition).}
When two type inferences are composed---the result type of a function
call depends on both the function type and the argument type---confidence
compounds multiplicatively:
\begin{equation}
\conf{A \to B}(e_1, e_2) = \frac{\conf{e_1} \times \conf{e_2}}{1000}
\label{eq:product}
\end{equation}
This corresponds to the GUM treatment of serial bottlenecks:
if either source is uncertain, the composed result is at most as
certain as the weaker source.
A function call \texttt{f(x)} where \texttt{f} is known (confidence~1000)
but \texttt{x}'s type is uncertain (confidence~700) yields result
confidence~700.

\paragraph{RSS rule (parallel composition).}
When two independent uncertainty estimates must be combined---for
example, the uncertainty of a binary operator applied to two independently
uncertain operands---uncertainties combine in root-sum-of-squares:
\begin{equation}
\unc{e_1 \oplus e_2} = \lfloor\sqrt{\unc{e_1}^2 + \unc{e_2}^2}\rfloor
\label{eq:rss}
\end{equation}
Integer square root suffices because uncertainties are already on a
coarse scale; the fixed-point representation avoids floating-point
non-determinism that would break the fixed-point test.

\subsection{The Gate Threshold}

The gate threshold $\theta = 950$ separates direct code emission from
guarded code emission.
This value is not a global constant (which would require BSS
initialization before the epistemic pass is ready) but is set at
function entry:

\begin{lstlisting}[language=sounio, caption={Gate threshold initialization}]
fn compile_expr(expr: i32) -> i32 {
  let GATE_THRESHOLD = 950  // set locally; BSS zeroes var inits
  let conf = EXPR_CONF[expr]
  if conf >= GATE_THRESHOLD {
    emit_direct(expr)        // zero overhead
  } else {
    emit_nop_guard(expr)     // 66 90: 2-byte NOP marker
  }
}
\end{lstlisting}

The 2-byte NOP \texttt{0x66~0x90} was chosen because it is a valid
x86-64 instruction (operand-size prefix + NOP), is patched to a
conditional trap by a runtime enforcement layer, and adds the minimum
footprint: two bytes per guarded site.

\subsection{The Epistemic Scope Stack}

Type inference proceeds through a scope stack that tracks variable
bindings with their epistemic types.
At block entry, the current scope is pushed; at block exit, it is popped.
Variable lookup yields both the type ID and its confidence.
If a variable is looked up before its binding is resolved---in a
forward reference within the same block---the lookup returns type ID~0
(unknown) with confidence~0.

The iterative refinement pass runs inside \texttt{compile\_all()} after
function registration but before codegen.
On each pass, every uncertain identifier is re-evaluated against the
current scope, global table, function signatures, struct fields,
and enum variants.
Identifiers that resolve gain confidence; those that remain unresolved
retain their current value.
Convergence is declared when a pass produces zero upgrades.
In practice, 3 passes suffice (5,317 upgrades on the \lean source),
and the fixed-point property guarantees that no upgrade can lower
a previously assigned confidence.

\subsection{Graded Modal Semantics}
\label{subsec:graded-modal}
% ============================================================================

The EGC confidence system has a natural interpretation as a graded modal
logic~\cite{Fairtlough1997}.
We define the \emph{graded modality} $\square_c\,\tau$ as the type $\tau$ with
confidence bound $c \in [0, 1000]$.
Four rules govern this modality:

\paragraph{Introduction.}
$\vdash e : \square_{1000}\,\tau$ whenever $e$ is an axiom (literal,
constant, or machine-verified value).

\paragraph{Weakening.}
$\square_{c_1}\,\tau \sqsubseteq \square_{c_2}\,\tau$ whenever $c_2 \leq c_1$.
More certain types are subtypes of less certain ones.

\paragraph{Application (GUM product).}
$\square_{c_1}(\tau_1 \to \tau_2)$ applied to $\square_{c_2}\,\tau_1$ yields
$\square_{\lfloor c_1 c_2 / 1000 \rfloor}\,\tau_2$.
The result confidence is at most $\min(c_1, c_2)$, with equality when both
sources are maximally certain.

\paragraph{Transitivity.}
If $\square_{c_1}\,\tau \sqsubseteq \square_{c_2}\,\tau$ and
$\square_{c_2}\,\tau \sqsubseteq \square_{c_3}\,\tau$, then
$\square_{c_1}\,\tau \sqsubseteq \square_{c_3}\,\tau$.

\noindent
Together these four rules make $(\square_c)_{c \in [0,1000]}$ a
\emph{sound graded type system}: the confidence ordering is a preorder,
weakening is admissible, and the product rule is monotone with respect to
the subtyping relation.
This is proved in \texttt{docs/proofs/graded\_modal.lean} (Gen~17), which
formalises the \texttt{egc\_graded\_soundness} theorem in Lean~4.

\paragraph{Knightian uncertainty (Gen~17 D1).}
Beyond the point estimate $c$, each token carries a
\emph{belief/plausibility interval} $[\beta, \pi]$ with $\beta \leq c \leq \pi$.
The gap $\pi - \beta$ quantifies Dempster--Shafer ``known unknowns'':
\begin{itemize}
  \item \texttt{measured()} sites: $\beta = 985$, $\pi = 995$ (gap = 10).
  \item \texttt{asserted()} sites: $\beta = 960$, $\pi = 980$ (gap = 20).
  \item Certain sites (literals, globals): $\beta = \pi = c$ (gap = 0).
\end{itemize}
The invariant $\beta \leq c \leq \pi$ is proved by the
\texttt{belief\_le\_conf\_le\_plaus} theorem in
\texttt{meas\_conf\_soundness.lean}.

\paragraph{Knowledge\textless T\textgreater{} subtyping (Gen~17 D3).}
First-class epistemic types \texttt{Knowledge<T,} $c$\texttt{>} are assigned
ETY kind~7 in the type pool.
Subtyping is covariant in confidence:
\texttt{Knowledge<T, $c_1$>} $\sqsubseteq$ \texttt{Knowledge<T, $c_2$>} iff
$c_1 \geq c_2$.
Unification takes the more conservative (lower) confidence.
The knowledge subtype check is formalized in \texttt{graded\_modal.lean} as
\texttt{knowledge\_subtype\_ok}.

\paragraph{Patient Zero --- modal form.}
The self-compilation fixed point (Gen~17: sha256(\texttt{gen17.elf}) =
sha256(\texttt{gen17b.elf})) instantiates the
\texttt{patient\_zero\_modal} theorem:
if the compiler achieves $\square_{1000}$ on all its own tokens, it is
epistemically complete.
The PLATINUM\,=\,100\% certificate (all 77\,366+ tokens at confidence~1000)
witnesses the antecedent; the theorem then concludes.

\section{The Bootstrapping Protocol}
\label{sec:bootstrap}
% ============================================================================

\subsection{Setup}

\lean is the self-hosted \sounio compiler: a single-file Sounio program
of 16,365 lines implementing the full pipeline from source text to x86-64
ELF binary.
The epistemic engine adds 737 lines (4.5\% of the total) and is
architecturally independent of codegen, allowing it to be toggled without
changing any emitted instructions.

The bootstrap chain is:
\[
\texttt{boot4.elf} \;\xrightarrow{\text{compile}}\; \texttt{gen1.elf}
  \;\xrightarrow{\text{compile}}\; \texttt{gen2.elf}
  \;\xrightarrow{\text{compile}}\; \texttt{gen3.elf}
\]
Fixed-point test: $\mathrm{md5}(\texttt{gen2.elf}) = \mathrm{md5}(\texttt{gen3.elf})$.
This must hold at every generation.

\end{enumerate}

\section{Codegen Gates}
\label{sec:gates}
% ============================================================================

\subsection{Mechanism}

At every call site, the compiler evaluates $\conf{e} \geq \theta$ at
compile time.
If the test passes, direct machine code is emitted: the call instruction,
operand, and return value are placed without modification.
If the test fails, a 2-byte NOP guard \texttt{0x66~0x90} precedes the
instruction sequence.
The guard serves three purposes:

\begin{enumerate}
\item \textbf{Tagging}: the 2-byte sequence is not produced by the
  optimizer for any other reason, so a post-hoc scanner can enumerate
  all guarded sites.
\item \textbf{Patching}: a runtime enforcement layer can overwrite the
  NOP with a conditional branch to a trap handler.
  The branch target is stored in a side table indexed by program counter,
  constructed during compilation.
\item \textbf{Measurement}: counting NOP guards at each generation gives
  the fraction of uncertain code, enabling the convergence table.
\end{enumerate}

\subsection{The R15 Runtime Tag Stack}
\label{sec:r15}

Generation~11 introduces an opt-in runtime confidence monitor via
the \texttt{--r15-monitor} compilation flag.
At every call site, the compiler emits a three-instruction check:

\begin{verbatim}
cmp  qword [r15 + gate_id*8], 950   ; compare side-table entry
jge  .ok                            ; skip if confident
ud2                                 ; UD2: SIGILL epistemic trap
.ok:
\end{verbatim}

\noindent
\texttt{r15} is loaded at program start (\texttt{\_start}) with the
absolute address of a BSS side table of \texttt{i64} entries, one per
call site.
The trampoline initialises all entries to~1000 via a short loop before
calling \texttt{main}.
Each entry is independently writable at runtime, enabling a host
process, debugger, or measurement harness to downgrade the confidence of
specific sites and trigger the trap for testing or dynamic recalibration.

At Generation~11, all 8,921 instrumented sites start with entry~$=1000$;
the trap branch is provably dead code (static confidence 1000 $\geq$ 950).
The compiled binary runs normally without triggering any SIGILL.
Fixed-point hash of the instrumented binary: \texttt{a1497f5d}.

\paragraph{Usage.}
\begin{verbatim}
souc source.sio output.elf --r15-monitor
# Output: r15_monitor: 8921 sites instrumented,
#         side_table_size=71368 bytes
\end{verbatim}

\paragraph{Design properties.}
\begin{itemize}
\item \emph{Zero overhead without flag}: the flag is opt-in;
  without it, the NOP2 / direct path is unchanged.
\item \emph{Per-site granularity}: each of the 8,921 call sites
  has an independent 8-byte entry; the side table is 70\,KB.
\item \emph{Dead-branch elimination}: at Gen~11 static confidence,
  a simple optimizer can prove all trap branches unreachable and
  eliminate them, recovering the direct-call baseline.
\item \emph{Forward compatibility}: when a future dynamic measurement
  system (e.g., Bayesian update from profiling) lowers a site's confidence
  below 950, the trap fires at the next call, providing hard enforcement
  of epistemic guarantees at runtime.
\end{itemize}

\subsection{Generation~12: The Epistemic Inspector}
\label{sec:gen12}
% ============================================================================

Generation~12 extends EGC from a \emph{compile-time analysis} into an
\emph{observable system}, adding three capabilities that together form
the \emph{Epistemic Inspector}.

\paragraph{Per-file confidence breakdown.}
When a program imports external modules, the global token count conflates
user code with stdlib tokens.
Generation~12 tracks which tokens originate from the main source file
(identified by their source position relative to \texttt{MAIN\_SRC\_END})
and emits a separate \texttt{epistemic\_main:} line:
\begin{verbatim}
epistemic:      76,417 expr, 76,417 certain (100%), 0 uncertain
epistemic_main: 75,514 expr, 75,514 certain (100%), 0 uncertain
\end{verbatim}
This separates the user's certainty guarantee from the standard library's.

\paragraph{Token-level JSON export (\texttt{--dump-conf-json}).}
The new flag \texttt{--dump-conf-json} emits a JSON array of every
expression token's position, token kind, confidence value, and source line:
\begin{verbatim}
{"total":1359, "certain":1359,
 "tokens":[{"p":1,"tk":3,"conf":1000,"line":24}, ...]}
\end{verbatim}
Applied to \texttt{pbpk\_2comp.sio} this produces 1,359 entries, all with
\texttt{"conf":1000}, confirming 100\% expression certainty at the
token level.
The JSON output is a foundation for editor tooling and the epistemic LSP
described in §\ref{sec:selfref}.

\paragraph{Knowledge\textless T\textgreater{} constructor bridge.}
Generation~12 introduces a direct connection between the compile-time
confidence lattice and the runtime \texttt{Epistemic} type in \texttt{stdlib/epistemic/}.
Functions named \texttt{measured} and \texttt{asserted} receive reduced
\texttt{FN\_EFF\_CONF} values (990 and 970 respectively) instead of the
default 1000, reflecting their semantic epistemic quality:
a \emph{measured} value carries instrument uncertainty; an \emph{asserted}
value carries user-claim uncertainty.
With literal arguments at confidence 1000, call sites produce
$\texttt{call\_conf} = 990$ and $970$ respectively --- both above the gate
threshold of 950, so zero guarded sites are introduced.

The compiler reports Knowledge\textless T\textgreater{} site statistics separately:
\begin{verbatim}
epistemic_ktype: 7 Knowledge<T> sites, 7 certain (100%)
\end{verbatim}
demonstrating that the compile-time epistemic analysis is now
\emph{semantically aware} of measurement vs.\ constant vs.\ asserted values,
bridging ISO~GUM measurement quality to the type-system confidence lattice.

The demo program \texttt{examples/science/epistemic\_measured.sio} instantiates
this bridge: $\texttt{dose} = \text{measured}(100, 5)$ carries
$\texttt{EXPR\_CONF} = 990$ and $\texttt{volume} = \text{measured}(10, 0.3)$
carries $\texttt{EXPR\_CONF} = 990$; the GUM product rule yields
$\sigma_{C_0} / C_0 = 5.9\%$, matching the analytical result.

\subsection{Generation~13: The MEAS\_CONF Dual Channel}
\label{sec:gen13}
% ============================================================================

Generation~12's Knowledge\textless T\textgreater{} bridge assigns a single confidence to
each call site, conflating \emph{type-system certainty} with \emph{GUM
measurement quality}.
Generation~13 separates these concerns with a parallel \texttt{MEAS\_CONF[262144]}
array---an independent confidence channel tracking the measurement provenance of
every expression token.

\paragraph{Channel semantics.}
\texttt{MEAS\_CONF[p]} records the GUM quality of the value computed at token~$p$:
\begin{itemize}
  \item $990$: token originated from a \texttt{measured()} call (Type~A, instrument data)
  \item $970$: token originated from an \texttt{asserted()} call (Type~B, literature value)
  \item $1000$: token originated from a \texttt{constant()} call (exact physical constant)
  \item $0$: not in the measurement channel (ordinary typed computation)
\end{itemize}
These values are independent of \texttt{EXPR\_CONF}: a token may have
$\texttt{EXPR\_CONF} = 1000$ (type-certain) and $\texttt{MEAS\_CONF} = 990$
(instrument-measured).

\paragraph{Propagation: GUM min-rule in Sweep~2.}
Arithmetic operators inherit the minimum non-zero \texttt{MEAS\_CONF} of their
operands, implementing the ISO GUM rule that combined uncertainty is dominated
by the least-certain input:
\[
  \texttt{MEAS\_CONF}[p_{\textit{op}}] =
    \min_{\neq 0}\!\bigl(\texttt{MEAS\_CONF}[p_{\textit{left}}],\;
                          \texttt{MEAS\_CONF}[p_{\textit{right}}]\bigr)
\]
This propagates measurement provenance through an entire computation graph.
For the expression $C_0 = \text{dose} / V_1$ where both operands were
\texttt{measured} (MEAS\_CONF = 990), the operator inherits MEAS\_CONF = 990,
correctly signalling that the initial concentration is instrument-derived.
When a \texttt{measured} variable is multiplied by an \texttt{asserted}
rate constant (MEAS\_CONF = 970), the result carries MEAS\_CONF = 970,
reflecting literature-quality heritage.

\paragraph{Dual-channel ESCOPE.}
The epistemic scope stack gains a parallel \texttt{ESCOPE\_MEAS[16384]} array.
When a binding is created from a \texttt{measured()} call, the variable's
ESCOPE entry carries both its EXPR\_CONF (type certainty) and MEAS\_CONF
(measurement quality).
Subsequent reads of that variable propagate both channels simultaneously.

\paragraph{Diagnostic output.}
A new \texttt{epistemic\_meas:} line reports how many tokens participate
in the measurement channel:
\begin{verbatim}
epistemic_meas: 63 tokens in measurement channel (meas_conf > 0)
\end{verbatim}
The \texttt{--dump-conf-json} output gains a \texttt{"meas"} field per token,
enabling tooling to trace measurement provenance token-by-token.

\paragraph{Darwin Epistemic PBPK benchmark.}
The file \texttt{examples/science/darwin\_epistemic\_pbpk.sio} demonstrates
the dual channel on a pharmacokinetic simulation:
instrument-measured physiological volumes ($V_1, V_2$, dose) carry
MEAS\_CONF $= 990$, while literature transfer rates ($k_{12}, k_{21}$) carry
MEAS\_CONF $= 970$.
The combined RSU for $C_0 = \text{dose}/V_1$ is computed analytically as
$3.6\%$ (GUM product rule), and the compiler assigns MEAS\_CONF $= 990$ to
$C_0$ via the min-rule---matching the GUM derivation.
A population of five virtual patients (varying elimination rate constants
$k_e \in \{0.10, 0.15, 0.20, 0.25, 0.30\}\;\text{hr}^{-1}$) all achieve
$|\text{RK4} - \text{analytical}| < 10^{-3}$ mg/L.
The Gen~13 compiler reports: 1761 expr, 1761 certain (100\%), 63 measurement-channel tokens.

Fixed-point: \texttt{b7371af0} (Gen~13 compiled by Gen~13 $=$ Gen~13).

\subsection{Generation~14: Confidence Tier Distribution}
\label{sec:gen14}
% ============================================================================

At 100\% expression certainty, every token exceeds the gate threshold.
But the confidence lattice $[0, 1000]$ contains fine structure within that
100\%: some tokens carry confidence exactly $1000$ (PLATINUM), while others
carry $999$ or $998$ (GOLD) due to the type-unification formula
$(c_a^2 + c_b^2)/(c_a + c_b + 1)$.
Even two PLATINUM inputs ($c = 1000$) yield a Gold output
($\lfloor 2{,}000{,}000 / 2001 \rfloor = 999$) when unified, reflecting
that type unification introduces microscopic epistemic noise analogous to
combining two measurements.

Generation~14 makes this structure explicit with four tiers:
\begin{description}
  \item[PLATINUM] ($c = 1000$): Maximally certain---literal constants,
    direct resolutions with no unification.
  \item[GOLD] ($c \in [950, 999]$): Type-certain (above gate threshold)
    but carrying unification noise or Knowledge\textless T\textgreater{} heritage.
  \item[SILVER] ($c \in [800, 950)$): Below gate threshold---emits
    runtime guards; not seen in Generation~14.
  \item[BRONZE] ($c \in [500, 800)$): Low confidence; not seen in Generation~14.
\end{description}

The compiler emits a \texttt{tier\_dist:} diagnostic line after each compile:
\begin{verbatim}
tier_dist: PLATINUM=56785 GOLD=19925 SILVER=0 BRONZE=0 [PLATINUM%=74%]
\end{verbatim}
On the Gen~14 self-compile, 74\% of tokens are PLATINUM and 26\% are GOLD.
The GOLD tokens are \emph{structurally explained}: they are precisely the tokens
produced by the confidence-squared unification formula $\lfloor(c_a^2+c_b^2)/(c_a+c_b+1)\rfloor$
when unifying two PLATINUM types. This is not measurement uncertainty but
\emph{representational precision}---the lattice distinguishes exact certainty
from near-certainty even within the 100\% threshold band.

A root-cause analysis reveals that \texttt{measured()} and \texttt{asserted()}
call sites report EXPR\_CONF $= 1000$ rather than 990 or 970.
The reason is structural: \texttt{ety\_from\_tnk} maps struct return types to
the \emph{unknown} type (kind~0), which causes Phase~B to zero the call
confidence; Phase~D then restores it to 1000 by the function-name lookup path.
The MEAS\_CONF dual-channel was designed precisely to carry measurement quality
in this case---MEAS\_CONF correctly records 990 and 970 at these sites even
when EXPR\_CONF cannot.

Fixed-point: \texttt{ef225205} (Gen~14 compiled by Gen~14 $=$ Gen~14).

\subsection{Generation~15: PLATINUM Ceiling Fix and Cross-Module Certificates}
\label{sec:gen15}
% - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - -

Generation~15 addresses the one remaining source of GOLD tokens in the
self-compile and introduces cross-module epistemic certificates.

\paragraph{PLATINUM ceiling (Gen~15~A).}
The unification formula $\lfloor(c_a^2+c_b^2)/(c_a+c_b+1)\rfloor = 999$
when $c_a = c_b = 1000$ introduces representational noise with no
epistemic justification: if both operands are maximally certain, the
result must be maximally certain.
Generation~15 adds the special case to \texttt{ety\_unify}:
\begin{verbatim}
if conf_a == 1000 && conf_b == 1000 {
    EUNIFY_CONF = 1000; return ty_a }
\end{verbatim}
This eliminates all 19,925 GOLD tokens on the self-compile.
After Gen~15, the self-compile tier distribution is:
\begin{verbatim}
tier_dist: PLATINUM=77147 GOLD=0 SILVER=0 BRONZE=0 [PLATINUM%=100%]
\end{verbatim}
Every tracked expression token is PLATINUM.

\paragraph{Cross-module certificates (Gen~15~B).}
The \texttt{.econf} protocol enables epistemic certainty to cross module
boundaries.
After compiling a library, the developer captures a certificate:
\begin{verbatim}
gen15.elf stdlib/epistemic.sio out.elf --emit-econf > epistemic.econf
\end{verbatim}
The certificate lists each function's \texttt{FN\_EFF\_CONF} value:
\begin{verbatim}
econf_begin
fn measured 990
fn asserted 970
fn constant 1000
...
econf_end
\end{verbatim}
When compiling a downstream program, the certificate is loaded in
Phase~A3, overriding \texttt{FN\_EFF\_CONF} before Phase~B runs:
\begin{verbatim}
gen15.elf program.sio out.elf --load-econf epistemic.econf
\end{verbatim}
The diagnostic confirms application:
\texttt{econf\_load: 25 FN\_EFF\_CONF overrides applied from certificate}.
This is the foundation for cross-module epistemic gradual compilation:
each compiled module ships an \texttt{.econf} alongside its \texttt{.elf},
enabling downstream compilers to inherit verified function confidences
rather than falling back to the default \texttt{FN\_EFF\_CONF = 1000}.

\paragraph{Machine-checked soundness (Gen~15~C).}
The three core properties of the Gen~13--15 epistemic system are proved
in Lean~4 (\texttt{docs/proofs/meas\_conf\_soundness.lean}):
\begin{enumerate}
  \item \textbf{MEAS\_CONF soundness}: the GUM min-rule is conservative---
        $\texttt{meas\_propagate}(m_1, m_2) \leq m_1$ and $\leq m_2$
        (Theorem~\texttt{meas\_conf\_soundness}).
  \item \textbf{PLATINUM preservation}: $\texttt{unify\_conf\_gen15}(1000, 1000) = 1000$
        (Theorem~\texttt{gen15\_platinum\_preservation}).
  \item \textbf{Monotonicity}: $\texttt{conf\_product}$ is non-decreasing in both
        arguments (Theorem~\texttt{conf\_product\_monotone}).
\end{enumerate}
The proofs are constructive and machine-checked; no axioms beyond Lean~4's
standard library are assumed.

Fixed-point: \texttt{cf421598} (Gen~15 compiled by Gen~15 $=$ Gen~15).

\subsection{Generation~16: Struct EXPR\_CONF Dual-Channel and EpistemicComplete Effect}
\label{sec:gen16}
% - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - -

Generation~16 resolves the last root-cause gap in the EGC type system
and introduces three new capabilities: dual-channel confirmation at
struct-returning call sites, a compiler-enforced \texttt{EpistemicComplete}
algebraic effect, and two domain-specific epistemic demonstrations
(population PBPK and quantum VQE).

\paragraph{Struct EXPR\_CONF gap (Gen~16~Track~A).}
In Gen~13--15, calling a struct-returning function such as \texttt{measured()}
produced \texttt{EXPR\_CONF=1000} (PLATINUM) at the call site---not the
correct \texttt{990} (GOLD) that \texttt{FN\_EFF\_CONF[measured]=990} would
suggest.
The root cause was a three-step failure cascade:
\begin{enumerate}
  \item \texttt{ety\_from\_tnk(6)=0} (kind~6 = struct not mapped) returned
        the \emph{unknown} type;
  \item Phase~B's guard \texttt{if ret\_ety == 0 \{ call\_conf = 0 \}}
        zeroed the call confidence;
  \item Phase~D's refinement loop restored \texttt{EXPR\_CONF=1000}
        (hardcoded) regardless of \texttt{FN\_EFF\_CONF}.
\end{enumerate}
Gen~16 applies three targeted fixes:
\begin{verbatim}
// A1: new canonical struct type (kind=6)
fn ety_mk_struct() -> i64 with Mut { return ety_alloc(6, 1000, 0) }

// A2: recognize struct/enum in ety_from_tnk
if tnk == 6 { return 6 }   // struct
if tnk == 7 { return 6 }   // enum -> same pool slot

// A3: Phase D uses actual effect confidence
EXPR_CONF[p] = FN_EFF_CONF[rfj]  // was: 1000
\end{verbatim}
After these fixes, \texttt{measured(100.0, 4.0)} produces
\texttt{EXPR\_CONF=990} (GOLD) at its call site---confirming the
measurement-quality epistemic tag through both channels simultaneously:
\texttt{MEAS\_CONF[p]=990} (Gen~13 dual-channel) \emph{and}
\texttt{EXPR\_CONF[p]=990} (Gen~16 type-system channel).
The self-compile remains 100\% PLATINUM (no struct-returning calls in
the compiler itself); the \texttt{darwin\_epistemic\_pbpk.sio} benchmark
shows:
\begin{verbatim}
tier_dist: PLATINUM=1679  GOLD=82  [PLATINUM%=95%]
\end{verbatim}
The 82~GOLD tokens are precisely the \texttt{measured()}/\texttt{asserted()}
call sites.

\paragraph{EpistemicComplete as algebraic effect (Gen~16~Track~B).}
A function declared \texttt{fn f() -> T with Epistemic} now carries a
compiler-enforced guarantee: every expression token in its body must have
\texttt{EXPR\_CONF $\geq$ GATE\_THRESHOLD = 950}.
Any violation triggers a compile error before code generation:
\begin{verbatim}
error: EpistemicComplete violation in fn f:
       uncertain token at pos 412 (conf=0 < 950)
\end{verbatim}
Implementation: after Phase~D's iterative refinement and both
post-refinement sweeps, a body-scan loop iterates over all functions
with \texttt{FN\_EFFECTS[fi] \& 512 $\neq$ 0} (the \texttt{Epistemic}
bit), walks their token ranges tracking brace depth, and flags any
expression token with $0 < \texttt{EXPR\_CONF} < \texttt{GATE\_THRESHOLD}$.
If any violations are found, \texttt{EPIST\_EFFECT\_VIOLATIONS > 0} causes
\texttt{return 1} before the codegen pass.
This makes epistemic completeness a \emph{checkable contract} rather than
a post-hoc diagnostic.

\paragraph{Population PBPK confidence budget (Gen~16~Track~C).}
The new example \texttt{examples/science/darwin\_pop\_confidence\_budget.sio}
simulates $N=100$ virtual patients with
$k_\text{elim} \sim \text{LogNormal}(\mu=0.20\,\text{hr}^{-1},\,\sigma_\ln=0.30)$
using an inline LCG RNG and a 12-uniform CLT normal approximation.
For each patient, the RK4 solution (dt=0.001, 24000 steps) is compared
to the analytical 2-compartment solution; the population confidence
budget is \texttt{n\_pass/100} (tolerance $|\text{RK4}-\text{analytical}|<0.001$\,mg/L).
The benchmark demonstrates MEAS\_CONF epistemic provenance tracking across
a population:
\begin{verbatim}
tier_dist: PLATINUM=1694  GOLD=24  [PLATINUM%=98%]
Population confidence budget: 100/100 (100%) within tolerance
DARWIN POP CONFIDENCE BUDGET PASSED
\end{verbatim}

\paragraph{Quantum VQE epistemic types (Gen~16~Track~D).}
The example \texttt{examples/epistemic\_quantum\_vqe.sio} implements a
1-qubit Variational Quantum Eigensolver with Hamiltonian $H=Z$, ansatz
$|\psi(\theta)\rangle = R_Y(\theta)|0\rangle$, and energy
$E(\theta) = \langle Z\rangle = \cos(\theta)$.
A 30-point grid search finds the minimum at $\theta = -\pi$,
$E_\text{min} = -1.0$.
The MEAS\_CONF bridge wraps quantum measurement outcomes in
\texttt{measured()} (MEAS\_CONF=990) and VQE optimizer parameters in
\texttt{asserted()} (MEAS\_CONF=970), demonstrating that EGC's epistemic
infrastructure applies directly to quantum computing contexts:
\begin{verbatim}
tier_dist: PLATINUM=1475  GOLD=13  [PLATINUM%=98%]
Ground state energy: -1.000000 Ha
QUANTUM VQE PASSED
\end{verbatim}

Fixed-point: \texttt{f136bdfb} (Gen~16 compiled by Gen~16 $=$ Gen~16).
Self-compile: PLATINUM=77,366/77,366 (100\%, +219 tokens from Gen~15).

\subsection{The Patient Zero Test}

An epistemic type system that assigns \emph{wrong} confidence---
reporting high confidence for types it has not actually inferred---
would be worse than no type system at all.
It would mask errors rather than expose them.

The Patient Zero test provides an empirical check against this failure mode.
\lean is the first and most demanding client of its own epistemic engine:
it is a 16,365-line program that uses every feature of \sounio including
the advanced constructs (generics, closures, struct arrays) that the engine
handles progressively across generations.
At each generation, the validation check is: do guarded sites correspond
to \emph{known incomplete} constructs?

Table~\ref{tab:guarded-breakdown} shows the construct breakdown at
Generation~6 (679 sites), Generation~9 (54 sites), and Generation~10 (0 sites).

\begin{table}[h]
\centering
\small

\toprule
Construct & Gen~6 & Gen~9 & Gen~10 & Resolution at Gen~10 \\
\midrule
Struct field access   & 412 & 14 &  0 & Subsumed by generic call recognition \\
Generic instantiation & 189 & 26 &  0 & \texttt{IDENT\textless T\textgreater()} pattern in Phase~D \\
Closure capture       &  78 & 14 &  0 & Resolved via escope refinement cascade \\
\midrule
Total                 & 679 & 54 &  0 & \\
\bottomrule
\end{tabular}
\caption{%
  Guarded sites by construct at Generation~6, Generation~9, and Generation~10.

}
\label{tab:guarded-breakdown}

The match is exact at every generation.
At Generation~9, every guarded site corresponded to a construct the engine
explicitly did not model: multi-level field chains, higher-kinded generics,
and recursive closures.
Generation~10's inference rule for the \texttt{IDENT\textless T\textgreater()}
pattern resolves all three categories simultaneously, because once the generic
call confidence is propagated through Phase~D, the cascading escope refinement
loop in the same pass upgrades the downstream struct and closure references too.
The result is $\text{guarded} = 0$: no site in \lean remains uncertain.
This confirms that confidence values are \emph{faithful} across all ten
generations: the engine neither hallucinated certainty nor missed a site.

\subsection{The Self-Reference Loop}

Figure~\ref{fig:loop} illustrates the epistemic self-reference.
The compiler source $S$ is processed by the epistemic engine $E$.
$E$ produces confidence annotations on $S$; these annotations are used
by codegen to emit direct or guarded instructions.
The resulting binary compiles $S$ again, producing the same annotations
(by the fixed-point property) and the same binary (by the fixed-point
test).
The loop is closed: $E$ validates $S$, and $S$ implements $E$.

\subsection{Code Size}

At Generation~10, zero guarded sites contribute zero bytes of guard overhead
to the 837\,KB binary (0.000\%).

5,432~bytes at Generation~6 (8 bytes per site $\times$ 679 sites) and
432~bytes at Generation~9, adds zero bytes at Generation~10.

\section{Related Work}
\label{sec:related}
% ============================================================================

\paragraph{Gradual typing.}
Siek and Taha~\cite{siek2006gradual} introduced gradual typing and the
consistency relation.
The refined criteria~\cite{siek2015refined} established the gradual
guarantee as the essential soundness property.
Recent work has strengthened the reusable meta-theory and direct operational
semantics available for gradual languages~\cite{siek2021parameterized,ye2024tdos}.
Castagna and Lanvin~\cite{castagna2017gradual} extended gradual typing
to set-theoretic types.
Our use of gradual ideas is narrower than a new general-purpose cast calculus:
we reuse partial precision and guarded boundaries, then attach graded
confidence and compiler-facing lowering decisions to those boundaries.

\paragraph{Refinement and liquid types.}
Refinement typing and liquid typing show how SMT-backed predicates can
eliminate runtime checks and prove value-level invariants
statically~\cite{rondon2008liquid}.
This is directly relevant to Sounio's confidence thresholds and safety gates.
However, refinement predicates are not the primary carrier of epistemic
meaning in our design.
Instead, they serve as a supporting proof mechanism for a language whose
surface semantics already distinguishes knowledge, confidence, and
admissibility.

\paragraph{Probabilistic and uncertain types.}
Bornholt et al.~\cite{bornholt2014uncertain} introduced \texttt{uncertain$\langle T \rangle$}
for tracking sensing uncertainty through computation.
Van de Meent et al.~\cite{vandemeent2021pp} survey probabilistic programming
as a language design centered on distributions and inference.
Mardziel et al.~\cite{mardziel2011knowledge} developed knowledge-oriented
type systems for probabilistic programs.
These systems are close neighbors, but their primary semantic object is
typically a distribution, a random variable, or a security/knowledge policy.
Our emphasis is different: typed knowledge state, provenance, and guarded
compilation in otherwise ordinary compiled programs.

\paragraph{Provenance as a language feature.}
Fehrenbach and Cheney~\cite{fehrenbach2018lip} show that provenance can be
integrated into a language and type system rather than treated as an external
database concern.
That result is an important precedent for Sounio.
The difference is scope: language-integrated provenance is query- and
derivation-oriented, whereas Sounio uses provenance alongside confidence and
observation to characterize ordinary compiled values and compile-time gates.

\paragraph{Uncertainty in scientific computing.}
Python's \texttt{uncertainties}~\cite{lebigot2024uncertainties} and
Julia's \texttt{Measurements.jl}~\cite{giordano2016measurements} provide
operator-overloaded uncertainty arithmetic.
These are libraries: they incur runtime overhead and provide no static
guarantees.
Our approach moves uncertainty handling into the language/compiler contract,
where it can interact with type checking, refinements, and code generation.

\paragraph{Self-hosting compilers.}
The fixed-point test traces to Thompson~\cite{thompson1984trusting}.
Self-hosting has been demonstrated for GCC, Rust, Go, and many others.
We use self-hosting as a demanding stress case for epistemic compilation,
not as a claim that self-hosting itself is novel.
The closest analogy is that Rust applies its own safety disciplines to the
compiler source, but without graded confidence or measurement-aware semantics.

\paragraph{Measurement uncertainty in software.}
ISO/IEC~17025~\cite{iso17025} and the GUM~\cite{jcgm2008gum} provide
the metrology foundations.
Wagner~\cite{wagner2022uncertainty} surveys uncertainty propagation
in scientific software.
Our contribution is to treat GUM-style propagation as part of the language and
compiler contract rather than solely as a library convention.

\section{Conclusion}
\label{sec:conclusion}
% ============================================================================

We have introduced epistemic gradual compilation, a framework in which
every type carries GUM-quantified confidence and the boundary between
fully-typed and dynamically-typed code is expressed on a continuous
$[0, 1000]$ scale rather than binary known/unknown.
The gate threshold $\theta = 950$ translates confidence into a
compilation decision: high-confidence types emit direct code;
uncertain types emit 2-byte guard markers.

The self-hosting experiment on \lean---the \sounio compiler---demonstrates
the framework's feasibility at scale.
Ten generations of bootstrap achieve 98\% expression certainty and
100\% call-site certainty, rising from 26\% at the start, with
bit-identical fixed points throughout.
Each generation adds exactly one inference rule family:
literals, variables, function calls, let-propagation, parameters,
casts, keywords, struct fields, generics, closures, and generic
call recognition.
At Generation~10, $\text{guarded} = 0$: the 2-byte NOP guard never fires.
The Patient Zero test closes the validation loop: the epistemic system
validates the source that implements it, and its confidence of 100\%
at the call-site boundary is the measure of its completeness.

Two directions remain open.
First, the R15 tag stack design (\S\ref{sec:gates}) will enable full
runtime enforcement at any future regression point, catching any
confidence estimate that was too optimistic at compile time.
Second, the framework extends naturally to the scientific benchmarks
in the companion paper~\cite{sounio2026}: PBPK pharmacokinetics and
functional neuroimaging, where the same GUM propagation rules apply
to measurement uncertainty rather than type confidence.

The deeper point is this: binary is never the right abstraction for
incomplete information.
Gradual typing taught us that types need not be all-or-nothing.
Epistemic gradual compilation teaches us that the gap between $?$
and~$\tau$ is itself a measurable, trackable, improvable quantity---
and that a compiler which applies this principle to itself is, by
the Patient Zero test, the most honest possible demonstration of its
own correctness.

\section{Lean~4 Machine-Checked Proofs}

The file \texttt{docs/proofs/meas\_conf\_soundness.lean} provides
Lean~4 proofs of the four main results stated in \S\ref{sec:gen15}.

but is fully mechanised: every lemma is checked by the Lean~4 kernel.

Key definitions and their correspondence to the implementation:
\begin{description}
  \item[\texttt{conf\_product a b}] $= \min(ab/1000,\;1000)$ — mirrors
        \texttt{ety\_conf\_product} in \texttt{lean\_single.sio}.
  \item[\texttt{meas\_propagate m1 m2}] $= \min(m_1, m_2)$ — mirrors
        the MEAS\_CONF Sweep~2 min-rule.
  \item[\texttt{unify\_conf\_gen15 a b}] $= 1000$ if $a=b=1000$, else
        $\lfloor(a^2+b^2)/(a+b+1)\rfloor$ — mirrors the Gen~15 \texttt{ety\_unify}.
  \item[\texttt{TokenArray n}] — an $n$-element array of confidence values
        bounded by 1000, providing the semantic domain for completeness.
\end{description}

The proof of \texttt{gen15\_platinum\_preservation} (\S4 of the Lean file)
is a single \texttt{simp} call after unfolding the conditional, reflecting
the triviality of the mathematical content: the \emph{difficulty} was
identifying the representational-noise problem, not proving that
$1000 = 1000$.
