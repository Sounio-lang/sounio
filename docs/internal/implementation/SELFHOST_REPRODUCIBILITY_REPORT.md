# Selfhost Reproducibility Report Generator

Use `scripts/selfhost/selfhost_reproducibility_report.py` to produce machine-readable and human-readable summaries from artifacts generated by `scripts/selfhost/selfhost_zero_fallback_gate.sh`.

## Usage

```bash
scripts/selfhost/selfhost_reproducibility_report.py \
  --gate-dir /tmp/sounio-selfhost-zero-gate-local
```

Optional output paths:

```bash
scripts/selfhost/selfhost_reproducibility_report.py \
  --gate-dir /tmp/sounio-selfhost-zero-gate-local \
  --json-out /tmp/repro/report.json \
  --md-out /tmp/repro/report.md
```

Default outputs:

- `<gate-dir>/artifacts/reproducibility_report.v1.json`
- `<gate-dir>/artifacts/reproducibility_report.v1.md`

## What It Validates

The script exits non-zero on malformed or incomplete artifacts, including:

- missing required files (`artifacts/summary.txt`, required logs)
- missing required `summary.txt` keys
- malformed `key=value` fields in summary/marker lines
- missing required marker lines:
  - `PARSE_ALL_REPORT_SUMMARY`
  - `PARSE_ALL_REPORT_SHARD`
  - `PARSE_ALL_MULTI_SUMMARY`
  - `PARSE_ALL_SUMMARY`
  - `strict=` driver markers in each required log
- inconsistent shard counts or non-contiguous report shard indexes
- inconsistent strict values across logs

## Included Fields

- deterministic schema metadata (`schema`, `schema_version`)
- platform snapshot of the machine generating the report
- gate time budgets and shard settings from `summary.txt`
- strict/no-fallback flags
- full gate marker counts and marker-pass outcomes
- parse-all report summary plus shard outcomes
- driver orchestration fallback/strict-error marker presence across logs
- oracle (Rust parity) marker presence across logs
