# Plan — 2026-08-22

Supersedes `ACTION_PLAN_2026-08-20.md`, which was written before the day that
followed it. Every item below carries **acceptance and abandonment**, per the
founder's standing rule that a decision without a stopping condition is
inflation with extra steps.

## The through-line

One move, four lanes: **the author asserts, and the compiler holds the evidence
to refute it.**

| lane | claim | state |
|---|---|---|
| **units** | `mg + mL` is a dimensional error | **enforced** (2026-08-21) |
| **provenance** | a computed value may not claim it was obtained | **R-ORIGIN enforced**; the rest open |
| **moduli** | a residue mod *p* is not a residue mod *q* | designed, blocked |
| **uncertainty ontology** | a GUM variance and a truncation band do not add | open (N5) |

No language does this across the board. Koka and OCaml 5 infer effects and make
the annotation optional; Rust and Java demand it and never infer; Zig ships
arbitrary widths and never asks whether you need them; LiquidHaskell and F*
prove bounds and never choose anything from the proof; PPLs separate aleatory
from epistemic in the model, never in the type.

## P1 — Finish what is one step from done

**P1.1 The `%` proof rule.** One decidable fact: if `p > 0` then `x % p`
inhabits `[0, p)`. With it, `type Fp = { n: i64 | n >= 0 && n < p }` closes on
its own and modular arithmetic becomes a refinement, which is the founder's
ruling of 2026-08-21.
*Acceptance:* `fn reduce(x: i64) -> Fp { x % p }` checks; `fn bad(x: i64) -> Fp { x }` is refused with `E042`; `a + b` on two `Fp` is refused until reduced.
*Abandonment:* if the static engine cannot discharge it without general
arithmetic reasoning, say so and put the modulus in a **unit_id**-style tag
instead — weaker, but it still refuses mixing mod *p* with mod *q*.

**P1.2 Refinement at the implicit tail.** The explicit `return` is fixed; the
tail is not, and `fn f() -> Fp { 2000000000 }` still compiles.
Likely cause: `last_literal_kind` is reset by the block walk before the
function-item handler reads it.
*Acceptance:* `refinement_holds_at_implicit_tail.sio` refuses with `E042`.
*Abandonment:* if the flag cannot survive the walk, thread the value
explicitly rather than widening the scratch mechanism further.

**P1.3 Land the stack.** `#2065`, then `#2059`.
*Acceptance:* both merged, the Madaros witness gate green with two known-failing.
*Abandonment:* none. This is finished work.

## P2 — The uncertainty ontology (N5)

The measurement that grounds it: **four ids out of thirty are ever branched on**
(`13 Observe`, `16 Hypothesis`, `17 MultiTest`, `22 Chaotic`). The four
uncertainty ontologies — `Approx` 23, `Perturbative` 26, `NWA` 27,
`NonUnitary` 28 — are branched on **zero** times. `GUM` is not an effect at all:
7 real sites in 6 files, all on thesis surfaces, resolving to `-1`.

So the gap is **not** a missing id. Recognising `GUM` would make it propagate
and change nothing. The gap is that **no ontology has a composition rule.**

**P2.1 One composition rule, one witness.** Pick the pair with the sharpest
physics: a GUM variance and a truncation band must not add.
*Acceptance:* a `compile-fail` that is refused with a **named** diagnostic, not
`E001`; and a `run-pass` proving the same two quantities compose once the
regime is reconciled explicitly.
*Abandonment:* if the ontology cannot be carried to the point of the operation,
say so and propose the value-level form — a two-channel quantity that keeps
stochastic variance and bounded error apart, which is what qwen defends as the
unclaimed design.

**P2.2 Is `Approx` an ontology or a shrug?** 30 sites, 20 files, the vaguest of
the four. Today nothing distinguishes it from `Perturbative`.
*Acceptance:* either a distinct composition rule, or a documented merge.
*Abandonment:* if no rule can be written, merge it and reduce the taxonomy —
the tree already carries `Confidence` as an alias of `Epistemic`, which is the
precedent.
