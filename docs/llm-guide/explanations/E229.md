# E229 — Lexer token table full

**Phase:** lexer  
**Severity:** error  
**Message pattern:** `error[E229]: lexer token table full (capacity 2097152 tokens)`  
  or `error[E229]: source exceeds lexer byte buffer (capacity 2097152 bytes)`

## Meaning

Madaros stores tokens for one compilation unit in fixed tables of length
**2097152**. When that wall is hit — or when the source itself exceeds the
matching **2097152-byte** `CURSOR_SOURCE` buffer — the compiler **refuses**
instead of continuing.

Previously, tokens past the wall were **silently dropped**. The parser then
saw a truncated stream (often a synthetic Eof mid-file) and reported a parse
error on a line that was still pristine. That is the same honesty failure as
fabricating a success value for work the backend cannot do (cf. **E219** for
unimplemented `extern "C"`).

## What to do

1. **Split the module** into smaller compilation units (preferred).
2. If measurement shows a higher hard ceiling is required for a real product
   path, raise the table **and keep this refusal** at the new bound. Raising
   the ceiling alone only moves the silent lie.

## Gate

`scripts/ci/token_table_ceiling_gate.sh` — generates a 2097152-comma witness and
requires `error[E229]` plus non-zero exit.
