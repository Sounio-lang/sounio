# E258 — String literal exceeds Name capacity

**Severity:** error

**Message pattern:** `error[E258]: N string literal(s) exceed Name capacity (384 bytes incl. quotes); first at line L, longest B bytes.`

## What happened

A string literal's byte length (including the surrounding quotes) is larger than the parser's `Name` capacity (384 bytes). Before this diagnostic existed, content past the capacity was silently dropped — the program still compiled and ran, but printed or used a truncated string with no warning (measured 2026-08-17: a 128-byte literal printed 127 bytes and exited 0).

## Common causes

- A generated or copy-pasted string literal that is longer than expected
- A literal built for testing capacity limits

## Fix

Split the literal into multiple concatenated pieces, or shorten it below the capacity:

```sounio
let s = "first part" + "second part"
```

If the workload genuinely needs longer inline string literals, `Name` capacity and the matching IR name-pool stride would need to be raised together — this is a compiler capacity limit, not a per-program error to work around case by case.
