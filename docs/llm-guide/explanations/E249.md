# E249 - Historical wide-float source reservation

**Severity:** error

**Historical message pattern:** `error[E249]: f128/f256 is reserved for compiler-owned format identity`

**Baseline context:** source inspected at
`f5b2c5850be9f3d3995719ffcade44a6d851658a`, October 2026 edition. E249 is a
retained V0-A catalog/message identity. On the inspected V0-B modular source,
`parser_reject_reserved_wide_float_path` in
[types.sio](../../../self-hosted/parser/types.sio) is a no-op. The
[remap gate](../../../scripts/ci/diagnostic_remap_2170_gate.sh) explicitly
expects no live parser E249 emitter. A retained message arm does not show that
this refusal is reachable. This page introduces no compiler execution result.

## Historical cause

V0-A reserved `f128` and `f256` for compiler-owned format identity and refused
source values before IR lowering. That reservation does not describe the
whole current wide-float surface. Current source contains selected f128
literal, arithmetic, comparison, and formatting paths; f256 and other wide
operations have separate representation and backend limits.

## Diagnose the operation that actually failed

Record the exact source, compiler artifact/build receipt, selected engine,
target, command, exit status, and full streams. If an installed artifact
prints E249, compare its identity with the selected source baseline before
rewriting the program. It may be an older artifact or a different route.

| Observed operation | Source-grounded distinction |
| --- | --- |
| Wide type annotation or unused declaration | Acceptance alone does not establish arithmetic, ABI, payload, or target support. |
| Modular f128/f64 value cast | `E248` names an unsupported conversion; it is not the old global E249 reservation. Inspect [f128_cast_to_f64_unimplemented.sio](../../../tests/compile-fail/f128_cast_to_f64_unimplemented.sio) and its engine annotation. |
| Selected f128 arithmetic/printing | Current lowering and softfloat/formatter source provide particular paths. Inspect the exact operation and its witness in the [numeric specification](../../spec/2026-10/05-numerics-units-and-algebra.md); do not infer all operations or targets from one example. |
| f256 lowering or an aggregate/FFI boundary | Establish support for that precise operation and representation; a frontend type check cannot certify native emission. |
| Wide epistemic payload/uncertainty | Scalar f128 support does not establish precision-preserving `Knowledge<f128>` or wide uncertainty propagation. Retain the separate semantic requirement. |

Several old E249 negative fixtures are explicitly ignored as superseded by
V0-B, including [f128_f256_arithmetic_unimplemented.sio](../../../tests/compile-fail/f128_f256_arithmetic_unimplemented.sio).
Read annotations rather than treating their filenames as a current refusal
contract.

## Fix

Preserve the requested format and precision. Use an existing supported
operation on the selected profile only when it satisfies the same contract;
otherwise keep the reproducer and report the unsupported conversion, lowering,
or target. Do not silently replace `f128`/`f256` with `f64`, encode a wide
value through `f64`, or claim parity without evidence. Any change to the
numerical representation requires an explicit semantic decision.

See [the error guide](../error-catalog.md) for code/route collisions and
[the complete example atlas](../examples.md) for source-marked candidates.
A source candidate remains unrun until a matching receipt establishes its
check, compilation, or execution stage separately.
