# E263 — Temporal validity window mismatch

**Severity:** error

**Message pattern:** `error[E263]: Temporal validity window mismatch: the provided value's validity window cannot satisfy the required type's validity constraint`

## What happened

A `Knowledge<T>` (or other epistemic-wrapper) value's declared validity
window (`ALWAYS` / a bounded `duration` / an explicit `ValidUntil` date)
does not subsume the REQUIRED type's validity window, at a function call
argument or an `as` cast between two epistemic wrapper types. For example,
passing (or casting) a value valid only for the next hour where a later
fixed `ValidUntil` date is required.

Function returns (explicit `return expr`, an implicit tail expression, or a
closure's declared return type) also enforce validity subsumption as part
of the same four-axis check, but currently report the generic E008
("return value does not match function's declared return type") rather
than this code -- E263's axis-specific classification is wired up only at
call boundaries and casts. If you see a validity mismatch at a return
position, look for E008, not E263.

This is one of the four axes epistemic call-boundary and cast checking
enforces for `Knowledge<T>` subsumption, alongside ontology, epsilon
(confidence), and provenance. It was previously misnumbered E246, which
already names an unrelated diagnostic ("unknown effect, or effect dropped
as a ninth slot"); this code was reassigned to E263 to remove that
collision.

## Fix

Either widen the source value's declared validity window (e.g. give it a
later `ValidUntil` or a longer duration), or relax the required type's
validity window to match what the value can actually promise.
