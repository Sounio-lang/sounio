# E263 — Temporal validity window mismatch

**Severity:** error

**Message pattern:** `error[E263]: Temporal validity window mismatch: the provided value's validity window cannot satisfy the required type's validity constraint`

## What happened

A `Knowledge<T>` (or other epistemic-wrapper) value's declared validity
window (`ALWAYS` / a bounded `duration` / an explicit `ValidUntil` date)
does not subsume the REQUIRED type's validity window, at one of several
positions: a function call argument, an `as` cast between two epistemic
wrapper types, or a function return. For example, passing (or casting) a
value valid only for the next hour where a later fixed `ValidUntil` date
is required.

This is one of the four axes epistemic call-boundary, cast, and return
checking enforces for `Knowledge<T>` subsumption, alongside ontology,
epsilon (confidence), and provenance. It was previously misnumbered E246,
which already names an unrelated diagnostic ("unknown effect, or effect
dropped as a ninth slot"); this code was reassigned to E263 to remove
that collision.

## Fix

Either widen the source value's declared validity window (e.g. give it a
later `ValidUntil` or a longer duration), or relax the required type's
validity window to match what the value can actually promise.
