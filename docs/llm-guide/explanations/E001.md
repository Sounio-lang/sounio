**E001 — Type mismatch or linear constraint violation**

> **Not refreshed by the October 2026 LLM-guide audit.** This retained
> explanation is reference material, not a current compiler or execution
> receipt. Codes, enforcement, and fixes can differ by engine and route. Start
> with the [current diagnostic guide](../error-catalog.md) and verify the full
> diagnostic against the selected artifact. Do not silently narrow precision,
> unwrap scientific values, or weaken effects/ownership to apply an old fix.

The type the compiler inferred for an expression does not match the declared or expected type, or a linear type was used in a context that violates linearity.

**Minimal example:**
```sio
fn add(a: i64, b: i64) -> i64 { a + b }

fn main() with IO, Panic {
    let result: f64 = add(1, 2)  // i64 returned, f64 declared
    println(result)
}
```

**Canonical fix:** Ensure the expression type matches the declared type. For numeric conversions use explicit casts (`x as f64`). For linear types ensure each value is consumed exactly once.

```sio
fn main() with IO, Panic {
    let result: i64 = add(1, 2)
    println(result)
}
```
