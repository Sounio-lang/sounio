# E251 - Product variance shortcut beyond the octonions

**Severity:** error

**Message pattern:** `error[E251]: product variance shortcut is unsound beyond the octonions: |xy| != |x||y| on Sedenion/Clifford, so Var(x*y) = |y|^2 Var x + |x|^2 Var y fabricates precision`

## What happened

Two `Knowledge<Hyper<A, _>>` values were multiplied where `A` is the sedenions or a
Clifford algebra (algebra kind ≥ 4). The checker propagates the product's uncertainty
with the GUM shortcut `Var(x·y) = ‖y‖²·Var x + ‖x‖²·Var y`. That formula is only correct
when the norm is multiplicative, `‖xy‖ = ‖x‖·‖y‖` — Hurwitz's theorem: true on ℝ, ℂ, ℍ, 𝕆,
false from the sedenions up.

This is the **third axis** of anti-garbling. E230 certifies that the operands share no
noise symbol (axis 2); the algebra's reassociation strategy certifies product order
(axis 1). Neither sees this one: on the sedenions a product with *disjoint* sources and
*no* re-association still under-reports. Kernel-checked witness
(`formal/lean4/EpistemicEffectsNSA.lean`, `sed_shortcut_understates`): sensitivity
`d = e₁+e₁₀` on one source, exact `y = e₄+e₁₅` — the shortcut reports variance 4, the true
first-order variance is 8. The zero-divisor pair `(e₁+e₁₀)(e₅+e₁₄) = 0` shows it also
over-reports, so the shortcut is not even conservative.

## How to fix

- Stay at the octonion level or below for `Knowledge<Hyper<…>>` products — there the
  shortcut equals the exact sensitivity propagator (`shortcut_eq_sensitivity_of_polarBasis`).
- Carry per-source sensitivity vectors (affine forms) instead of a scalar variance, and
  compute `Σ_s ‖∂_s x · y + x · ∂_s y‖²` — exact on every Cayley–Dickson level
  (`exact_preservation`).
- Addition of sedenion Knowledge values is unaffected: no norm identity is involved.
