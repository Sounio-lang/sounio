# MoE F32 mul_mat_id: Q5_K + Q8_0 (Plan E)

**Date:** 2026-10-28
**Branch:** `cursor/moe-f32-q5-q8`
**Status:** Draft for review
**Depends on:** Plan A-D (Q4_K mmid F32, runtime, `moe_ffn_q4k`, layer-0 forward hook) - PR #3292 / tip on `cursor/moe-f32-mmid-pr`

## Roadmap position

Program order agreed: **4 -> 2 -> 3**

1. **This cycle (4):** Q5_K + Q8_0 kernels through `moe_ffn_*` + hetero demos
2. **Next (2):** multi-layer MoE in `ll_forward_impl`
3. **Then (3):** real Mixtral/Q4_K (and later Q5/Q8) safetensors loader

## Goal

Native Sounio hetero MoE expert matmul for **Q5_K** and **Q8_0** weights with **F32** activations under the same amax contract as Q4_K (`amax=1e5`). No llama.cpp runtime dependency.

Approach: **A elevated (SOTA+++)** - twin stacks mirrored on the measured Q4_K path (dp4a + vec n=1 with packed/`__ldg` loads from first green), not a new quant-enum dispatcher.

## Out of scope (this cycle)

- Multi-layer MoE in `ll_forward_impl` (cycle 2)
- Mixtral / safetensors MoE loader (cycle 3)
- Changing `llama_moe_ffn_block` to multi-quant (stays Q4_K until a later plan)
- GraphIR multi-quant node typing
- Q5_0 / Q5_1 / Q6_K / IQ variants
- GPU SiLU / combine (host path unchanged)

## Architecture

| Layer | Q5_K | Q8_0 |
|-------|------|------|
| Kernel CU/PTX | `mmid_q5k_dp4a_f32` + `mmid_q5k_vec_f32` | `mmid_q8_0_dp4a_f32` + `mmid_q8_0_vec_f32` |
| Lab host | `mmid_q5k_*_lab` | `mmid_q8_0_*_lab` |
| Runtime | `rt_load_mmid_q5k`, `rt_mul_mat_id_q5k` | `rt_load_mmid_q8_0`, `rt_mul_mat_id_q8_0` |
| MoE FFN | `moe_ffn_q5k` | `moe_ffn_q8_0` |
| Demo | `examples/hetero_moe_q5k_demo.sio` | `examples/hetero_moe_q8_0_demo.sio` |

Shared (reuse, do not fork): `moe_topk`, `moe_silu_mul`, `moe_weighted_sum`, host u8/i32 helpers in `moe.sio`.

Do **not** introduce `moe_ffn(quant, ...)` or a single `rt_mul_mat_id(quant)` enum in this cycle.

## Data flow

1. Host packs expert weights as Q5_K or Q8_0 bytes; strides `expert_stride` / `row_stride` analogous to Q4_K.
2. Router: `moe_topk` on f32 logits -> ids i32 + renorm weights f32.
3. Three `rt_mul_mat_id_*` calls (gate, up, down): y/dst F32; auto vec when `ntokens == 1`.
4. Host SiLU*up and weighted combine -> dst F32.
5. Non-zero kernel/runtime status -> `!ok` on the MoE result (same pattern as Q4_K).

## Kernel requirements (SOTA+++)

- Port block layout and math from the known-good CUDA reference for each quant; keep F32 scales (not half) so large activations stay accurate.
- Invalid expert ids: quiet NaN on expert 0 (same policy as Q4_K).
- Vec n=1: packed weight loads / `__ldg` from first green (no byte-at-a-time baseline left as the ship path).
- PTX: sm_89, driver-JIT friendly `.version` aligned with Q4_K (8.5) unless a documented toolchain constraint forces otherwise.
- Build scripts under `scripts/gpu/` mirroring `build_mmid_q4k_dp4a_f32.sh` / L4 lab runners.

## Lab gates (L4)

Shapes (match Q4_K): m=4096, k=2048, 128 experts, 4 used, amax=1e5.

| n | NMSE | us/run target |
|---|------|----------------|
| 1 (vec) | <= 5e-4 | <= 120, or a documented higher ceiling with justification |
| 16 | <= 5e-4 | < 2500, or documented ceiling |
| 64 | <= 5e-4 | < 5500, or documented ceiling |

Oracle: CPU dequant + GEMM for that quant. Receipts written under `stdlib/hetero/kernels/` and summarized in `docs/design/moe-f32-mmid.md` (Plan E section).

## Runtime

- Separate function pointers on `Runtime` for Q5_K and Q8_0 (dp4a + vec each); 0 = not loaded.
- Lazy load once per quant module (same pattern as `rt_load_mmid` for Q4_K).
- `rt_mul_mat_id_q5k` / `rt_mul_mat_id_q8_0`: host raw bytes in/out; pick vec iff `ntokens == 1`.

## MoE + demos

- `moe_ffn_q5k` / `moe_ffn_q8_0`: copy structure of `moe_ffn_q4k`, call the matching runtime entry.
- Demos: synthetic packs, tiny dims acceptable for smoke; on GPU require status 0 + finite outputs + `DONE`; `exit(0)` after DONE to avoid CUDA teardown hang.
- Regression: existing Q4_K demos and `moe_ffn_q4k` remain green (`bin/souc check` + prior L4 behavior unchanged).

## Error handling

| Case | Behavior |
|------|----------|
| PTX/load fail | load returns !ok; demos print unavailable path and exit 0 or explicit fail per Q4_K demo style |
| Kernel status != 0 | MoE result `!ok` |
| slots > 16 or slots > n_experts | reject (-20) as Q4_K |
| Missing packs / null | caller/demo must not claim success |

## Success criteria

1. Q5_K lab L4 gates met (or ceilings documented).
2. Q8_0 lab L4 gates met (or ceilings documented).
3. `moe_ffn_q5k` + `moe_ffn_q8_0` + both demos typecheck; L4 smoke DONE when GPU present.
4. Q4_K path has no regression.
5. Design note `moe-f32-mmid.md` updated with Plan E receipts.
6. No llama.cpp link in the Sounio runtime path.
