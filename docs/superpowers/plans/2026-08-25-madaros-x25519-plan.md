# Madaros X25519 Key Exchange Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** implement X25519 (RFC 7748) key exchange in pure Sounio, plus a genuine OS-entropy source for private-key generation, verified against published test vectors — the key-exchange primitive a future TLS handshake sub-project will call.

**Architecture:** two new modules under `stdlib/crypto/` (`csprng.sio`, `x25519.sio`) plus a one-line documentation fix to the existing `random.sio`, built bottom-up — entropy source first (independent, trivial), then field arithmetic, then the Montgomery ladder, verified against RFC 7748's own test vectors at each stage.

**Tech Stack:** Sounio/Madaros (`./bin/souc`), no non-Sounio code anywhere in this plan's deliverables.

**Spec:** `docs/superpowers/specs/2026-08-25-madaros-x25519-design.md`

## Global Constraints

- **Never use native `u32` arithmetic anywhere near a 32-bit-word boundary** — use `stdlib/hash/word32.sio`'s `add32`/`rotl32`/`xor32`/etc. (a documented, real Madaros compiler defect: native `u32` `+`/`-` do not wrap mod 2^32 at all).
- **Never copy a fixed-array value via `var x = *ref`** — a real, documented Madaros compiler defect (`docs/handoff/souc_v0800_defects.md` §D8): dereferencing a fixed-array reference aliases the caller's array instead of copying it (not type-specific, a type annotation does not suppress it). Copy via explicit element-by-element assignment. Plain array-to-array assignment without a dereference (`var b = a`) copies correctly.
- **The Montgomery ladder (including `cswap`) must be constant-time** — no branch or memory-access pattern that depends on a secret scalar bit. Compute both possible results unconditionally and select via a bitmask, never an `if` keyed on scalar data.
- **RFC 7748's all-zero-output rejection is mandatory** — `x25519` must check its own output and report failure (`ok = false`) on an all-zero result, never silently return it as a valid shared secret.
- **Private-key entropy comes from `/dev/urandom` via `read_file`, never from `stdlib/crypto/random.sio`'s `CryptoRng`** (a deterministic, non-cryptographic PRNG despite its misleading header comment, which this plan corrects).
- Field arithmetic uses a 10-limb, radix-2^25.5 representation (alternating 26/25-bit limbs) — NOT a 5-limb radix-2^51 representation, which would need genuine double-word (~102-bit) intermediate products this compiler has no native support for. Every intermediate arithmetic value must stay provably far below `i64`'s 63-bit danger zone ("Finding 11": native `i64`/`u64` right-shift/divide/modulo break whenever bit 63 is set) — reasoned about explicitly in a code comment at each task, matching `stdlib/bignum/bigint.sio`'s and the AEAD plan's Poly1305 task's own established discipline.
- Sentinel `bool`/`i64` error convention — never `Result<T,E>`/`Option<T>`.
- Every test's expected value comes from RFC 7748, independently re-verified against the actual RFC text before being trusted in committed test code — never a self-generated value, and never trusted purely because "the mandated vectors pass" (the AEAD ciphers plan's Poly1305 task found a real, self-consistent bug invisible to every mandated vector — the same risk applies here, so every task in this plan that builds field arithmetic must go beyond the RFC vectors with an independent cross-check, as specified in each task below).
- Module imports: bare `use <filename>::{name|*}`, no `module` declaration.
- Commit convention: Conventional Commits (`feat(crypto): ...`). **Never add an AI-attribution line to any commit.**
- Test invocation: `bash scripts/run_sio_test_suite.sh --filter-prefix csprng_` / `x25519_` — never the whole-repo suite. Use `--jobs 2` (this exact branch has repeatedly found high parallelism produces spurious 30-second timeouts on this test runner).
- Run every shell command as a plain foreground command — never a background/Monitor-style wait mechanism.

## Task 1: `stdlib/crypto/csprng.sio` — OS entropy source

**Files:**
- Create: `stdlib/crypto/csprng.sio`
- Modify: `stdlib/crypto/random.sio` (header comment only, one line)
- Test: `tests/run-pass/csprng_os_random.sio`

**Interfaces:**
- Produces: `pub fn crypto_os_random_bytes(n: i64) -> (RawBuf, bool) with IO`. Task 2/3 (X25519's key-generation examples, if any test needs a "generate a fresh key" path rather than a fixed RFC vector) may call this; the RFC-vector-based tests do NOT need it (they use fixed, published scalars).

`read_file`'s real, confirmed signature on this compiler is `read_file(path: string) -> string with IO` (NOT a 3-argument pointer form — this was confirmed during an earlier sub-project on this same branch). Its underlying implementation issues exactly ONE `read()` syscall internally (confirmed by reading `self-hosted/native/codegen.sio`'s `emit_builtin_read_file`) — it does NOT loop until EOF, which matters because `/dev/urandom` is a character device with no EOF: a naive "read until EOF" implementation would hang forever, but a single bounded `read()` call returns immediately with up to the requested number of bytes.

```sio
use net::socket::*

pub fn crypto_os_random_bytes(n: i64) -> (RawBuf, bool) with IO {
    let out = rawbuf_new(n + 8)
    var filled: i64 = 0
    while filled < n {
        let s = read_file("/dev/urandom")
        let available = str_len(s)
        if available <= 0 {
            return (out, false)
        }
        var to_copy = available
        if filled + to_copy > n {
            to_copy = n - filled
        }
        var i: i64 = 0
        while i < to_copy {
            rawbuf_set(&out, filled + i, str_char_at(s, i) as i64)
            i = i + 1
        }
        filled = filled + to_copy
    }
    (out, true)
}
```

(Adjust the loop/chunking logic if Step 1's real measured per-call byte count differs from what's assumed here — the shape above already handles "one call returns fewer bytes than requested" by looping, so it should be correct regardless of the exact measured value, but re-verify against your Step 1 finding.)

## Task 2: `stdlib/crypto/x25519.sio` (part 1) — field arithmetic

**Files:**
- Create: `stdlib/crypto/x25519.sio`
- Test: `tests/run-pass/x25519_field_arithmetic.sio`

**Interfaces:**
- Produces (file-private, no `pub` — Task 3 in the SAME file relies on these exact names/signatures, but nothing outside this file needs them): `struct FieldElement { limbs: [i64;10] }`, `fn fe_zero() -> FieldElement`, `fn fe_one() -> FieldElement`, `fn fe_from_bytes(b: &[u8;32]) -> FieldElement`, `fn fe_to_bytes(fe: &FieldElement) -> [u8;32]`, `fn fe_add(a: &FieldElement, b: &FieldElement) -> FieldElement`, `fn fe_sub(a: &FieldElement, b: &FieldElement) -> FieldElement`, `fn fe_mul(a: &FieldElement, b: &FieldElement) -> FieldElement`, `fn fe_sqr(a: &FieldElement) -> FieldElement`, `fn fe_invert(a: &FieldElement) -> FieldElement`, `fn fe_cswap(swap: bool, a: &FieldElement, b: &FieldElement) -> (FieldElement, FieldElement)`.

This task builds the field arithmetic ONLY (no ladder yet, no clamping, no public API) — it's the highest-risk task in this plan, analogous to the AEAD ciphers plan's Poly1305 task (wide/limb arithmetic where a subtle carry bug can be invisible to a small number of fixed test cases). Every function here must be independently testable in isolation before Task 3 builds the ladder on top.

- [ ] **Step 1: Write failing tests for each field-arithmetic primitive, using round-trip and small-known-value checks**

Since RFC 7748 doesn't publish standalone field-arithmetic test vectors (only full X25519 input/output pairs, which Task 3 will test), this task's own tests must establish correctness through structural properties and small hand-computable cases:

```sio
//@ run-pass
// Structural + small-value tests for GF(2^255-19) field arithmetic.
// These do NOT replace Task 3's RFC 7748 end-to-end vectors -- they
// establish that each primitive operation is individually sound before
// the Montgomery ladder is built on top of it.
use crypto::x25519::*

fn main() -> i64 with IO {
    // fe_from_bytes/fe_to_bytes round-trip: encoding 1 and re-decoding
    // must recover 1 (the simplest possible non-zero value).
    var one_bytes: [u8;32] = [0;32]
    one_bytes[0] = 1
    let one_fe = fe_from_bytes(&one_bytes)
    let one_back = fe_to_bytes(&one_fe)
    var i: i64 = 0
    while i < 32 {
        if one_back[i as usize] != one_bytes[i as usize] {
            print_int(1)
            return 1
        }
        i = i + 1
    }

    // fe_add(1, 1) round-trips to the byte encoding of 2.
    let two_fe = fe_add(&one_fe, &one_fe)
    let two_bytes = fe_to_bytes(&two_fe)
    var expected_two: [u8;32] = [0;32]
    expected_two[0] = 2
    var j: i64 = 0
    while j < 32 {
        if two_bytes[j as usize] != expected_two[j as usize] {
            print_int(2)
            return 1
        }
        j = j + 1
    }

    // fe_sub(2, 1) == 1.
    let back_to_one = fe_sub(&two_fe, &one_fe)
    let back_to_one_bytes = fe_to_bytes(&back_to_one)
    var k: i64 = 0
    while k < 32 {
        if back_to_one_bytes[k as usize] != one_bytes[k as usize] {
            print_int(3)
            return 1
        }
        k = k + 1
    }

    // fe_mul(1, x) == x for an arbitrary non-trivial x.
    var x_bytes: [u8;32] = [0;32]
    x_bytes[0] = 42
    x_bytes[5] = 7
    let x_fe = fe_from_bytes(&x_bytes)
    let x_times_one = fe_mul(&x_fe, &one_fe)
    let x_times_one_bytes = fe_to_bytes(&x_times_one)
    var m: i64 = 0
    while m < 32 {
        if x_times_one_bytes[m as usize] != x_bytes[m as usize] {
            print_int(4)
            return 1
        }
        m = m + 1
    }

    // fe_sqr(x) == fe_mul(x, x).
    let x_sqr = fe_sqr(&x_fe)
    let x_mul_x = fe_mul(&x_fe, &x_fe)
    let x_sqr_bytes = fe_to_bytes(&x_sqr)
    let x_mul_x_bytes = fe_to_bytes(&x_mul_x)
    var n: i64 = 0
    while n < 32 {
        if x_sqr_bytes[n as usize] != x_mul_x_bytes[n as usize] {
            print_int(5)
            return 1
        }
        n = n + 1
    }

    // fe_invert(x) * x == 1, for x=2 (2's modular inverse mod the field
    // prime p=2^255-19 is a well-defined, independently-computable value:
    // since p is odd, 2^-1 mod p = (p+1)/2 -- INDEPENDENTLY VERIFY this
    // reasoning and the resulting byte value before trusting it here).
    var two_bytes_in: [u8;32] = [0;32]
    two_bytes_in[0] = 2
    let two_in = fe_from_bytes(&two_bytes_in)
    let two_inv = fe_invert(&two_in)
    let should_be_one = fe_mul(&two_in, &two_inv)
    let should_be_one_bytes = fe_to_bytes(&should_be_one)
    var p: i64 = 0
    while p < 32 {
        if should_be_one_bytes[p as usize] != one_bytes[p as usize] {
            print_int(6)
            return 1
        }
        p = p + 1
    }

    // fe_cswap(false, a, b) leaves a and b unchanged; fe_cswap(true, a, b)
    // swaps them. Verify both, using two distinguishable values.
    let (no_swap_a, no_swap_b) = fe_cswap(false, &one_fe, &two_fe)
    let no_swap_a_bytes = fe_to_bytes(&no_swap_a)
    let no_swap_b_bytes = fe_to_bytes(&no_swap_b)
    var q: i64 = 0
    while q < 32 {
        if no_swap_a_bytes[q as usize] != one_bytes[q as usize] { print_int(7); return 1 }
        if no_swap_b_bytes[q as usize] != two_bytes[q as usize] { print_int(8); return 1 }
        q = q + 1
    }
    let (swap_a, swap_b) = fe_cswap(true, &one_fe, &two_fe)
    let swap_a_bytes = fe_to_bytes(&swap_a)
    let swap_b_bytes = fe_to_bytes(&swap_b)
    var r: i64 = 0
    while r < 32 {
        if swap_a_bytes[r as usize] != two_bytes[r as usize] { print_int(9); return 1 }
        if swap_b_bytes[r as usize] != one_bytes[r as usize] { print_int(10); return 1 }
        r = r + 1
    }

    println("x25519_field_arithmetic: fe_add/sub/mul/sqr/invert/cswap all satisfy their structural properties")
    return 0
}
```

Before trusting the `fe_invert(2)` reasoning above (`2^-1 mod p = (p+1)/2` since `p` is odd), independently verify it yourself: `p = 2^255 - 19`, `(p+1)/2` is an integer since `p` is odd, and `2 * ((p+1)/2) = p+1 ≡ 1 (mod p)`. This is correct number theory, but re-derive it yourself rather than trusting this plan's transcription, and additionally verify `fe_mul(&two_in, &two_inv)` reduces to exactly `fe_from_bytes(&one_bytes)`'s encoding (not just "close to 1") since `fe_to_bytes` must perform the final reduction mod `p` correctly for this comparison to be meaningful.

- [ ] **Step 3: Implement the field arithmetic in `stdlib/crypto/x25519.sio`**

This is real, substantial cryptographic arithmetic (10-limb radix-2^25.5 GF(2^255-19) field element add/sub/mul/sqr/reduce, matching the well-documented "ref10"-style curve25519 field-element representation) — there is no ambiguity in the underlying mathematics, only in expressing it correctly in this specific language/compiler. Write:

```sio
use net::socket::*

// GF(2^255-19) field element in radix-2^25.5 (10 limbs, alternating
// 26-bit and 25-bit limbs -- limbs[0,2,4,6,8] hold up to 2^26-1,
// limbs[1,3,5,7,9] hold up to 2^25-1 before any carry-propagation pass).
// This representation is chosen (per the spec) specifically because
// products of two such limbs stay under 2^52, and summing several such
// products stays comfortably under i64's 63-bit danger zone (this
// project's own documented "Finding 11": native i64/u64 right-shift/
// divide/modulo break whenever bit 63 is set) without needing any wider
// native integer type -- the same discipline stdlib/bignum/bigint.sio and
// this branch's own Poly1305 implementation (stdlib/crypto/poly1305.sio)
// already establish and prove correct for this compiler.
struct FieldElement {
    limbs: [i64; 10],
}

fn fe_zero() -> FieldElement {
    FieldElement { limbs: [0;10] }
}

fn fe_one() -> FieldElement {
    var f = fe_zero()
    f.limbs[0] = 1
    f
}

// <fill in: fe_from_bytes (32 little-endian bytes -> 10 limbs, using the
// standard 25.5-bit-per-limb bit-extraction -- limb i covers bits
// floor(i*25.5) to floor((i+1)*25.5)-1 of the 255-bit value), fe_to_bytes
// (10 limbs -> 32 bytes, INCLUDING full carry propagation and final
// conditional subtraction of p=2^255-19 if the represented value is
// >= p, per RFC 7748's own encoding procedure -- this is exactly the kind
// of "missing final carry/reduction step" that caused a real, subtle bug
// in this branch's own Poly1305 implementation; do not skip or
// under-verify this step), fe_add (limb-wise addition, no reduction
# needed immediately since inputs are assumed already-bounded and a few
// additions don't overflow the danger zone -- but eventually needs a
// carry pass before any further multiply, reason explicitly about when),
// fe_sub (limb-wise subtraction -- GF(2^255-19) subtraction needs care
// with negative intermediate limb values before carry propagation;
// reason explicitly about the bound), fe_mul (the standard schoolbook
// 10x10 limb product with the field's specific reduction using the
// 2^255 ≡ 19 (mod p) identity to fold high-order terms back down, then a
// carry-propagation pass), fe_sqr (same as fe_mul but exploiting a*b ==
// b*a symmetry to halve the number of distinct limb products, a standard
// optimization -- verify correctness against fe_mul(x,x) via this task's
// own test before trusting the optimized version, and it's fine to
// implement fe_sqr as a direct call to fe_mul(x,x) initially if the
// optimization proves error-prone; correctness first, per this project's
// own stated priorities), fe_invert (a^(p-2) mod p via a fixed sequence
// of squarings and multiplies -- p-2 = 2^255-21 is a public constant, so
// this is not a data-dependent-timing concern despite operating on
// secret input `a`; the standard addition-chain for this specific
// exponent is well-documented in reference X25519 implementations,
// implement it as a fixed sequence of fe_sqr/fe_mul calls, not a
// general-purpose modexp loop that branches on exponent bits), fe_cswap
// (constant-time conditional swap: convert `swap: bool` to an all-1s or
// all-0s i64 mask, e.g. `let mask: i64 = 0 - (swap as i64)`, then for
// each limb pair compute `diff = mask & (a.limbs[i] ^ b.limbs[i])`,
// `new_a = a.limbs[i] ^ diff`, `new_b = b.limbs[i] ^ diff` -- NEVER an
// `if swap { ... } else { ... }` branch, which would defeat the entire
// point of this function>
```

Do not use `var x = *ref` anywhere when copying a `FieldElement`'s `limbs` array — rebuild element-by-element per this plan's Global Constraints.

```sio
pub const X25519_KEY_LEN: i64 = 32

// RFC 7748 section 5: clamp a raw 32-byte scalar for X25519.
pub fn x25519_clamp(raw: &[u8;32]) -> [u8;32] {
    var out: [u8;32] = [0;32]
    var i: i64 = 0
    while i < 32 { out[i as usize] = raw[i as usize]; i = i + 1 }
    out[0] = out[0] & 248     // clear bits 0,1,2 (0xF8 mask)
    out[31] = out[31] & 127   // clear bit 7 (0x7F mask)
    out[31] = out[31] | 64    // set bit 6 (0x40)
    out
}

// The shared Montgomery ladder core. `u_bytes` is the input u-coordinate
// (either the fixed base point 9, or a peer's public key). `scalar_bytes`
// MUST already be clamped by the caller (both public entry points below
// clamp before calling this).
fn x25519_ladder(scalar_bytes: &[u8;32], u_bytes: &[u8;32]) -> [u8;32] {
    let x1 = fe_from_bytes(u_bytes)
    var x2 = fe_one()
    var z2 = fe_zero()
    var x3 = x1
    var z3 = fe_one()
    var swap: bool = false

    // RFC 7748's ladder iterates from bit 254 down to bit 0 (bit 255 is
    // always 0 after clamping).
    var pos: i64 = 254
    while pos >= 0 {
        let byte_index = pos / 8
        let bit_index = pos % 8
        let scalar_bit = ((scalar_bytes[byte_index as usize] >> (bit_index as u8)) & 1) != 0

        let do_swap = scalar_bit != swap
        // <fill in: fe_cswap(do_swap, &x2, &x3), fe_cswap(do_swap, &z2, &z3);
        // update swap = scalar_bit>
        // <fill in: the standard Montgomery differential-addition-and-
        // doubling step using fe_add/fe_sub/fe_mul/fe_sqr on
        // (x2,z2)/(x3,z3)/x1, per RFC 7748's own pseudocode (the "A, AA,
        // B, BB, E, C, D, DA, CB" naming from the RFC, or equivalent) --
        // implement this from the RFC's actual formulas, verify against
        // the RFC 7748 vectors in Step 2 before trusting it>
        pos = pos - 1
    }
    let (final_x2, _final_x3) = fe_cswap(swap, &x2, &x3)
    let (final_z2, _final_z3) = fe_cswap(swap, &z2, &z3)

    let z2_inv = fe_invert(&final_z2)
    let result = fe_mul(&final_x2, &z2_inv)
    fe_to_bytes(&result)
}

pub fn x25519_base_point_mul(scalar: &[u8;32]) -> [u8;32] with IO {
    var base: [u8;32] = [0;32]
    base[0] = 9
    x25519_ladder(scalar, &base)
}

pub fn x25519(scalar: &[u8;32], u_coordinate: &[u8;32]) -> ([u8;32], bool) with IO {
    let result = x25519_ladder(scalar, u_coordinate)
    var all_zero: bool = true
    var i: i64 = 0
    while i < 32 {
        if result[i as usize] != 0 { all_zero = false }
        i = i + 1
    }
    (result, !all_zero)
}
```
