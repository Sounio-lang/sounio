# MoE F32 vec chase + LLM FFN Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** In one gated L4 cycle, push `mmid_q4k_vec_f32` toward <=120 us/run (or document the ceiling), then wire one MoE FFN block into the Sounio llama path with a runnable demo - no llama.cpp.

**Architecture:** Keep the vec kernel as a pure CUDA unit with lab gates; keep `moe_ffn_q4k` as the only MoE matmul stack; add a thin `llama_moe_ffn_block` in `stdlib/llm/llama.sio` that does router top-k + `moe_ffn_q4k` and a demo that feeds synthetic Q4_K packs. Speed miss on vec does not block the LLM task.

**Tech Stack:** Sounio (`.sio`), CUDA 12.6 PTX sm_89 (`.version 8.5`), hetero runtime (`ce_launch_2d_shmem`), L4 via `srun` on `gpuorangefs-r770-proxmox`, branch `cursor/moe-f32-mmid`.

**Spec:** `docs/superpowers/specs/2026-10-28-moe-f32-vec-llm-design.md`

- [ ] **Step 2: Apply one focused vec edit**

In `mmid_q4k_vec_f32` / `mmid_dot_q4_K`, try **one** primary tactic this cycle (do not stack unrelated rewrites):

Preferred order (stop when time is used):
1. Vectorise nibble loads in `mmid_dot_q4_K` (`uint32_t` packs + `__ldg` on `q`) while keeping F32 `y` math.
2. Or raise useful occupancy: tune `threads` (still divides m tiles) and/or process multiple rows per thread if register pressure stays sane.
3. Or stage Q4_K row tiles with `cp.async` into shared **only if** the diff stays small and shmem fits with `k*sizeof(float)` activations.

Keep quiet-NaN behaviour for invalid ids. Do not change dp4a path behaviour.

Illustrative direction for (1) - replace per-byte nibble loop body with 4-wide loads (adapt to existing indices `yb[64*il + j]`):

```cuda
// inside mmid_dot_q4_K, per il group:
const uint8_t * q = b.qs + 32 * il;
const float * y_lo = yb + 64 * il;
const float * y_hi = y_lo + 32;
#pragma unroll
for (int j = 0; j < 32; j += 4) {
    const uint32_t raw = __ldg(reinterpret_cast<const uint32_t *>(q + j));
#pragma unroll
    for (int lane = 0; lane < 4; ++lane) {
        const int qq = int((raw >> (8 * lane)) & 0xFFu);
        acc = fmaf(d1 * float(qq & 0xF) - m1, y_lo[j + lane], acc);
        acc = fmaf(d2 * float(qq >> 4) - m2, y_hi[j + lane], acc);
    }
}
```

If float4 staging for `yshared` loads is not already present, optional:

```cuda
for (int i = threadIdx.x; i < k / 4; i += int(blockDim.x)) {
    reinterpret_cast<float4 *>(yshared)[i] =
        *reinterpret_cast<const float4 *>(y + 4 * i);
}
```

(only when `k % 4 == 0`, which holds for k=2048).

  - `pub fn llama_moe_ffn_block(rt: &Runtime, cfg: &LlamaMoeFfnCfg, x_f32: *mut u8, router_logits: *mut u8, gate_w/up_w/down_w: *mut u8, dst_f32: *mut u8) -> MoeFfnResult`

- [ ] **Step 1: Add config struct + block function to `llama.sio`**

Near the top imports, add:

Add (names exact):

```sio
pub struct LlamaMoeFfnCfg {
    pub n_experts: i64,
    pub slots: i64,
    pub hidden: i64,
    pub inter: i64,
    pub n_tokens: i64,
    pub gate_bytes: i64,
    pub up_bytes: i64,
    pub down_bytes: i64,
    pub expert_stride_g: i64,
    pub row_stride_g: i64,
    pub expert_stride_u: i64,
    pub row_stride_u: i64,
    pub expert_stride_d: i64,
    pub row_stride_d: i64,
}

/// One MoE FFN: top-k on router_logits then moe_ffn_q4k.
/// x_f32 / dst_f32 are f32[n_tokens * hidden]; router_logits f32[n_tokens * n_experts].
/// Expert packs are Q4_K bytes. Dense SwiGLU path in ll_forward_impl is unchanged.
pub fn llama_moe_ffn_block(
    rt: &Runtime,
    cfg: &LlamaMoeFfnCfg,
    x_f32: *mut u8,
    router_logits: *mut u8,
    gate_w: *mut u8,
    up_w: *mut u8,
    down_w: *mut u8,
    dst_f32: *mut u8
) -> MoeFfnResult with Alloc, Mut, Panic, Div {
    var bad = MoeFfnResult { ok: false, status: -20, ms_gate: 0.0, ms_up: 0.0, ms_down: 0.0 }
    if cfg.n_experts <= 0 || cfg.slots <= 0 || cfg.hidden <= 0 || cfg.inter <= 0 {
        return bad
    }
    if cfg.n_tokens <= 0 { return bad }
    let ids = heap_alloc(cfg.n_tokens * cfg.slots * 4)
    let route_w = heap_alloc(cfg.n_tokens * cfg.slots * 4)
    moe_topk(router_logits, cfg.n_tokens, cfg.n_experts, cfg.slots, ids, route_w)
    moe_ffn_q4k(
        rt, x_f32, cfg.hidden, cfg.n_tokens, cfg.slots,
        ids, route_w,
        gate_w, cfg.gate_bytes,
        up_w, cfg.up_bytes,
        down_w, cfg.down_bytes,
        cfg.n_experts, cfg.inter,
        cfg.expert_stride_g, cfg.row_stride_g,
        cfg.expert_stride_u, cfg.row_stride_u,
        cfg.expert_stride_d, cfg.row_stride_d,
        dst_f32
    )
}
```

Do **not** rewrite `ll_forward_impl` dense SwiGLU in this task. The block is the llama-path entry point the demo (and a future loader) call.

- [ ] **Step 1: Write the demo**

Compact shape (same family as hetero_moe_layer_demo): hidden=256, inter=512, experts=8, slots=2, n_tokens=1.

```sio
//@ run-pass
// llama_moe_ffn_block smoke: synthetic Q4_K packs, no llama.cpp.
// Usage: llama_moe_ffn_demo [gemm-ptx] [mmid-ptx]

use hetero::runtime::{rt_load_mmid, rt_open}
use llm::llama::{LlamaMoeFfnCfg, llama_moe_ffn_block}
use hetero::cublas_bench::{gb_host_f32, gb_host_set}

// Include the same write_u8 / f32_to_f16_bits / pack_q4k helpers as
// examples/hetero_moe_layer_demo.sio (copy, do not import across examples).

fn main() with IO, Mut, Panic, Div, Alloc {
    var gemm_ptx = "stdlib/hetero/kernels/gemm_naive_f32.ptx"
    var mmid_ptx = "stdlib/hetero/kernels/mmid_q4k_dp4a_f32.ptx"
    if arg_count() > 0 { gemm_ptx = get_arg(0) }
    if arg_count() > 1 { mmid_ptx = get_arg(1) }

    var rt = rt_open(gemm_ptx, "gemm_naive_f32")
    if !rt.ready {
        print("gpu: unavailable\nLLAMA MOE FFN DONE\n")
        exit(0)
    }
    if !rt_load_mmid(&!rt, mmid_ptx) {
        print("mmid: PTX load failed\nLLAMA MOE FFN DONE\n")
        exit(0)
    }

    let hidden: i64 = 256
    let inter: i64 = 512
    let experts: i64 = 8
    let slots: i64 = 2
    let n_tokens: i64 = 1

    let row_g = (hidden / 256) * 144
    let row_u = row_g
    let row_d = (inter / 256) * 144
    let eg = inter * row_g
    let eu = inter * row_u
    let ed = hidden * row_d
    let gate_w = heap_alloc(experts * eg)
    let up_w = heap_alloc(experts * eu)
    let down_w = heap_alloc(experts * ed)
    pack_q4k(gate_w, eg, row_g, experts, inter, hidden, 0.02)
    pack_q4k(up_w, eu, row_u, experts, inter, hidden, 0.02)
    pack_q4k(down_w, ed, row_d, experts, hidden, inter, 0.02)

    let x = gb_host_f32(n_tokens * hidden)
    let logits = gb_host_f32(n_tokens * experts)
    let dst = gb_host_f32(n_tokens * hidden)
    var i: i64 = 0
    while i < hidden {
        gb_host_set(x, i, 0.01 * ((i % 7) as f64))
        i = i + 1
    }
    i = 0
    while i < experts {
        gb_host_set(logits, i, if i < slots { 2.0 } else { 0.0 - 1.0 })
        i = i + 1
    }

    let cfg = LlamaMoeFfnCfg {
        n_experts: experts, slots: slots, hidden: hidden, inter: inter,
        n_tokens: n_tokens,
        gate_bytes: experts * eg, up_bytes: experts * eu, down_bytes: experts * ed,
        expert_stride_g: eg, row_stride_g: row_g,
        expert_stride_u: eu, row_stride_u: row_u,
        expert_stride_d: ed, row_stride_d: row_d,
    }
    let r = llama_moe_ffn_block(&rt, &cfg, x, logits, gate_w, up_w, down_w, dst)
    if !r.ok {
        print("llama_moe_ffn_block failed status=")
        // print status then exit non-zero if the harness supports it
        print("\nLLAMA MOE FFN DONE\n")
        exit(1)
    }
    print("ok ms_gate=")
    // print r.ms_gate, r.ms_up, r.ms_down (use existing f64 print helpers in demos)
    print("\nLLAMA MOE FFN DONE\n")
}
```

Fill print helpers exactly as in `hetero_moe_layer_demo.sio` (same style for floats).
