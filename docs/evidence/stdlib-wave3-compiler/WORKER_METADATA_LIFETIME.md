# Worker metadata across dependency arena reclamation

Bindings and constructor intents used to be Box-linked nodes allocated while a dependency arena mark was active. They remained in global metadata after module_frontend reclaimed that arena. The real raw11332 imported thread failed identity10/cap201; another imported fixture hung in lowering. With the diagnostic NoReset switch both promptly advanced to the independently repaired empty-extern error 204. NoReset is not a correction.

Bindings and intents now use private fixed-stride records in lazy heap_alloc pages, outside the Box arena. Each record family has at most 128 pages of 128 KiB (16 MiB, 131072 records). Pages are retained and reused between compilations; list roots and allocation cursors reset per compilation. A failed allocation or exhausted record budget marks Worker admission bad and returns no usable record. Source signature Boxes remain rooted by the existing canonical source-signature list, captured before dependency lowering.

Immediately before each of the two dependency arena resets, module_frontend materializes remapped identities as direct accumulator bindings, preserving source epoch, signature identity, freshness, and trusted physical origin. It then removes dependency bindings and all lazy remap edges. Reusing a retired table address cannot reinterpret an already consolidated accumulator identity. Conflicting source identities still poison admission. The global Box arena is reclaimed normally; this change does not retain dependency AST/IR or disable reclamation.

Budget accounting clarification: the 32 MiB bound above is record payload. The current Linux native heap_alloc prepends an eight-byte header and rounds each mapping to 4096 bytes; 128 KiB payload therefore maps 132 KiB. At all 256 pages allocated, the two record families map at most 33 MiB, plus 2 KiB of page-pointer arrays and existing compiler metadata outside this component. No total process-memory bound is inferred.
