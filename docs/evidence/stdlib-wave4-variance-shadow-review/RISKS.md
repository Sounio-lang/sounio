# Scope and risks for owner review

- This is a review artifact, not a qualified implementation. A successful static patch-shape check says nothing about Sounio checker/native correctness.
- The new origin table is one boxed LowerLocalI64Slots (4096 i64 words, 32 KiB payload); the Lowerer carries only its existing locals pointer plus a Boolean context field. It must not be replaced by an inline large array or packed into scalar_kind.
- Local tables are shared through Box during Lowerer copies. Assignment invalidation is monotone and conservatively visible to sibling branches. New declarations may seed a new binding; assignments never re-enable it. Every slot writer must reset it, and scope/function/closure/FO-inline cases need actual controls.
- The whole-function fence is intentionally strict. A method, borrow, dereference, closure, match, handler, for-in or unknown form anywhere can disable certification even if unrelated to the integer variable. A resulting first-tracking scope error is a new explicit unsupported case, not a passed regression. A finer per-BindingID whole-function analysis is future work.
- The closed grammar only applies to the new absent-target assignment path. Existing tracked arithmetic and floating-point/Knowledge behavior are not changed. A zero numeric value is not proof of absent provenance; zero-variance Knowledge with sensitivities must remain tracked.
- First real promotion requires same lexical depth, loop depth zero and a plain scalar. The assumption that this point dominates subsequent in-scope uses must be checked against actual block/control-flow lowering and the final-IR auditor. No undefined register is replaced with zero.
- Newly encountered Hessian first-promotion is refused. Existing tracked Hessian behavior is unchanged. FO-inline refusal uses the existing frame-clash rollback and must demonstrate that speculative IR and origin facts cannot escape.
- The diagnostic uses a distinct semantic marker with the existing hard-error path. Root/owner must verify its error/barrier behavior, invalid current-function handling, probe error propagation and FO-inline rollback; no parse/unknown-name failure qualifies the refusal.
- The new private first-tracking cell copies RHS variance and uses the existing FO slot allocator; opaque nonzero variance without sensitivity must retain its variance/residual. No general clear/reset change is included.
- Separate observations, NOT changes in proposed.patch: declaration privatization currently precedes later type-metadata variance discovery; assigning a tracked constant may retain old derivative rows because the helper call is gated on nonempty sensitivity. Both need independent numerical repros. Unconditionally clearing residual is unsafe for an opaque nonzero RHS. The patch deliberately leaves all these paths intact.
- Whole-corpus source/native qualification and default compiler activation remain separate. No new compiler bootstrap or scientific job was submitted by this lane for the review patch.
