## Runner and collector binding

The existing C++ runner accepts an optional final --coherent-kind KIND.
Its allowed kind is fixed by the compiled protocol: 1 for base/UCA, 2 for CLDR
keys, 3 for metadata. It executes the exact ELF directly with that one argument.
It records argc/kind in ELF_INVOCATION.tsv. The optional collector prefix
--coherent-kind KIND requires the matching receipt for every partition.
The legacy four-key STATUS and six-column RESULTS.tsv schemas stay unchanged.

Legacy execution and collection before/after pass without arguments.
The old runner rejects the new flag. New runners reject wrong kind and extra
argc before creating output. Controls also reject wrong row count, missing
success marker, nonzero native exit, actual exec argv mismatch, missing or
tampered kind/argc binding, missing partition and duplicate partition.

The C++ control executable only validates test orchestration. It implements
no Unicode behavior. The separate focused Sounio execution is the runtime proof.
No wrapper substitutes for the actual executable identity.
