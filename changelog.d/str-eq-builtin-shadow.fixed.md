A user function named `str_eq` no longer captures `string == string`, `!=` or a string-literal `match` arm on Madaros. Those lower to a call of the runtime `str_eq` by bare name, and `stdlib/str/lib.sio`'s `pub fn str_eq(a: &Str, b: &Str)` was bound instead, so every string comparison in a program that also called the `Str` version passed two string handles to it (`tests/stdlib/str/test_str.sio` failed five comparisons, and other programs hit `ud2`). `str_eq` joins the builtin-shadow list (KL-21): a user definition is renamed `str_eq__user` in its module, its own callers and importers still reach it, and string equality reaches the runtime.
