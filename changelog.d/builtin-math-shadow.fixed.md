Madaros: a function named `sqrt`, `exp`, `log`, `sin`, `cos` or `pow` defined in some module no longer replaces the builtin for the whole program. It is called from its own module and from the modules that import it; every other module, and the compiler's own uncertainty arithmetic, gets the builtin. Before, `use pb::m::{fb}` alone made `sqrt(4.0)` print 104 when `pb::m` defined `pub fn sqrt(x) { x + 100 }`, and `use math::pure::{exp}` made every bare `sqrt` in the importer type as `math::pure::sqrt` (E035, Panic) (`tests/multimodule/builtin_math_shadow/`).
When two loaded modules both export such a name (`math::pure::exp` and `epistemic::propagate::exp`), a module that imports it is bound to the definer its own `use` items name — an explicit import beats a glob — instead of being refused; only an ambiguous import (two explicit, or two globs) is refused.
