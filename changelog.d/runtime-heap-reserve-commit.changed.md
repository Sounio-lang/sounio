Madaros-compiled Linux programs no longer stop at a fixed 2 GiB runtime heap. The heap is reserved once at start up with `MAP_NORESERVE`, sized to `min(1 TiB, RAM + swap)` and never below 2 GiB, and committed by the kernel only as it is touched, so resident memory is unchanged. When `RLIMIT_AS` or strict overcommit refuses the reservation the program halves it and retries down to 256 MiB, and below that exits 184 instead of faulting (the old fixed mapping segfaulted under `ulimit -v`). The arena-full exit 181 and its diagnostic are unchanged; it now fires when this machine cannot back more heap. No environment variable sizes the heap.
