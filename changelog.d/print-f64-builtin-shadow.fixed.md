A user function named `print_f64` no longer captures `println`/`print` of an `f64` on Madaros. The lowerer calls the runtime printer by the bare name `print_f64`, and a same-named user function was found first: `stdlib/plot/bar.sio`'s private `print_f64(value, decimals)`, imported through `chemistry::kinetics`, turned every `println(f64)` of the importing program into a call with a garbage `decimals`, which printed the exact binary expansion followed by an unbounded run of zeros (`chemistry/test_chem_network_ode_sys5` wrote 400 MB in 6 s; `chemistry/test_kin_sigma_small_variance` printed wrong digits). `print_f64` joins the builtin-shadow list (KL-21), so a user definition is renamed `print_f64__user` in its own module and the module's own calls still reach it.
