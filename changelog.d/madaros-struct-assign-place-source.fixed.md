Madaros: assigning a whole struct or fixed array from a place expression (`(*w).ts = (*w).tsa`, `x = *p`, `x = o.f`) now stores a value copy, as the bare-identifier form already did. It stored the source handle, so the two places were one object and a later in-place write through either showed through the other: a silent wrong value with exit code 0, independent of the struct size (found as an AUC 10 times too large in a 14112-double work struct of the circ28 tangent module). Pinned by `tests/run-pass/madaros_struct_assign_place_source_no_alias.sio`. Also fixed: `*d = v` through a `&!S` parameter now writes into the referent object (it rebound the handle in a temporary slot, so `&!o.f` callers lost the store), scalar-only structs assigned from a place and `[Struct; N]` element assignment `a[i] = a[j]` are copied, and an un-annotated array literal of structs records its element type (`println(a[1].x)` printed IEEE bits for a float field). Pinned by `madaros_ref_field_deref_store.sio` and `madaros_struct_array_elem_assign.sio`.
