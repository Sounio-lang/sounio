Madaros no longer fails to compile a function that builds a struct literal from many fields of pure-helper results. Each field's first-order (FO) variance re-lowered the whole helper, and those speculative pastes ran `fresh_reg` past `IR_MAX_VREGS`; the paste was rolled back but its registers were not, so the function's own code then found no register left (`cd_product_16 needs at least 16385 virtual registers`, which broke every importer of `math::cayley_dickson`: `neuro/test_neuro`, `nn/test_fractal_sedenion_e2e`, `snn/test_g2_convergence_e2e`, `snn/test_g2_grad_e2e`). A paste is now admitted only while the function still has room for the largest paste seen so far plus 1024 registers; a refused paste raises `FO_INLINE_TRUNCATED` like the depth and budget caps.
