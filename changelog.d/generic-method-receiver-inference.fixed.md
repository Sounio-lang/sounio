Madaros infers the type arguments of a generic struct's methods from the receiver. An inherent `impl S<T> { .. }` over exactly the struct's own parameters is now specialized once per struct instance (`impl S__i64 { .. }`, `impl S__f64 { .. }`), so `v.push(10)` dispatches on `v`'s concrete instance type and needs no turbofish, and the i64 and f64 instances of the same method coexist. The instance comes from how the receiver is built: `S::<i64>::new()`, `S::f::<i64>()`, `S::f(literal..)`, a `let v: S<i64>` annotation (its struct literal takes the instance too), or an `S<i64>` parameter. `tests/stdlib/collections/test_heap_vec_generic.sio` compiled with "generic method specialization requires one unambiguous explicit turbofish"; it now runs. The refusal stays for a receiver whose type arguments nothing names (`Gen { n: 0 }.push(5)`) when that call can reach the generic method.
