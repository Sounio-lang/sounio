In the no-Madaros fallback, `bin/souc` exec'd the legacy lean_single ELF with the verb arguments untranslated: `souc run file.sio` compiled a source literally named `run` and wrote the output ELF over `file.sio` when a file named `run` existed in the working directory (exit 0, the user's source replaced by a binary), and `souc check` / `souc compile` / `souc build` misrouted the same way. The fallback and the forced `SOUNIO_SOUC_ENGINE=lean_single` branch now share one verb translation, including the `build` alias of `compile`; behavior on the default Madaros path is unchanged. Both lean paths also parsed only `-o` for `compile|build` and silently dropped every other option, so `souc build file.sio --backend gpu -o OUT` exited 0 with a native ELF under `OUT` where the public `souc --help` contract promises a GPU (PTX) artifact; a non-native `--backend` or any `--gpu-target` is now refused nonzero (`error[E-SRB-BACKEND-001]`) before anything is written, while `--backend native` remains accepted. A new CI gate (`scripts/ci/souc_lean_fallback_dispatch_gate.py`) exercises the automatic fallback in a Madaros-less sandbox with adversarial decoy files in the working directory: verbs translated, source bytes preserved, unsupported backends refused with no artifact written.
