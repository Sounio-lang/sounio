`use json::*`, `use http::*`, `use ffi::*`, `use infra::*`, `use systems::*` and every other import of a stdlib directory module now resolve on Madaros. The import resolver tried a directory's root file (`X/mod.sio`) only for the `packages/` candidate, so a directory with no `X.sio` beside it was an unresolved import ("AST closure incomplete ... unresolved=1"). It now falls back to `X/mod.sio` and, for stdlib roots, `X/lib.sio`, as lean_single does, after every file candidate has missed, so an import that already named a `.sio` file resolves exactly as before. The module specification (MOD-002) records the rule.
