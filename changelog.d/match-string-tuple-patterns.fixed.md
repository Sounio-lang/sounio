Madaros match arms with string-literal and tuple patterns no longer fall through silently (SIO-322). Both pattern kinds reached the match lowerer's "unsupported pattern — skip" fallthrough, so a string scrutinee always took the wildcard arm and even the irrefutable `(a, b)` tuple arm never ran, with check: OK throughout. String literals now content-compare through the same `str_eq` call `s == "lit"` lowers to; tuple patterns test and bind element slots (bindings, `_`, integer/bool/string literals, nested tuples), with f64 elements tracked through the scrutinee's tuple float mask. Any pattern kind the lowerer still cannot test honestly is now refused fail-closed instead of skipped.
