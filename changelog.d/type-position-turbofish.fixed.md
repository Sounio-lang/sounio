Madaros parses a turbofish in type position, `HeapVec::<i64>::new()`, as lean_single does; the arguments bind the impl's type parameters exactly as `HeapVec::new::<i64>()` does. It was a parse error ("expected expression, found `::`"). A turbofish-less method call that matches a generic method template only by name (`v.push(10)` on a `HeapI64Vec`, while `HeapVec<T>` also has `push`) no longer fails the whole compile with "generic method specialization requires one unambiguous explicit turbofish": the error stays for calls that can reach the generic owner type, which is decided by whether the owner is named anywhere outside its own `impl` and `struct` declaration.
