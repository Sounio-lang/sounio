Madaros read two `Knowledge` fields wrongly. `s.kn[i].value` on a `[Knowledge[T]; N]` struct field returned 0.0 whenever another struct in the program had a field named `value` at a different index (any program importing `math::pure`, through `CheckedLog`): the element type of such a field was not named in the struct layout, so the slot was picked by field name across all structs. And a literal with a constant value, `Knowledge { value: 0.077, variance: 0.5, .. }`, read back `variance` 0.0, because the derived variance of the constant overwrote the declared one. Both now read the declared numbers, as `lean_single` does; oracle: `tests/run-pass/knowledge_field_array_value_named_twin.sio` and `tests/run-pass/knowledge_literal_declared_variance.sio`. In `darwin_pbpk::epistemic_pbpk28` the finite-difference step h = max(1e-6·|mean|, 0.01·σ) was computed with mean 0, which is why `tests/run-pass/pbpk28_fail_closed_guards_madaros.sio` did not reject its oversized stencil; it now passes.
