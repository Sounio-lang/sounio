`llm::attn_gpu` carries Plan I: GPU attention packs, sampling, and generate on top of the MoE mega forward. `AttnPacks` loads per-layer Q/K/V/O quant quads from `attn_q4k` / `attn_q5k` sidecars or matching GGUF Q4_K / Q5_K tensors, with loud failure on partial quads or mixed dtypes. `attn_proj_mmid` runs one dense projection through the existing mmid path with a trivial single-expert ids row and falls back with a status code when packs or PTX are absent. `attn_load_kernels` probes the new `attn_rope_f32`, `attn_softmax_causal_f32`, and `attn_av_f32` device kernels; `attn_gpu_status` reports 0 (CPU), 1 (dense runtime), or 2 (quant plus kernels) so labs never mistake fallback for GPU math. `llama_sample_greedy` wraps argmax, `llama_sample_temp_top_p` adds temperature and top-p over a heap-ordered prefix with an LCG seed and rejects bad params instead of silently going greedy, and `llama_generate_from_ids` loops prefill plus decode until `max_new` or EOS. New labs `llama_attn_gpu_demo` (prefill versus decode receipts, runtime parity, mmid smoke at status 2) and `llama_generate_demo` (greedy determinism, temp/top-p finiteness, cold-temp argmax agreement) gate the slice. Serving stays on the CPU forward; it adopts this path later.
