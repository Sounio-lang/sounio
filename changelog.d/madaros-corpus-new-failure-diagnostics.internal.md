When the Madaros corpus regression gate finds a failure that is not in `tests/madaros_corpus_baseline.txt`, it now re-runs that one program and prints the last lines of the compiler's (or the program's) output and its exit status, for the first ten new failures. Until now the gate printed only the program name and the stage, because the per-program runs discard their output, so a new failure could not be diagnosed from the CI log.

The corpus baseline `tests/madaros_corpus_baseline.txt` is reconciled with three identical measurements: the 16 entries that now pass are removed and `async_join.sio` moves from `compile` to `run` (it now compiles and crashes when run). Two tests written before the handler parser became fail-closed, `handle_if_f32_literal_join.sio` and `handle_match_f32_literal_join.sio`, drop their `with { 0 }` block, which is no longer a valid handler clause; the body join they check is unchanged.
