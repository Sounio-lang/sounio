When the Madaros corpus regression gate finds a failure that is not in `tests/madaros_corpus_baseline.txt`, it now re-runs that one program and prints the last lines of the compiler's (or the program's) output and its exit status, for the first ten new failures. Until now the gate printed only the program name and the stage, because the per-program runs discard their output, so a new failure could not be diagnosed from the CI log.

The corpus baseline `tests/madaros_corpus_baseline.txt` is reconciled with three identical measurements: the 16 entries that now pass are removed, `async_join.sio` moves from `compile` to `run` (it now compiles and crashes when run), and `handle_if_f32_literal_join.sio` and `handle_match_f32_literal_join.sio` are recorded as `compile` failures. Those two tests predate the handler backend: their `with { 0 }` block is no longer a valid handler clause, and without it the checker still refuses them.
