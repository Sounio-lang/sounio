Madaros now treats the result of the raw builtins `read_f64` and `bits_to_f64` as an f64. Before this fix, `read_f64(p, i) as i64`, and `x as i64` after `let x = read_f64(p, i)`, passed on the raw IEEE-754 bits instead of converting the value: 1.0 became 4607182418800017408. `bf_join_inner` indexes rows that way, so it read far outside its buffer and crashed. A user-defined function with the same name keeps its own declared return type.
