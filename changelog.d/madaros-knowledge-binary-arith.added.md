On Madaros, `+ - * /` between two `Knowledge<f64>` values (names, calls or nested expressions of those) now compiles and runs instead of being refused with E245. The result is a `Knowledge` whose variance follows first-order GUM propagation for independent operands (`va + vb`, `b^2 va + a^2 vb`, `va/b^2 + a^2 vb/b^4`) and whose confidence is the minimum of the operands'; `println`/`print` of a `Knowledge<f64>` prints its nominal value. Operands with differing epsilon, validity or provenance annotations are no longer an E004 (only the payload type must agree), an array literal of `Knowledge` values that differ only in the epsilon bound takes the weakest bound instead of E020, and `x + y` over two bound names now reports the minimum confidence rather than the left operand's. `%` and operand shapes the lowering cannot classify (field access, index, `if`) stay E245; E230 on operands of unknown provenance is unchanged.

A type alias of `Knowledge[f64]` (`type DailyDose = Knowledge[f64]`, including an alias of an alias) is now classified as Knowledge by the lowerer wherever the literal type was: function return types, parameters and `let` annotations. Before, `println` of an alias-typed call result was refused as an unresolved scalar kind (ir/lower.sio `lower_type_expr_knowledge_value_float` and its siblings matched only the literal `Knowledge`).

`covid_2020_kernel` and `med/vancomycin_full_propagation` now declare the independence of their inputs by building each `Knowledge` inside the function that combines it (E230 keeps refusing parameters and call results of unknown provenance, ADR-016 5.5). `vancomycin_full_propagation` keeps its `-> DailyDose` return type. `field_identity_survives_declaration_order` is unchanged: arrays of `Knowledge` stay refused on Madaros (GUM_UNTRACKED_CONTAINER, #3546), so it is not fixed by this change.
