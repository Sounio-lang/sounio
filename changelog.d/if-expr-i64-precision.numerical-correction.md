Recursive `i64` factorials written with `if`/`else` as a value expression can no longer silently return wrong values above 2^53 in a source-built Madaros (SIO-204, #3212: `f(20)` printed 45284158381054464 instead of 2432902008176640000). The source fix landed earlier (#3210 and the FO-inline discard fixes); `tests/run-pass/if_expr_i64_precision.sio` now pins the exact acceptance shape, including equality with the early-return control. Note: the checked-in prebuilt `bin/madaros-linux-x86_64` (2026-10-11) still carries the defect — a refresh was prepared and gated, but the `obo_elplus_driver` compiled by current source runs ~2× slower and exceeds the ontology gate's 900s timeout, so the refresh is blocked on that performance regression (filed separately).
