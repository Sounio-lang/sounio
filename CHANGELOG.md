# Sounio Changelog

All notable changes to the Sounio toolchain and language are recorded here.

From 3.0.0 on, the following rules from [ADR-018](docs/decisions/adr-018-release-cycle-and-versioning.md) apply:

- The toolchain follows Semantic Versioning, and the language is versioned by **edition**.
- Each section is assembled from the `changelog.d/` fragments that pull requests add; do not edit this file in a PR (see [`changelog.d/README.md`](changelog.d/README.md)).
- "Breaking" covers printed numbers as well as source code. A change to a recorded output must pass the epistemic consistency test of ADR-018 §3, or be declared as a numerical correction.

The release process is in [`docs/RELEASE_POLICY.md`](docs/RELEASE_POLICY.md).

## Current maturity

**Status: research language (pre-1.0).** APIs may change; not recommended for production use.

## [3.0.0-rc.2] - 2026-10-31

This is the second 3.0 release candidate. It is `main` at 3ab32211c, merged into `release/3.0`, so it contains everything listed under 3.0.0-rc.1 together with the entries below, which were merged after that section was written. The 7-day soak described in [ADR-018](docs/decisions/adr-018-release-cycle-and-versioning.md) starts again with this tag.

### Breaking

- `CsvTable.data` is stored column-major with stride 256 (`col * 256 + row`). `csv_table_get` and the column reducers still return the same numbers. Code that reads the public `data` field as `row * n_cols + col` does not. Read-only `SciDataset` functions, and `io::scientific` `print_csv`, `print_csv_named`, `print_epistemic_csv`, `print_json_matrix`, `print_npy_data`, `col_mean`, `col_std`, `matrix_data_get`, `matrix_data_print_csv`, and `matrix_data_print_json`, now take references. Mutators that return a new dataset, and SMAT row-major storage, are unchanged.
- `darwin::atlas`, `data::csv_loader` and `data::frame` now use fixed-capacity buffers with an explicit length instead of growable `[T]` arrays, which changes their public API. They now compile and run on Madaros and lean_single. Before, `csv_loader` and `frame` were refused on Madaros (`char_at`, character literals, `String`), and atlas kept its operators private. Atlas works on `DnaSeq` (up to 256 bases plus `len`). `dna_seq_try_push` returns false at capacity and `dna_seq_push` panics there. The double-cover projection now reads a reflection's rotation index from (y, z), where it used to always read 0. `csv_loader` returns a `NetworkData` with up to 512 edges, node ids below 512 and a `status`, plus a CSR `Adjacency`. A header line, a negative id, a wrong field count, a bad weight or an overflow gives an error status and no edges, where it used to be read as node 0 or truncated. `parse_i64`/`parse_f64` are renamed `csv_parse_i64`/`csv_parse_f64`, because lean_single binds the bare names to its builtins. `frame` columns hold up to 64 rows, built from a `[T; 64]` buffer and a length, with string cells as `FrameStr`. A frame holds up to 8 columns and is passed by reference. `dataframe_add_column(&!df, &col)` returns `FRAME_OK`, `FRAME_ERR_COL_CAPACITY` or `FRAME_ERR_LENGTH_MISMATCH` and leaves the frame unchanged on error. An absent name, an out-of-range row or a mask of the wrong length now panics instead of returning an empty column or zeros.
- Canonical atomic and mutex operations now require a checked Platform context and explicit resource closure; monotonic instants and profiler begin/end use the same context and return acquisition or state errors. Existing stdlib consumers and the atomic example are migrated.

### Refusals (soundness)

- A payload pattern on a user enum reached through a reference (`match p { Proposition::Var(name) => .. }` with `p: &Proposition`) is now refused with E264 on Madaros, like the by-value form. The reference hid the enum from the refusal, so the arm was accepted, its binding was typed as the enum itself (`expected string, found Proposition` at every use), and the lowerer would have compared only the discriminant. Payload bindings of a refused arm are now typed as an error, so the E264 is the only diagnostic. Payload-carrying enums remain unsupported on Madaros (KL-20).
- lean_single now refuses an unterminated string literal with `error[E273]: unterminated string literal` at the opening quote (line:column), matching Madaros. It previously swallowed the rest of the module and reported only `unbalanced braces in module`. Witness: `tests/compile-fail/unterminated_string_lean_single.sio` (SIO-266).
- Madaros now refuses implicit IO builtins called without `with IO`, with E035 (SIO-27, #2760). `println`, `print`, `print_f64`, `read_file`, `write_file`, `write_bytes`, `append_file` and `file_size` were bound import-unknown with no attributed effects, so a function could perform IO while declaring none; they now carry the IO effect whenever the name does not resolve to a user-declared function (the same rule lean_single applies), in both checker spines. (`read_i64`/`write_f64` and friends are raw pointer accessors, not file IO, and stay effect-free, as in lean_single.) The Mut half needed no change: mutation through `&!T` already drew E035, and mutating a function-local `var` is the spec §7.2.1 escape rule. New compile-fail fixtures pin all three shapes; the w17 witness (IO leak through an unannotated HOF) is promoted to closed. Two behaviours mirror lean_single exactly: a bare `main` may call the IO builtins (entry-point waiver), and a builtin IO call inside a closure is effect-transparent -- the obligation lands on the enclosing named fn, so the closure keeps its pure type and still flows through pure fn-typed parameters when the caller declares IO.
- A recorded native relocation that the x86-64 backend cannot patch is now refused (rc=29) instead of shipping an ELF whose `[rip+0]` site reads or calls the next instruction. Unknown kinds still refuse as rc=20. rc=29 is distinct from malformed IR and dynlink symbol-cap overflow, which already use 25.
- Madaros now refuses a selective import that names no definition in the loaded modules, with E-USE-ITEM (SIO-346). `use cmp::lib::{max_i64, no_such_fn}` previously bound `no_such_fn` as import-unknown and checked clean; using it compiled to a body-less stub that died with Illegal instruction, and leaving it unused passed silently. Braced import names are now recorded at collect time and validated after every module has been collected: a name with no function signature, struct, enum, or enum variant anywhere in the loaded modules is refused with a diagnostic naming the name and the module path, whether or not it is ever called.
- Invalid or unavailable scalar Normal/Beta evaluations now raise runtime `Panic` instead of returning finite sentinel or fabricated values. Checked calls expose diagnostic status 1 for domain/options, 2 for nonfinite input, 3 for exhausted work, 4 for arithmetic failure and 5 for unsupported representation; scalar underflow retains a finite logarithm independently.
- Legacy private fixed-array FFT helpers now assert before output mutation for invalid sizes, non-radix requests, nonfinite active inputs and insufficient real-spectrum capacity, including the 4096-real request whose 2049 bins exceed the legacy 2048-element output. Native assertion rejection exits1 without a diagnostic string on the verified backend; it no longer silently continues with invalid output.
- `syscall6(.., &!buf, ..)` with a local array `buf`, or a borrow of an array element or struct field, is now refused at compile time on Madaros ("syscall6 cannot pass a borrow of the local array"). A local array is a GC object of 8-byte boxed slots, so there is no address at which the kernel sees its bytes; the call used to pass the GC handle (`write(1, 0x1, 3)` = EFAULT, and a `read` into such a buffer wrote to whatever address the handle number named). Declare the buffer at module level and pass `&!BUF`.
- D-24 (ADR-020) implemented on Madaros: passing a dimensionless value (a plain `f64` variable, a cast, a computed ratio) to a unit-bearing parameter is now refused with `error[E041]: unit mismatch in call argument`, matching lean_single. Pure literal expressions keep adopting the parameter unit, so `exponent(0.0, delta)` and `echo(1000.0)` still compile. Witnesses: `tests/compile-fail/unitless_value_into_unit_param.sio` (madaros) and `tests/compile-fail/unitless_value_into_unit_param_lean_single.sio` (lean_single) (SIO-62).

### Semantics

- The shipped Madaros prebuilt is rebuilt from `main` at the ADR-014 merge, so `&&` and `||` now short-circuit for everyone using `bin/souc` or `bin/madaros`, matching `lean_single`. The right operand is evaluated only when the left one does not decide the result.
- `&&` and `||` now short-circuit when compiled by Madaros, as they already did under `lean_single` (ADR-014): the right operand is evaluated only when the left one does not decide the result. A guard such as `i < n && a[i] == x` no longer evaluates `a[i]` when `i >= n`, and a side effect in the right operand no longer runs when the left one decides. Programs that relied on Madaros evaluating both operands change behaviour; none were found in the repository.

### Numerical corrections

- `f64` results from blocks ending in a local tuple field or scalar-reference dereference retain their floating-point classification through `if` and `match`, including aliases and shadowing. Downstream arithmetic now agrees with the C++23 reference instead of converting IEEE-754 payloads as integers; the bounded before/after evidence and separate pre-existing alias refusal are recorded in `tests/reference/f64_block_metadata_receipt.md`.
- `f64` values returned by `match`, or by `if` blocks ending in a locally bound value, retain their floating-point classification instead of being treated as integer payloads by later arithmetic. The discriminating native regression and exact binary-fraction C++23 oracle are recorded in `tests/reference/f64_expression_class_receipt.md`.
- Float literals are now correctly rounded on both engines, including decimals longer than 19 significant digits (SIO-65 / D-27, #2826, #1644). lean_single converts at compile time with Madaros' bignum Algorithm M instead of a run-time mulsd/divsd chain — `1.0e-300` was 13 ulps off and literals in [2^-1075, 2^-1074) read as 0.0 — and both engines now re-read the token's source digits when a nonzero digit does not fit the i64 significand, retaining 800 significant digits plus a sticky tail, so a literal just above a binary64 midpoint no longer rounds down (the 60-digit counterexample in `tests/run-pass/float_literal_long_decimal_midpoint_2826.sio` read ...972, correctly ...973; expected bits are pinned by the exact-rational oracle `tests/oracles/float_literal_long_decimal_oracle.py`). The lean_single seed was re-derived to its new fixed point (`bc49db1aeecafce1bd2d921d2be9ca1c`, receipt `SeedReceipt-20261027T013709Z`), and the chemistry goldens whose grid spacing literals were misrounded were regenerated under ADR-020's ruling (option a).
- Recursive `i64` factorials written with `if`/`else` as a value expression can no longer silently return wrong values above 2^53 in a source-built Madaros (SIO-204, #3212: `f(20)` printed 45284158381054464 instead of 2432902008176640000). The source fix landed earlier (#3210 and the FO-inline discard fixes); `tests/run-pass/if_expr_i64_precision.sio` now pins the exact acceptance shape, including equality with the early-return control. The shipped prebuilt `bin/madaros-linux-x86_64` is rebuilt from `main` in this release ([#3383](https://github.com/Sounio-lang/sounio/pull/3383), [#3386](https://github.com/Sounio-lang/sounio/pull/3386)) and carries the fix.
- `physics::phonon`'s pulsatile inlet used the Bhaskara I sine approximation outside the half-period where it holds. On the negative half-cycle it gave -1.5 at -π/2 instead of -1, so every trough of the portal and arterial waveforms was 1.5 times too deep. The waveform now uses `math::pure::sin`, and `PI` has full double precision. For the rapamycin defaults the lattice profile moves by up to 0.81 ng/mL (8.1e-7 kg/m³) toward the exact-sine C++23 oracle `tests/oracles/phonon_quantity.cpp`. `physics::phonon` and `physics::pbpk_phonon` are now importable: their state, constants and functions are `pub`, and `pbpk_phonon` imports `phonon`.
- `Beta(1,1)` density at 0.5 now returns exactly 1 instead of 1.9915822398055509. Normal/Beta density, tails and quantiles use checked canonical kernels; the large-shape Beta prefix uses centered deviance and a guarded positive series. Paired native execution and C++23 oracle receipts are recorded in [SIO-162 evidence](../docs/evidence/stdlib-SIO-162-prefix/README.md), with bounded regional qualification.
- `complex::lib` no longer loses about 1e-4 near ±pi. It evaluated `sin`/`cos` with the native builtins, which reduce modulo 2·pi and truncate a Taylor series at x^13 on [-pi, pi], so `cos(pi)` was -0.999900: `|e^(i·pi) + 1|` was 1e-4, `complex_sqrt(-1)` and the roots of x² + 1 missed ±i by ~1e-8. The module now uses `math::libm::libm_sin`/`libm_cos`, which agree with glibc to 1 ulp (`tests/oracles/libm_trig_glibc.cpp`, C++23), and `tests/stdlib/complex/test_complex.sio` passes. Angles beyond |theta| = 1.6e6 (for example `complex_exp` with |im| > 1.6e6) now give NaN components instead of the builtins' inaccurate values.
- Struct fields returned through typed function pointers, aliases and casts now use the declared result layout. A callback returning `{ state: 0, outcome: 1, value: 42, wake: 99 }` could previously expose `value` as 0 when another struct placed a same-named field at a different offset. The corrected value agrees with the independent C++23 field-layout reference in `tests/reference/fn_pointer_struct_return_layout.cpp`; native before/after receipts are in Slurm 17940 and the C++23 receipt in `/orangefs/training/sounio-foundry/runs/stdlib-next-20261027-25/results`.
- `ode::pbpk14_rk4::solve_pbpk14_rk4` integrated a stiff 14-compartment model (fastest rate bounded by ||A||_1 = 875/h) with plain explicit RK4 at the caller's step, so 24 h in 100 steps (0.24 h) overflowed to NaN, as did 2 h in 50 steps. Each caller step is now split into the RK4 substeps needed to keep h·||A||_1 <= 2.5, inside RK4's stability region; `||A||_1` is probed from the model itself and exposed as `pbpk14_stiffness_bound`, and the solution reports the substeps taken in a new `substeps` field. Results now match a converged 10^6-step reference to 1e-9 relative (`tests/oracles/pbpk14_rk4_stability.cpp`, C++23).

### Added

- `arrow::lib` reads and writes Apache Arrow IPC streams and files in native Sounio. Schemas cover the built-in types, nested children in pre-order, dictionary batches (including deltas), variadic view buffers, and custom metadata on fields, schemas, and messages. Record-batch bodies can be lz4-frame or zstd compressed. Zstd decode reads Huffman literals, including four streams and direct weight headers, and FSE sequence tables up to table log 6. LZ4 frames must end on the end marker, and a content checksum on that frame is checked. Record batches round-trip date, time, decimal, interval, half and single floats, fixed-size binary, map, list view, large utf8, large list, and both union modes. Date, time32, year-month intervals, and decimal32 are signed. Fixed-size binary keeps every byte, including widths other than 1, 2, 4, and 8. A file's embedded stream ends with the spec end-of-stream marker before the footer. `arrow_ipc_read` still accepts a single batch and returns -7 when another batch is present. `arrow::ext` reads and writes the canonical extension types (`arrow.uuid`, `arrow.json`, `arrow.bool8`, `arrow.opaque`, fixed and variable shape tensors, `arrow.parquet.variant`, and `arrow.timestamp_with_offset`). `arrow::flight` wraps those encapsulated IPC messages as Arrow Flight DoPut and DoExchange data frames.
- The Arrow device feed stages one float32 matrix of up to 8 MiB. Eight features at that size are 262144 rows, and `arrow_feed_rows_for_payload` returns that count. Each IPC record batch is still at most 16 rows; the feed writes one batch per 16 rows and assembles them into the single device copy. Nulls and float64 features are refused.
- Dynamic arrays (`[T]`) now support `.push(v)` on Madaros native-v2 (SIO-311). Appending to an open array was refused with E019 ("method calls are not supported for this type"); the checker now admits `push` on `[T]` (fixed arrays `[T; N]` keep the refusal, since their extent is part of the type) and lowering emits the existing `__sounio_seq_push` intrinsic, which grows the shared aggregate object -- flags hold the logical length, payload_size the capacity -- and retargets the handle-table entry when it grows, so every alias observes the append.
- `epistemic::klibanoff::klibanoff_compose_with_active(c, alpha, lambda, current, expected_posterior_var, reward_weight)` feeds the smooth-ambiguity certainty equivalent of a reward credal set into `active::expected_free_energy` as the expected reward, so α/λ ambiguity aversion reaches the EFE pragmatic term; α = 0 is the precise limit and the walley ≤ smooth ≤ precise sandwich carries over. `epistemic::active` also gains `beta_posterior_confidence`, `confidence_probability` and the `efe_*` accessors, and `EFEComponents` fields are public.
- Madaros: enum variants with payloads (KL-20). An enum with at least one payload variant lowers to a tagged cell (discriminant word, then one word per payload field, sized for the largest variant; `docs/compiler/ENUM_PAYLOAD_LAYOUT.md`). Tuple and struct variants construct, match with payload binding (by value and through `&`), nest (`Node::Two(Leaf::Val(a), _)`, `Some(Shape::Circle(r))`), pass, return and take methods. The checker types payload bindings with the declared field types and adds E277 (constructor arity), E278 (pattern arity), E279 (`==` or an integer cast on a payload enum) and E280 (non-exhaustive match over a payload enum); E264 now refuses only a payload field that is not one word. Payload-free enums are unchanged. Generic enums still do not parse.
- Madaros now compiles `s.as_bytes()` and shared range borrows of arrays. `as_bytes()` is a `[u8]` holding the string's bytes (it was typed `&i8`, so `.len()` and indexing failed with E011/E019, and it had no lowering), `read_file(..)` is typed `string` instead of unknown, `bytes[..n]`, `bytes[lo..]` and `bytes[..]` parse, and `&a[lo..hi]` reaches the slice-borrow checker (it fell to the scalar index check, E014) and lowers as a bounds-checked copy borrowed like `&a`. A bound outside `0 <= lo <= hi <= len` stops the program (exit 1). `&!a[lo..hi]`, `..=`, and float- or struct-element ranges are refused at compile time.
- Adds `scripts/stdlib/math_pure_ln_boundary_gate.sh` (wired into `deep_science_gate.sh`): compiles `tests/run-pass/math_pure_ln_pos_inf_terminates.sio` with a source-built Madaros, checks `ln(+inf)` terminates against the C++ reference in `tests/reference/math_pure_ln_boundary_reference.cpp`, and runs a guard-removed negative control that must time out (discriminating).
- Madaros has an opt-in array bounds check for the first slice of ADR-023. Building with `SOUNIO_NV2_BOUNDS_CHECK=1` checks every index into a local array, a by-value array parameter or a struct-field array against the array's length, as an unsigned comparison, and exits with status 101 when the index is out of range, instead of reading or writing the neighbouring memory. It is off by default. References to arrays, global arrays in BSS, packed strings and `lean_single` are not covered yet.
- Three physics modules on dimensioned `units::lib::Quantity` values. Tests and importers (`viz::sci`, `examples/phonon_live`) had named them since 2026-06-02, but they did not exist until now. `physics::mechanics` provides kinetic energy, Hooke force, work, power and Newtonian gravitation, with dimension checks and first-order GUM uncertainty; gravitation includes the CODATA uncertainty of G. `physics::phonon_quantity` is the sinusoid transport lattice of `physics::phonon` in SI (kg/m³), with dimension-checked `PhononParams`. Its uncertainty comes from forward sensitivities to the initial state and to the portal, arterial and tissue concentrations. A step panics rather than report an uncertainty that leaves out an unpropagated constant. `physics::pbpk_phonon_q` adds the cycle-averaged liver coupling and the well-stirred correction. `units::lib` gains `dim_rate`, `dim_diffusion`, `dim_spring_constant`, `dim_concentration` (mass concentration) and the `q_*` constructors. Values agree with the C++23 oracle `tests/oracles/phonon_quantity.cpp`.
- Normal and Beta distributions now expose checked density/log-density, CDF/SF/log-tails and quantiles with separate availability flags, work metadata and genuine support infinities. Quantile results retain an observed forward log-tail; requests that cannot meet the numerical work or representation constraints remain explicit unavailable results.
- Checked radix-2 FFT plans support caller-owned dynamic buffers, explicit normalization and the complete 2049-bin unique spectrum of 4096 real samples. Size, radix, capacity and finite-input validation precede writes, with transactional public outputs on arithmetic failure.
- `math::libm` gains `libm_sin` and `libm_cos`: Cody-Waite reduction to [-pi/4, pi/4] with a three-piece pi/2 and fdlibm's minimax kernels, within 1 ulp of glibc on 423 points for |x| <= 1.6e6. Outside that domain the reduction is no longer exact (x = 1e16 would give sin ~0.232 against ~0.780), so every |x| > 1.6e6, infinities and NaN return NaN rather than a wrong finite value.
- Checked owned byte buffers, dynamic i64 deques/maps and binary readers now accompany Linux x86-64 native atomics, mutexes, threads, OS entropy, monotonic time and TCP/UDP operations, with C++23 reference and ownership controls.

### Changed

- The security policy's supported-version table now lists the 3.0 series that `souc --version` reports (`3.0.0-rc.1`).
- `souc --version` now reports the toolchain version with the engine build after it — `3.0.0-rc.1 (madaros <build>)` — instead of the engine banner `Madaros v0.80.0` (ADR-018 §1, SIO-159). A new parity gate, `scripts/ci/citation_version_gate.sh`, fails a stable release tag whose name, `CITATION.cff` version and reported toolchain version are not one string. README and the website getting-started pages no longer present `Madaros v0.80.0` as a version.

### Fixed

- The release tarball (`scripts/release.sh`, i.e. `scripts/install.sh --prefix`) now runs where it is extracted. `bin/souc` and `bin/madaros` source `scripts/lib/resolve_madaros.sh`, which the installer did not ship, so an extracted release died at its first command; `souc --version` also had no `CHANGELOG.md`/`CITATION.cff` to name its version from. The installer now ships both helpers and both files, every link in the prefix is relative (they pointed into the deleted staging directory), the install gate checks a relocated prefix and checks that the installed `souc --version` names the tree's version, and the Release Gate runs it. ([#3391](https://github.com/Sounio-lang/sounio/pull/3391), [#3392](https://github.com/Sounio-lang/sounio/pull/3392))
- Array `++` (dynamic and fixed) lowers to the new `array_concat` native-v2 builtin (heap alloc + element copy) instead of the interim fail-closed refusal; the compile-fail pin is replaced by a run-pass test covering i64, float-marked f64, and empty sides, and the SNN layer constructor pattern compiles again.
- The `f64` slots of a tuple element read through an array of tuples (`xs[i].0 * xs[i].1` with `xs: &[(f64, f64)]`, or a local `[(f64, f64); N]`) are floats again in Madaros arithmetic. Every arithmetic site took them as integers, so a dot product over the slice silently returned `0.000000` and `xs[1].1 + 1.0` printed `4616189618054758400.000000`, the IEEE bit pattern of 4.0. The array local now carries its element tuple's float mask.
- Arrow body codecs: `xxh32` now runs xxHash32's four-lane stripe path for inputs of 16 bytes or more, so LZ4 frames whose block or content checksum covers 16+ bytes are no longer rejected with `-6`. A Zstandard content checksum is now checked (low 32 bits of xxHash64), and a Huffman literal stream must be consumed exactly, so truncated or corrupted Zstandard bodies no longer decode as success.
- The BigFrame per-group verbs in `stdlib/data/bigframe_ops.sio`, `bigframe_stats.sio` and `bigframe_ml.sio` now run under Madaros. They read their per-group results with `res[k]` instead of `read_f64(res as *mut f64, k)`. Under Madaros, casting a local array to a pointer gives a small handle id, not the address of the data, so those 45 reads crashed. The row-emitting verbs, among them `bf_unique`, `bf_drop_duplicates`, `bf_value_counts` and the `*_by` group emitters, now reuse one row buffer for the whole loop. Before, they created a new `[f64; 64]` on every row, and each one took space in Madaros's fixed, never-reclaimed runtime arena.
- A bare call to a runtime builtin such as `read_i64` or `write_i64` is no longer rejected as a private function because another module defines a function of the same name.
- Calls that the checker handles only through its by-value call path are checked again: typekind builtins such as `defer_action`, `deferral_reason` and `prove_robust`, contest witnesses, and the other calls `call_expr_should_bridge_by_value` selects. A Madaros built after the gen2 receiver change refused each of them with `expression kind was not checked in place (Expr.kind dispatch missed)` instead of checking it or giving its typed diagnostic.
- `fit_pca` passes exclusive references into `standardize_data`, `center_data`, and `deflate_matrix`, so `stdlib/stats/multivariate/pca.sio` typechecks.
- core::result: `IntResult` and `FloatResult` gain `is_ok`/`is_err`/`unwrap`/`unwrap_or`/`err` methods in `impl` blocks. Madaros has no UFCS, so `r.is_ok()` against the free-function aliases was E011 (`tests/stdlib/core/test_result_e2e.sio`).
- A `let` that reads an aggregate through a dereference or a field access now value-copies it in Madaros, instead of binding the source storage (SIO-278). `let saved = *b; (*b).a[0] = 99` left `saved.a[0]` reading 99 where lean_single prints 1, and `let s = o.f` shared the same way; plain-identifier lets have copied since #1475/#1479. The let lowering now runs the same budgeted deep copy for `*p` and `o.f` right-hand sides whose type is a registered struct or a word-scalar fixed array, so aggregate fields get fresh backing while Box fields keep reference semantics.
- `.push(v)` on a dynamic array that starts as the empty literal `[]` no longer segfaults on Madaros native-v2 (SIO-311 follow-up). The native allocator returned any zero-element allocation of at most 16 bytes as a raw object base with no handle-table slot, the path meant for small value structs; an empty array literal (8-byte payload) took it. `__sounio_seq_push` grows an array by retargeting its handle entry, so the first push past the initial capacity wrote through a garbage handle entry. Array-literal allocations now always receive a handle, including empty ones.
- `epistemic::active` compiles again on both engines. It had been written against types that no longer exist (Rust lifetimes, `BetaConfidence`, a `provenance` field, `.is_empty()` on slices), so every program importing it failed to parse. It now reads the flat `Epistemic` (val, variance, confidence 0..1000). `update_belief` keeps the old Beta rule on that integer: the prior Beta has mean c/1000 and concentration 2 (the Beta(1, 1) every measured value used to start from), successes = trunc(10 · obs_precision / prior_precision) and failures = 1 are added as counts, and the new confidence is round(1000 · α/(α+β)); `update_belief_with_prior_strength` takes the concentration explicitly. Logarithms and square roots now use the full-range `math::pure::ln` and `ep_sqrt` instead of local series that lost accuracy away from 1. Action and observation lists are two parallel `&[f64]` slices instead of a slice of tuples, `most_uncertain` returns an index, and `update_sequential` is exact cumulative Bayes (one Beta carried across all observations, rounded once) and panics on slices of different lengths. `propagate::monte_carlo` accepts a callback with `Mut, Div, Panic`, as its own body runs with them; pure callbacks still fit. Values agree with the C++23 oracle `tests/oracles/active_belief_update.cpp`.

- Column reductions on a `CsvTable` walk a contiguous run of values. Graph spectral kernels and scientific matrix reads no longer copy the whole numeric buffer on each call. Results of those reads are unchanged.
- Madaros no longer gives a `var` initialised with an integer or bool literal (`var k: i64 = 0`, `var n_fail = 0`) first-order uncertainty slots. One uncertainty channel anywhere in a function (an `if` that bumps an integer counter is enough) made every such counter carry sensitivity slots and, since #2827, a residual slot rewritten at every loop head and assignment. `obo_elplus_driver.sio`, which has no `f64`, compiled to 385 KB instead of 156 KB and ran about 3x slower. Integers bound to a variance-carrying right-hand side keep their slots; the 168 `tests/run-pass` programs that use `measure` or `Knowledge` print the same output as before.
- Reusable FFT plans cache permutations and twiddles once, removing allocation and trigonometric evaluation from repeated transforms. Three AB/BA/AB observations of 32 forward/inverse pairs at N=4096 are documented with raw process timings and RSS; they are bounded observations, not a general performance guarantee.

### Security

- GitHub Actions workflows that had no permission block now grant the token read access to repository contents, and a job still raises that only where it opens an issue or otherwise needs a broader scope. Process core dumps named `core.<pid>` are ignored, so a dump cannot be committed the way earlier dumps carried API keys into history. Source files named `core.sio` and directories named `core` stay tracked.
